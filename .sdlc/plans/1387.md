# Plan 1387: upkeep on a 12-hour window

## Behaviour (smallest design; PROVISIONAL, owner to ratify)
- New setting `upkeep.window_hours` (top-level key of the block, int 1..8760, default 12; wrong type closes the block with a problem, as every key). Old trigger keys stay readable; docs and doctor say they no longer schedule.
- New module `skills/sigma-loop/scripts/feature_upkeep_window.py` (stdlib only, no git, no gh): stamp file `state/upkeep/window.json` (per machine: last_at, unreached list, outcome). `is_open(settings, sdlc_dir, now)`: true when no stamp, stamp unreadable, stamp in the future beyond 300 s, or now - last_at >= window_hours*3600. `stamp(...)`, `describe(...)` (last sweep age, next window in).
- `feature_upkeep_sched.scheduler_tick` (machine door, unchanged signature): after collect/job-alive checks, if the window is closed return decision `window-closed` (status file written for tick liveness as today, NO list_units, NO git, NO gh). If open: write the stamp (attempt), start ONE detached sweep job (`start_job(..., sweep=True)` -> `feature_upkeep_job.py --sweep`) and return decision `started`, unit `*`. The per-unit due/drift/cooldown/backstop selection is removed from the tick (functions it used for the doctor stay if still referenced).
- `feature_upkeep_job.py`: new `--sweep` mode and gated `run_sweep(...)`: takes the same exclusive `job.lock` (busy -> outcome `busy`, recorded as refusal not failure), lists units via `list_units` + include/exclude, and for each unit in turn runs the existing per-unit engine child (`--engine`) through `bounded_run.run_group` with the remaining share of one total cap (`cap_seconds(settings)`). The engine already reports `current` for a unit not behind and does the lease, backup ref, direct-commit refusal, conflict handling; a refused/parked/failed unit does not stop the loop. Per-unit outcome goes to `state.record_outcome`. Units not reached when the cap or a stop file hits are listed as `unreached`. At the end: job.json done with `outcome` "swept" plus `sweep` summary (counts per outcome, unreached), and the window stamp rewritten with the unreached list. The watcher's `collect` notes the outcome as today (unit key `window`).
- Session start: `upkeep_session.py lines` prints (project door, reading only, stamp read only): "upkeep: last sweep <age> ago, next window opens in <t>" (or "no sweep yet" / "window open"), replacing the per-unit "N merges behind" lines (drop `due_units` usage there; keep `due_units` function only if tests/other callers need it, else remove). New subcommand `upkeep_session.py start <sdlc_dir>`: machine door + window open -> calls `scheduler_tick(..., started_by="trigger")` (spawns the detached sweep, returns at once; prints nothing; exit 0 always). `hooks/session_start.sh` runs `start` once, in the same guarded block, never waiting (output to /dev/null).
- Watcher: `watch_daemon.scheduler_step` unchanged (it calls `scheduler_tick`); the window check is stamp-only.
- Doctor (`feature_upkeep_sched.health` rows): add `upkeep window` row (hours, last sweep age, unreached units) and a failing row when upkeep is on and the last sweep is older than 2 windows (or none ever recorded and upkeep on > 2 windows is unknowable: only warn when a stamp exists and is old, or a watcher tick exists without any stamp for 2 windows is skipped).
- Docs: `docs/configuration.md`, upkeep section of `docs/branching-model.md`, doctor text, template config (`upkeep.window_hours: 12`, must equal DEFAULTS), CHANGELOG under `## Unreleased` only. Keep new instruction text minimal (context-budget ratchet): docs only, no SKILL.md growth.
