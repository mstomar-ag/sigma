# Plan 1590: chain parallel independent branches and a single-active-chain lock

## Files
- `skills/sigma-loop/scripts/chain_parallel.py` (new, pure plus a small state file): `width(config)` = 1 unless `chain.parallel` is an int >= 2, then min(chain.parallel, parallel.goals.max_concurrent) and 1 when goal-level parallelism is not enabled (`parallel.goals.enabled is True`, same rule as `loop.goals_parallel`); `ready_set(members, blockers, in_flight, width)` returns members with no open in-chain blocker, never one already in flight, at most `width - len(in_flight)`; `widen_ok(remaining_cap, in_flight, p90)` refuses when the remaining cap does not cover the in-flight goals at p90 (p90 None: allowed only at width 1, i.e. refuses widening past 1); lock: `.sdlc/state/chain-active.json` holding `{chain: {pid, heartbeat, pool}}`; `acquire(sdlc, chain, pool, config, pid, now)` raises `ChainRefused` naming the active chain when the pool intersects, or when `chain.max_active` (default 1) active chains already exist; a lock whose pid is dead AND heartbeat older than a stale age (default 900 s, derived from the pick timeout) is reclaimed; `release`, `heartbeat`.
- `skills/sigma-loop/scripts/chain.py` `run`: acquire/refresh the lock before the claim and refresh heartbeat each cycle; a refused cycle raises `ChainRefused` with nothing started; pick limited to `width` minus in-flight claimed members through a new optional `--max-concurrent N` on `loop.py next-batch` (absent: byte-identical to today). A `done`, `stopped` or `stuck` state releases the lock. `stop` releases it.
- `skills/sigma-loop/scripts/loop.py`: only the optional `--max-concurrent` argument, clamped to the configured cap, never above it.
- Registries: script help allowlist (`tests/test_script_help.py`), write-surface inventory if a new `.sdlc/state` writer is added, CHANGELOG line under Unreleased, config template doc line for `chain.parallel`, `chain.max_active` only if a config template lists chain keys.

## Behaviour
Default sequential: `chain.parallel` unset means width 1 and today's output. Never above `parallel.goals.max_concurrent`. In-flight = members of this chain currently claimed (in progress). Widen check uses `chain_spend.estimate` p90 and the remaining cap from `chain_spend.admit` numbers; unknown p90 refuses widening. State the ceiling: lock file is one JSON read per run cycle.
PROVISIONAL (owner to ratify): stale heartbeat age 900 s; in-flight estimate = in-flight count x p90.

## Test list (tests/test_chain_parallel.py)
test_ready_set, test_blocked_never_batched, test_bounds (each bound broken once: chain.parallel ignored, goals cap ignored, both red), test_lock, test_stale_lock (dead pid + stale heartbeat reclaimed; live pid fresh not; dead pid but fresh heartbeat not; live pid stale heartbeat not), test_widen_vs_cap, plus: default unset is byte-identical to the previous `run` result, and `next-batch` without `--max-concurrent` unchanged.

## Risks
Lock file left behind by a crash: reclaimed by the two-part stale rule. Race between two runs acquiring: use an atomic create (O_EXCL) or atomic replace under the existing state writer, and test the race deterministically at the seam.
