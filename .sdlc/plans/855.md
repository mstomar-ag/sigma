## Defaults and flags (reviewer may overturn)
- DEFAULT 1 verb: `work.py seal-retire <sdlc> <goal> --reason "<why>"`. Dispatched OUTSIDE `_COMMANDS` like `seal-tests`/`quality-waive`; own exit codes (0 retired, 2 usage/missing reason, 4 refused). Library: `sealed_tests.retire(sdlc_dir, stem, reason, now=None)`. No `--into` flag: the verb never touches test files (fewer lies to tell). `seal-retire` is not in `_COMMANDS`, so it does not use the `SEALED REFUSED:` exit-4 mapping; it prints `seal-retire: REFUSED [<clause>]: ...` itself.
- DEFAULT 2 tombstone `.sdlc/state/sealed/<stem>.retired.json` (schema `sigma-sealed-retired/1`: goal, reason, retired_at, generation, files{rel: sha256} copied from the live record). Written atomically FIRST (temp + `os.replace`, 0600), live record unlinked LAST. Crash between the two leaves the goal sealed and the verb re-runnable (an existing tombstone is overwritten by the re-run). Refuses: no/blank reason, goal not sealed (no live record; "already retired" is named when a tombstone exists), unsafe stem, symlinked record/tombstone path.
- DEFAULT 3 fold gesture (documented, not a verb): the maker merges the sealed tests into the owner test file in the goal worktree, runs the owner test file green, `work.py seal-retire`, then one normal `work.py commit` that carries the move and deletion of `tests/acceptance/<stem>/`. Order matters: the commit gate would refuse that edit while the record exists, so retire comes first.
- DEFAULT 4 honesty: retire is the same record-delete disarm that D-11 names, now recorded and reasoned instead of silent. It does NOT close D-11 (anyone can still `rm` the record; the tombstone is evidence, not prevention). Stated in the docs row and CHANGELOG.
- DEFAULT 5 prune: add `("sealed", ".retired.json")` to `goal_state_prune.FILE_FAMILIES`? NO. `("sealed", ".json")` is matched by suffix; a `<stem>.retired.json` name ends in `.json` and would be taken with stem `<stem>.retired` (unsafe/unknown stem, so the family check must be read, not assumed). Step 4 settles it by test: tombstone must be pruned with its goal (age-gated 7 days, same as the record) and must not be mistaken for a live record. Whichever of the two is true today gets a pinned test; if the suffix match skips it, add the explicit family tuple.

## Property notes (AGENTS.md)
- RELIABILITY: no end-to-end seal claim and no PC-10 number; both UNMEASURED with the reason (#537). Controls are claimed only with an observed red test id.
- SCALABILITY: retire is O(files in one record). Seal-tree growth is bounded at 14 files/goal by the breaker cap (ceiling 1,400 files at 100 goals, derived not measured); lever is retire plus fold.
- RESILIENCY: tombstone first, record last; crash leaves the goal sealed and the verb re-runnable; no unbounded retry.
- SAFETY: no new process spawn, no network, no config key, no consumed quota; reason is plain text (no secrets guidance: the doc says do not paste any). Refuses loudly on every precondition.
- LIVENESS: not a long-running component; doctor's sealed row still reports sealed goals, and a retired goal drops out of it by design.
- Host-agnostic: all logic in Python and git; works on Claude Code, Cursor, Codex alike.
- Root-checkout rule: writes only under the goal's own `.sdlc/state/sealed/` on the machine that runs the verb; no tracked root file written. The folded move lands through the goal's ordinary commit.
