# Plan 1062: name an unset integration branch for upkeep

## Decision
Init is not changed. An empty `work.base` also means "whichever branch the loop started on" for
goal work, so recording the default branch at init would change existing behaviour. The issue offers
the alternative (pass and doctor name the unset base); that is the change.

## Files
- `skills/sigma-loop/scripts/feature_rebase.py`: the `no-base` outcome sets `why` when `work.base`
  is empty (not when base equals the unit branch, which stays silent).
- `skills/sigma-loop/scripts/feature_upkeep_sched.py`: `health()` adds a row
  "upkeep integration branch" (not ok) when the upkeep block is open and `work.base` is empty.
- `tests/test_upkeep_sched.py`, `tests/test_feature_rebase.py`: new tests.

## Behaviour
Gate closed (upkeep block off): `health()` returns `[]` as before, and no pass runs. Base set: no
extra row, `why` unchanged. No new git, gh, or write calls.

## Test list
- health names the unset base only when upkeep is on (row present, absent with base set, empty when off)
- fresh scaffold, upkeep enabled: the row appears (end to end)
- pass report: empty base gives why naming work.base; base equal to branch keeps empty why

## Risks
- A consumer matching `why == ""` on no-base: grep found none outside tests.
- Doctor row count changes only for upkeep-on, base-empty configs, which were silently inert.
