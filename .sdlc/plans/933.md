# Plan: #933 unit approval and unattended guard (upkeep part C, slice 6)

## Goal
Add the offline guard that decides whether a feature unit may be landed: attended consent, or a single-use,
expiring, head-bound unit approval. Off by default: with the upkeep gate closed nothing is read, written or created.

## Ruling adopted
The carrier is a per-unit approval record under a fresh state directory `state/unit-approvals/` of the project
directory, made by an explicit verb, bound to unit key, repository slug and verified head, expiring, and consumed by a
create-once marker taken before the merge call. The native-review mode stays optional and fails closed for a solo
maintainer. The `sigma:approve` comment never counts.

## Files
- skills/sigma-loop/scripts/feature_land_approval.py (new): approve, consume, native_review, authorize, main.
- tests/test_feature_land_approval.py (new): the tests below.
- tests/test_feature_registry.py: classify the new address builder (folds) and its sibling importer (no unit name);
  two fixture keys added for the fold driver.
- docs/launch/write-surface.json: one fs-write entry for approve (count 2).
- Not touched: feature_upkeep.py config schema (no new key; native review is a call argument), the never-delete guard
  (the module has no delete-shaped call, REST write or push refspec; a test pins that), legacy env registry (only the
  three already-registered internal names are read).

## Design points
1. Every entry point is wrapped by the upkeep project gate; closed returns the closed verdict and does nothing.
2. Path name is a digest of slug, folded unit key and head: one approval per unit per repository per head, no unit name
   in a path. The record repeats the fields, and the fields are what bind.
3. Consume order: validate everything, then O_CREAT|O_EXCL the marker, then return ok. A denied consume burns nothing.
4. Attended means the two tokens `--user-requested <unit>` on argv and none of the driven-launcher fingerprints. A
   fingerprint can only deny consent. Residual: an agent can fabricate the flag; documented, not claimed closed.
5. Scale: one small file per hand-made approval; nothing prunes it because a delete is refused in this tree (stated in
   the module). Portability of O_EXCL beyond local POSIX disks is unmeasured.

## Test list
- closed gate (several shapes of config) leaves the whole tree byte-identical, for all three entry points
- approve writes a record in the fresh directory, digest name, and it consumes once
- approve refuses a bad unit, head, slug, ttl; nothing is created
- marker exists when consume returns; second consume denied
- deterministic control: marker pre-existing denies
- concurrent consumers smoke test: exactly one wins (labeled smoke)
- binding: other head, slug, unit denied; case fold of the unit accepted
- record copied to another head's name denies (fields bind, not the file name)
- expiry denies and does not burn the approval
- malformed records deny
- attended consent lands with no state; wrong or prefix or equals-form flag is no consent
- each driven fingerprint denies consent; driven with approval lands once
- native review: distinct approved review at head passes; author, comment, wrong commit, changes requested fail;
  a marker approval does not satisfy it, and a failed native review burns nothing
- module pins: no subprocess, network, delete-shaped or gh text, no unregistered env names
- existing: script help matrix, address-builder classification, write-surface ratchet

## Controls (break once, see red)
Drop O_EXCL; drop expiry compare; drop fingerprint denial; remove the gate decorator; drop the in-record field check.
Each turned a named test red.
