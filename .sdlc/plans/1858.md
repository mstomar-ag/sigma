# Plan 1858: a verify lease must not reserve a multiple of its measured peak

## Problem
`_finish` records `peak // lease.workers`. A lease taken with workers 1 for a run that started several pytest
workers puts a whole-run value in the ring; admission then multiplies it by `workers` again (9 GB vs 1.77 GB).

## Files
- `skills/sigma-loop/scripts/resource_lease.py`
- `tests/test_resource_lease.py`
- `docs/parallelism.md` (cold-start/ring paragraph) and the doc-pin test `tests/test_resource_docs_1605.py`

## Behaviour
1. Each lease also keeps `procs`: the most processes of its tree (lease pid plus descendants not holding their own
   lease) whose footprint is at least a quarter of the tree's largest, taken wherever `peak` is raised.
2. `_finish` divides by `max(workers, procs)` so the ring unit is bytes per sizeable process of the run.
3. The ring for kind `verify` is mirrored by a ring `verify_run` of whole-run peaks (observed.json, same bound).
4. `_decide` for `verify`: `n * cost` never exceeds `RUN_MARGIN` (1.5) times the largest `verify_run` value; n is
   lowered to fit, minimum 1 when one unit fits the room. No `verify_run` data: unchanged.
5. Other kinds and a cold ring: byte-identical behaviour.

## Test list
- tree of 5 sizeable processes under a workers=1 lease: ring value <= peak/5
- skewed ring (the 9 GB case: p90 1.81 GB, workers 5, largest run peak 1.77 GB) grants est_mem <= 1.5 * 1.77 GB
- control: with the bound removed (monkeypatched RUN_MARGIN huge) that test fails
- control: procs ignored (divide by workers only) fails the first test
- non-verify kinds and rings without `verify_run` admit as before
- doc pin: parallelism.md names the unit

## Risks
Footprint threshold is a heuristic; documented as such. Dividing by more processes lowers the unit, the whole-run
bound caps the other direction.
