Spec: issue F-07, M-02, M-03, M-05, M-12, M-14 with epic corrections. Builds on merged #1495 (`applier.option_gesture(kind, option)` from the bank; gestures unpark/keep-parked/none; `decision_record.key_of`); invent no parallel field.

## Behaviour
1. `applier.sync(sdlc_dir, config, source)` at start of each tick and as `applier.py sync`: for each open parked issue (bounded per tick, best-effort on GitHub read failure) with a resolved learnable kind, exactly one matching rule and no ask in ANY state for its newest park, open an ask with opened = now. Asks keyed by (issue, park event id/time); an applied or answered ask covers its park (M-02). A veto of a keep-parked apply closes the ask and leaves the issue for a person.
2. open_for_park: mark a pending ask of another kind or opened before the newest park comment `superseded` and open a new one. Unpark by any path closes pending asks (auto_unpark sweep calls close_for_issue; sync closes asks whose issue is no longer parked or whose rule no longer matches, M-12). _prune removes superseded asks after two days.
3. M-05: kinds with no route options (needs_decision, unknown, gate holds) have gesture none and open no ask. M-03: ask stores `armed_at` = max(opened, rule confirmed, first tick the pair was eligible); window counts from armed_at; one notice comment when an ask becomes armed ("rule X will apply after <time> unless you answer or reply no").
4. apply builds its record via decision_record.build with gesture and answer key (M-12). `applier.py <dir> --dry-run` prints each planned action with rule, level and effective window and writes nothing (M-14).
Closed gate (applier disabled): no sync, no ask, byte-identical.
