# Plan 1853: zone classifier, gitlink with a missing target

Cause measured on git 2.49: `git cat-file --batch-check` prints `<key> missing` for a gitlink whose target commit is not in the object store, the same line as for a path not in the tree, so `zones._newness` called it `new`.
Files: skills/sigma-loop/scripts/zones.py (`_find_absent_gitlinks`: for the keys the batch called missing, one `ls-tree -z` per 200 keys with literal pathspecs; mode 160000 entries become `submodule`; a failing call types everything unknown), tests/test_zones.py, docs/change-zones.md (process count, timings), CHANGELOG.md.
## Test list
- the two existing parametrised cases with an absent target (gitlink existing; path under it unknown)
- 450 new paths plus the gitlink last: later chunk still finds it
- failing ls-tree: everything unknown
- no ls-tree call when nothing is missing
Controls seen red: find skipped; rc ignored; first chunk only. The mode-160000 filter is defensive: a missing key never names a non-gitlink entry, so its break is unobservable.
Risk: one extra git process per 200 missing paths (measured and documented).
