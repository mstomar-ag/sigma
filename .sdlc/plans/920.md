# #920 plan: upkeep part A, slice 4 - shared verify runner and unattended git environment

## Goal

Give the optional branch-upkeep feature the two execution boundaries that later slices must not each invent, as
inert libraries with no caller and no gate of their own, plus one bounded doctor helper:

1. A shared verify runner (new library module bounded_run, in the sigma-loop scripts folder). It runs a command in
   a process group of its own under a wall-clock budget, stops the whole group on overrun or when a stop file
   appears (SIGTERM, a grace, then SIGKILL), stops the tree even when its own caller is SIGKILLed, keeps output as a
   bounded tail, returns a distinct no-command outcome, refuses to run without the git-local shell-command trust,
   and runs only in a scratch worktree, never in the project's own checkout.
2. An unattended git runner (new library module unattended_git, same folder): the rebase engine's
   `(cwd, argv) -> stdout` runner contract with no prompts, no editor, no askpass helper, signing off, a hooks
   policy, a fetch that leaves the main checkout's fetch record alone and starts no maintenance, and a required
   time limit per git verb with a typed timeout error. It is injected into the real engine through the engine's own
   `run=` argument; the engine's default runner stays byte-identical.
3. A new bounded local-probe helper in the doctor (the existing uncapped runner is untouched).

Nothing calls any of it, so nothing changes while the upkeep gate is closed (proved, not asserted: see "Closed-gate
proof"). Done when the four boxes of `.sdlc/acceptance/920.md` hold, every new behaviour has a recorded assertion red
before its green (and a break-it-and-see-red control), and the independent verify command is green.

Sources: dossier `.sdlc/research/920.md` (cited below as "dossier"; its measurement ids M-n, radius rows BR-n, debt
rows TD-n and questions Q-n), design `.sdlc/design/911.md` (slice 4 row and the rows BR-79, BR-87, BR-90, D-36, D-39),
acceptance `.sdlc/acceptance/920.md`. All code was read in the goal worktree at the fork tip, which contains slices 1
and 2. Lane: large (a new shared execution boundary).

Revision note (after the independent review). The mechanism, bytes and staging sequence held; the review blocked on
verification gaps and this revision closes them without changing the selector count (still 22) or any existing
behaviour: (B-1) the documented entry `run_verify` now has its own controls for forwarding the stop file, the budget,

## Decisions (do not reopen in Implement)

D1. The runners are plain libraries: no `gated` decorator, no entry point, no registry entry, no template or
schema key, no new environment variable, no skill or reference text. They are called by nothing now; a later gated
caller reads `feature_upkeep.read(config).settings` and hands them seconds (see the interface table). The template
note "nothing runs from this block" stays true. (Dossier Q-1.)

D2. Two new modules, loaded by path like their siblings, neither named with the feature prefix (the fold inventory
and the reader scan key on it): bounded_run (mechanism plus the verify entry; the only sibling it loads is
`shell_policy`) and unattended_git (loads bounded_run). Neither has a command line, so both go in the help test's
LIBRARY_ONLY set, one entry per line. Names and the loading idiom follow `skills/sigma-loop/scripts/autowatch.py`
(`_load`).

D3. The engine's default runner and its 15 default consumers (dossier BR-11) are not edited. unattended_git builds a
new runner with the same contract; gated callers inject it as `run=`. The proof drives the real public pass.
(Q-2.)

D4. The doctor gets one new function, `_bounded_run(args, timeout=None)`, with `_real_run`'s return contract (text,
or a falsy `_RawFailure` carrying the text), built on init's `real_runner`, which stops the whole tree on overrun.
`_real_run` and the seven uncapped local probes stay exactly as they are (D-39 is met by providing the bounded way
in; moving the existing probes is deferred, TD-8). (Q-6.)

D5. No existing verify path is rewired: the loop script's verify verb, the landing helper's verify and the chat door
keep their documented "no timeout" behaviour (`skills/sigma-loop/SKILL.md` line 202 and
`skills/sigma-loop/references/landing.md` line 71 say so; the loop skill file has 26 characters of room). Tracked as deferred work for design C (BR-13, BR-15, BR-16). (Q-3.)

D6. Stopping: SIGTERM to the whole group, wait up to a grace (ten seconds, the figure the shipped bounded drive
uses) for the group to leave while reading the pipes and reaping the leader (a zombie leader keeps a darwin group
"alive"), then SIGKILL, then a bounded wait. A group that already left costs nothing. The same escalation runs after
a normal exit, so a run never leaves a background child behind. A command that finished is never reported as
overrun (the exit is checked first). The stop file is polled every 0.25 s with `os.path.exists`, is checked once more
before anything is spawned, and is never deleted by the runner.

D7. Lifeline: a tiny sentinel in a session of its own holds the read end of a pipe whose write end only the caller
has; end-of-file without `done` means the caller died (SIGKILL included) and the sentinel runs the same escalation
on the group id. This is the shipped pattern copied (about 30 lines), not imported: importing the bounded drive
costs about 0.4 s and loads the module that owns claim arming (dossier M-14, D-36). Not covered, and stated: the
sentinel itself being SIGKILLed; the caller dying between spawn and the group id reaching the sentinel; a descendant
that moved to a new session or a new process group (its group cannot be signalled, but it cannot stall the run either).

D8. Output: pipes are read without blocking into a bounded ring (merged mode keeps the last 64 KiB; split mode keeps
the first 64 MiB of stdout and the last 64 KiB of stderr). After the group is stopped the pipes are drained for at
most five seconds and closed, so a pipe held by an escapee cannot stall the caller. (Q-8.)

D9. Verify entry order, each step spawning nothing before the next: validate the budget (ValueError, the only
exception) -> blank or non-text command is NO_COMMAND (before any trust read) -> no process-group support is REFUSED
-> any repository-location variable (the eight of LOCATION_VARS) exported in the process environment is REFUSED, naming
the variables and never their values (the trust predicate is consumed unchanged and reads with the caller's
environment, so an exported git dir would lend the trust of the repository it names) -> no git-local trust is
UNTRUSTED with the shipped refusal text verbatim (`skills/sigma-loop/scripts/shell_policy.py:39`) -> a directory that is
a repository's own checkout is REFUSED with the main-checkout text, and one git cannot classify (git older than 2.31, an
unreadable directory, a safe-directory refusal) is REFUSED with a different text -> run. Trust is read against the
scratch worktree itself, a linked worktree of the trusted project (a fresh clone always refuses, M-7).

D10. Environment and arguments for git (all per command, none stored): environment GIT_TERMINAL_PROMPT=0,
GIT_EDITOR=true (an exported editor outranks `-c core.editor`), GIT_ASKPASS and SSH_ASKPASS set to the empty text
(one empty askpass neutralises the configured program and the ssh helper too), the eight repository-location
variables removed (the same set as `skills/sigma-loop/scripts/work.py:1339`); arguments after `git` and before any
caller option: `-c commit.gpgsign=false`, `-c push.gpgSign=false`, `-c rebase.updateRefs=false`,
`-c maintenance.auto=false`; hooks policy as a factory argument, "off" (default) pointing `core.hooksPath` at a fresh
nonexistent directory under the working directory or "inherit"; for the `fetch` verb the flag
`--no-write-fetch-head` after the verb. `-c` is preferred to the config-count variables (an inherited count would
collide). The verify command gets the same environment pins (no prompt can be answered unattended).

D11. Per-command limits are a required argument (a mapping from git verb to seconds with a "default" entry; each a
finite number above 0 and at most 86400, the top of the gate's own range); the module holds no default number. An
overrun raises `GitTimeout`, a RuntimeError carrying argv, limit, whether SIGKILL was needed and the elapsed time; its
message names only the verb and the limit (a remote URL in argv can carry a credential). Any other failure raises a
plain RuntimeError with git's own text, exactly as the default runner does. A new read `unmerged_paths(run, cwd)`
tells a conflict from a stop with no unmerged path (a failed signature, a timeout kill). Re-classifying the engine's
"stopped means conflict" (`skills/sigma-loop/scripts/feature_rebase.py:665`) is slice 6's, because that file is hot
(Q-5, Q-11).

D12. Where process groups do not exist (Windows) both runners refuse loudly instead of killing weakly.

D13. One deterministic seam: `run_group(..., clock=)` drives only the budget, so the overrun and TERM-before-KILL tests
jump the deadline instead of sleeping; the grace stays real time. Real-time budgets are kept in smoke form with
generous bounds (at least 2 s budgets, 8 s waits). Nothing here is a port of a script across a performance boundary:
the runners are new, and the one probabilistic element, timing, has this seam.

D14. Test shape (the pull-request gate): 22 function-level selectors in four new test files plus one new support
module, all unparametrised and silent, none edited by Part 2; every mutation control sits inside the test it
controls; three UNLISTED tests that touch only existing code are green already in Part 1.

```python
def _bounded_run(args, timeout=None):
    """`_real_run`'s return contract (the output text, or a `_RawFailure` carrying it), with a time limit on EVERY
    command, local or not. `_real_run` leaves local probes uncapped on purpose (a slow local diagnostic must never be
    reclassified as a missing tool), so a caller that cannot afford to hang on a wedged binary calls this instead: the
    upkeep readiness rows of a later slice. Built on init's runner, which stops the whole process tree on an overrun
    and returns 124; the limit is the fleet's per-call bound unless the caller passes one. Never raises."""
    try:
        preflight = _load_init_script("preflight")
        limit = preflight.call_timeout() if timeout is None else timeout
        code, text = preflight.real_runner([str(a) for a in args], timeout=limit)
    except Exception as exc:
        return _RawFailure("%s: the bounded probe could not run (%s)" % (args[0] if args else "", exc))
    return text if code == 0 else _RawFailure(text)
```

## The five properties (AGENTS.md)

RELIABILITY. Every claim above names its measurement; what was not measured is marked. Unmeasured: behaviour on
Python 3.10 (the grammar was checked against the 3.10 parser only; the modules were smoke-run on 3.11.15 and 3.14.7),
on git older than 2.49.0 (`--no-write-fetch-head` is recalled as 2.29 and not run), on Linux (CI runs ubuntu; the
tests use POSIX shell only and a Linux zombie check, none run here), on a real remote with server-side hooks or
automatic gc, and the ssh transport (no prompt lever was measured; the time limit and group stop bound it).

SCALABILITY. Per run the runner adds one extra short-lived process and about 5 descriptors and no lock, store or
file. Measured per-run overhead 15.0 ms against 3.0 ms for a bare spawn (100 runs each), so a pass of 50 git calls
costs about 0.6 s more and 500 calls about 6 s: linear, at 10x and 100x. Memory is bounded by the kept tail
(64 KiB merged, 64 MiB cap on one split-mode stdout); a 200 MB command output cost 6.1 MB of peak memory (one run).
Named ceiling: concurrent runs, about 5 descriptors each, so 100 concurrent runs need about 500 descriptors, above a
256 soft limit (computed, not measured); the feature runs one job and one verify at a time, so it is not reached.
No chokepoint is added (no lock). The scratch worktree a caller cuts costs 0.13 s at 1,232 files and 6.56 s at
123,200 files (dossier M-10, roughly linear); this slice cuts none.

RESILIENCY. Each failure has a stated recovery with no person: a hung command is stopped at its budget; a killed
caller leaves no tree (lifeline); a stop file ends the run; a full pipe, a flood of output and an escapee holding a
pipe are bounded; a lifeline that cannot start means nothing is run; SIGTERM first means no leaked reference lock
(if one is ever leaked by something else, removing the stale lock file is the documented hand lever; nothing here
deletes it). Nothing is persisted, so a crash or reboot loses nothing and there is nothing to restore. The runners keep no
state, so repeating a call is safe for them; whether a command or git operation may be repeated, and how often, is
the caller's decision.

SAFETY. Nothing spawns, sends, writes or consumes quota unless a caller calls it; limits are caller-supplied (the
constants are mechanism figures, named above); no file is written; nothing is deleted; no secret is read or logged
(the verify command inherits the operator's environment, credentials included, and its output tail can contain
anything it prints: callers must treat `out` as sensitive, and the typed timeout's message carries no argv); Windows is
refused loudly; the verify command is repository-supplied shell, so it needs the git-local opt-in and a scratch
worktree. The trust predicate is consumed unchanged and reads with the caller's environment, so `run_verify` refuses
when any repository-location variable is exported (a control reproduces the exploit: an untrusted clone's worktree ran
on a trusted repository's git dir); `checkout_kind` strips them for its own read and has a control for that.

LIVENESS. The runners have no long-lived component. A dead or hung run is distinguishable from an idle one: the
result carries an outcome word and the elapsed time, and the stop file and lifeline cover the cases where nobody is
watching. Heartbeats and ages belong to the job (slice 7).

## Known limits (stated, not fixed in this slice)

- Inherited signal disposition. If the caller has SIGTERM ignored or blocked, the child inherits that, never sees
  SIGTERM, and every stop becomes a SIGKILL after the grace (measured in review: no SIGTERM seen, escalated). In that
  situation the lock-leak rationale for TERM-first does not hold. The shipped bounded drive lists the same hazard.
- Escapees. A descendant that moves to a new process group inside the same session escapes the group stop, as one that
  starts a new session does (measured in review).
- Linux zombie members. `_group_alive` counts an unreaped zombie member as alive. In a container whose process 1 does
  not reap orphans, a run that leaves a background child would cost about 15 s and report escalation (not run).
- Unattended git environment. There is no `GIT_OPTIONAL_LOCKS=0` (a caller can pass it through `environ`) and no ssh
  batch-mode lever; a credential-helper window would be bounded only by the time limit.
- The no-caller pin scans Python only: a planted shell-script caller leaves it green.
- `_bounded_run` is described as never raising; a non-sequence `args` raises from inside its own handler. Callers pass
  a list.
