# Plan: GitHub write plumbing in gh_api (#931, upkeep part C slice 2)

## Behaviour
Additive plumbing only. No existing function changes its argv, defaults or failure behaviour, so with
the upkeep gate closed (the default) every existing path is byte-identical. The gate module
`skills/sigma-loop/scripts/feature_upkeep.py` stays the only reader of the `upkeep` block; these helpers read no config
and have no caller yet (the engine in later slices is the first).

Files:
- `skills/sigma-loop/scripts/gh_api.py`: `GhApiError` gains `returncode` (default None); `_call` copies it from the
  wrapped failure. New: `bounded_runner(cwd, timeout)` adapter (keeps exit code, wraps timeout as kind transport,
  a missing binary as kind other, all as GhApiError via `classify`); `merge_pr_pinned` (keyword-only method in
  merge, squash, rebase; repo required; head pin must be 40 hex; `merge_reply_sha`); `commit_parents`;
  `branch_rules` plus `rules_have_merge_queue`; `repo_settings` plus `delete_branch_on_merge`;
  `create_pr_nondraft` (typed `-F draft=false`). Every new op refuses a missing or malformed repo before a call.
  `merge_pr` and `create_pr` stay as they are (their tests pin the squash default and optional sha).
- `skills/sigma-loop/scripts/merge_observation.py`: `_WRITERS` gains the landing writer name (PROVISIONAL name
  `verify_merge.land_unit`, the engine function a later slice creates).
- `tools/readiness/write_surface.py`: `_GH_API_WRITES` gains `merge_pr_pinned` and `create_pr_nondraft`; gate text
  for the new runner site; `docs/launch/write-surface.json` and `.md` rows regenerated with real gate text.
- `docs/cloud-sessions.md`, `skills/sigma-doctor/scripts/doctor.py`: degraded-feature text (REST only, no GraphQL
  fallback, draft readiness and queue landing unavailable).
- `CHANGELOG.md`: one Unreleased line.
- Direct-gh baseline (seed D-35): confirmed unchanged; a test counts no new literal gh pr list in gh_api.
- Rejected alternative (D-20): the CLI merge route with a head-match flag; it resolves the repository from the working
  directory, exits 0 on an enqueue and cannot return the reply sha, so the REST route stays.

## Test list
All in `tests/test_gh_api.py` unless named.
1. merge_pr_pinned argv: method explicit, sha last, repo in path; refuses empty, short, non-hex, uppercase pin,
   bad method, missing repo, bad number, each with zero calls.
2. merge reply sha: returned and validated; a non-dict reply or a malformed sha raises.
3. commit_parents: argv, returns parent list, malformed payload raises, bad sha refused.
4. branch_rules and rules_have_merge_queue; repo_settings and delete_branch_on_merge (true, false, absent -> None).
5. create_pr_nondraft sends `-F draft=false` and repo required; create_pr argv unchanged.
6. bounded_runner: nonzero exit keeps returncode and class from stderr; timeout is kind transport; missing binary is
   kind other; cwd and timeout bound; argv never gains a leading gh twice.
7. Gate-closed identity: golden argv for every pre-existing PR op and the error wrap without returncode surprises.
8. `_WRITERS` contains the landing writer and an unknown writer is still refused (`tests/test_merge_observation.py`).
9. Scanner (`tests/test_write_surface.py`): the new write helper names are flagged, a read helper is not; inventory
   gate text for the runner site is pinned and a weakened text fails the pin.
10. Doctor row and cloud-sessions text contain the new degraded-feature wording.

## Risks
- The head pin is only as good as the caller passing the sha it verified; the helper refuses a malformed one.
- Inventory rows are hand-written (D-19); the ratchet checks presence not text, hence the pin test.
- Live behaviour of the commit, rules and settings endpoints is unverified offline.
- Controls (break once, see red): drop the empty-pin refusal; remove a name from `_GH_API_WRITES`; weaken the pinned
  gate text; drop `returncode` copy in `_call`; remove the writer from `_WRITERS`.
