# Plan: question-shaped issues park instead of arming (#1703)

Goal: a filing or migration leftover that asks a person to decide is parked with a declared kind, not armed.
Smaller rule chosen (PROVISIONAL, owner to ratify): declared path on `track` plus a configurable detector; the
`"park"` bucket value of #1482 item 3 is not added.

## Files
- `skills/sigma-loop/scripts/file_triage.py`: `Decision` gains trailing field `qkind` (default None).
  `ai_filed.triage.question_patterns` (list of regex strings; default title patterns: starts with "Question:",
  "Decide", "Should"; ends with "?"; case-insensitive, matched on the TITLE only; `[]` disables; wrong type reads
  as default). `_decide`: after the deny-list, a declared `flags["park"]` (qkind in `qkind.QKINDS`, not "unknown")
  returns park, reason "declared question", qkind; then the detector (also before the human-confirmed arm, so the
  migration parks human-typed leftovers) returns park, reason "question for a person", qkind needs_decision.
  Refresh the stale "UNWIRED" docstring.
- `skills/sigma-loop/scripts/handoff.py`: `create_tracked_issue(..., needs_person=None)` passes
  `{"park": needs_person}` to `_triage_plan`, which uses `decision.qkind` instead of the hard-coded kind (a deny-list
  match still wins). `track` takes `--needs-person <qkind>`; an unknown kind exits 2 with nothing filed. With
  triage off the flag is ignored with a warning (legacy path unchanged). Update USAGE.
- `skills/sigma-loop/scripts/promote.py` `plan_for`: park with `d.qkind or "needs_decision"`; the reason text names
  the question so the dry run shows it.
- Docs: `skills/sigma-promote/SKILL.md` line 18, `docs/planning-the-backlog.md` step 6, `docs/label-model.md`
  step 5 area, the `_ai_filed` text in `skills/sigma-init/templates/config.json.tmpl` (exactly what parks:
