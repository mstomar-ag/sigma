# Plan 1504: define.py open cuts the unit branch from the remote base

## Goal
`define.py open` resolves the base as `<remote>/<base>` after a fetch (same rule as `work.py start`),
refuses with one line when the remote ref is missing, names the base commit in its output, and writes the
owner (active login) plus one repository entry into the unit record.

## Steps
1. `_step_branch`: new `_cut_from_remote_base`: `git ls-remote --heads <remote> refs/heads/<base>`
   (empty -> refusal, one line), `git fetch <remote> <base>`, `git rev-parse --verify refs/remotes/<remote>/<base>`.
   Push `<sha>:refs/heads/<branch>` (the same push refspec shape; no new write kind). Detail reads
   `<remote>/<base>@<sha12> -> <branch>`; report gains `base_commit`. `_push_source` (local-first) is removed.
2. `_commit_record`: owner via `gh api user --jq .login` through the runner seam (failure leaves owner empty,
   one stderr line); repo slug via `feature_sync.repo_slug`; the entry gets `owner` and `repos[slug] =
   {branch, owner}` inside the existing `amend` call (no new write path).
3. CHANGELOG line at the end of Unreleased. No SKILL.md change.

## Test list
- New `tests/test_define_remote_base.py` (real git, bare remote, CLI driven): local main two commits behind ->
  remote branch equals remote main; missing remote base refuses with one line and pushes nothing; record has
  owner and one repo entry; unresolvable login does not fail the open; up-to-date local base opens at the same
  commit with unchanged step outcomes.
- Existing define fakes taught the new probes (ls-remote of the base, fetch, rev-parse --verify, gh api user);
  the three local-first refspec tests are rewritten to the remote-first rule.
- Guards: tests/test_write_surface.py, test_bk_gate.py, test_no_direct_gh.py.

## Risks
- Fetch needs the network at open time; an unreachable remote is a failed step (already true of ls-remote).
- Control: break the push source back to the local base, see the two-commit test red.
