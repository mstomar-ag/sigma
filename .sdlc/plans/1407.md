# Plan 1407: apply the blocker rank when the blocked and blocking marks are assigned

## Goal
Whenever a writer assigns a blocked/blocking pair, the blocker is raised (raise-only) in the same action batch, using the shared rule from 1406 (`discovery.blocker_required_ranks`, mode from `sources._blocker_promotion`).

## Smaller design (PROVISIONAL)
ONE method on the GitHub source, `raise_blocker_priority(blocker, dependent)`: reads both priorities (bounded REST reads, unknown = lowest), calls the shared helper for the single edge plus the blocker's own known dependents when cheap, and writes through the existing `_write_blocker_promotion` (label + board field + one comment naming old rank, new rank, dependent). Returns a small result (raised / unchanged / skipped-with-reason). Fail-open: a read failure reports on stderr and does less. Mode "off" returns immediately, no calls. Idempotent: equal or higher rank writes nothing. A confirmation-labelled blocker is never raised or edged. Local source: no-op.

## Files
- `skills/sigma-loop/scripts/sources.py`: the method (reuse `_write_blocker_promotion`, `_priority_name`, `_write_priority_label`).
- Callers, one call each, gated on the source having the method: `auto_unpark.py` `compute_blocking_actions` (the sweep; add a rank action to the returned batch or call after it applies), `blockers.py` `_act` (routed/promoted/chained cases), `handoff.py` open and track (a follow-up filed for a blocked goal with no/unknown priority is filed at the goal's priority), the precheck park path in `loop.py`, define if it assigns blocked marks.
- New write calls must be registered in the write-surface inventory and the never-delete guard only if they are new gh call shapes (reuse existing writers, so ideally none).
- `CHANGELOG.md` line under Unreleased on its own line.
