# Plan 999: file triage core, pure (slice 14 of #988)

Goal: a pure library `file_triage.py` that decides arm or park for an AI-filed issue. No network, no model call, no
caller yet. Any judge would be an injected callable; this slice needs none.

## Design
- `decide(title, body, flags, config) -> Decision(kind, priority, reason)`; kind is arm, park, or queue (queue only when
  triage is switched off, the old behaviour). Total: any error parks.
- Order: triage off -> queue; invalid buckets -> park with reason; deny-list -> park; human-confirmed filing
  (`flags["human_confirmed"]` true) keeps `flags["priority"]` and arms; otherwise a bucket (flag, else a mechanical
  scan of urgent and routine vocabulary, else unclear) maps to its configured priority and arms.
- Deny-list: the hard-stop classifier (all default classes forced on for this check), a configurable word list, secret
  shapes, and the recorded-permission marker parsed by the existing first-line parser (loaded lazily by path).
- `validate_buckets(config)` -> dict with ok, buckets, reason. A bucket must be P0-P4 and rank strictly below the human
  default (`ai_filed.human_default_priority`, PROVISIONAL P1). Priorities are never blocking.
- Login-free: `flags` may carry a login; it is never read.
- Config (template, top-level `ai_filed`): `triage.enabled` true, `buckets.urgent/routine/unclear` P2/P3/P4,
  `triage.deny_words`. PROVISIONAL defaults, documented in `_ai_filed`.

## Test list
- bucket at or above the human default closes with a reason (control: set a bucket to P1, see red).
- hard-stop word parks and never arms; marker on the first line parks; marker later does not.
- result never contains a blocking priority across a sweep of inputs.
- triage off returns queue; absent block means on.
- same input with different logins gives equal output.
- human-confirmed keeps its plan priority; deny-list still parks it.
- module has no process or network imports; template block parses and matches the code defaults.
