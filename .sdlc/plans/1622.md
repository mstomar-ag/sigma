# Plan 1622: DAG local history, chain lifecycle and monthly archives

Spec: the issue body (7 Done-when bullets) and the epic's History line: append-only, monthly, numbers/event names/timestamps only, never deleted. Existing API: `dag_store` (`save` is the single writer of the stored map; `load`; `mode`; `path`; `state.atomic_write_text`), `dag_core` (`build`, `components`, `cycles`), `dag_chain._graph`, `dag.py` CLI (add a verb), `doctor.py` `_dag_map_row`/`_dag_cycles_row` (landed pattern), `dag_refresh.health`.

## Files
- NEW `skills/sigma-loop/scripts/dag_history.py` (library; add to the script-help library allowlist):
  - `diff(old, new, ts)` -> records (pure; `old` may be None = first map, which records nothing but chain state). Kinds: `edge-added` (a=blocker, b=blocked), `edge-removed`, `node-resolved` (closed/merged/closed-unmerged newly), `node-deleted` (present in old, absent in new: deleted-marked, never forgotten), `chain-completed` (a chain of 2+ nodes whose members are all resolved in new and were not all resolved in old), `chain-superseded` (old chain, a weak component with >= 2 nodes identified by its lowest member number, whose member set was merged into or split into other components: the record names the successor chain ids). A one-to-one component whose membership merely grows or shrinks is NOT superseded. Records are JSON objects `{"t": <ISO UTC>, "ev": <kind>, ...numbers}`, nothing else (no titles, labels, names, urls).
  - `append(sdlc, config, records)`: appends one line per record to `.sdlc/state/dag-history/YYYY-MM.jsonl` (the month of the record's own timestamp), `open(..., "a")`, one write per line, creates the directory; mode `off` writes nothing; bounded: refuses nothing, never raises, prints one stderr line on failure. No function in the module deletes, truncates or rewrites a history path.
  - `record_save(sdlc, config, old_map, new_map, now)` = diff + append, called from `dag_store.save` (the single writer of the map, so insertions and refreshes are both covered) after a successful write, lazily imported, inside try/except so a history failure never fails or delays a save. Same-map twice -> empty diff -> nothing appended.
  - `read_month(sdlc, month)` opens ONLY `<month>.jsonl` (a strict `YYYY-MM` pattern; anything else refused); returns the records; `size_bytes(sdlc, month=None)`.
  - `WARN_BYTES = 1_000_000`; `health(sdlc, now)` -> the current month's size and whether it is above the warning.
- `skills/sigma-loop/scripts/dag.py`: verb `history --month YYYY-MM [--sdlc DIR]` printing that month's records one per line (no month given: the current month); help text in the argparse description.
- `skills/sigma-doctor/scripts/doctor.py`: a row `dag history: <bytes> in <month>` OK, not-OK with the fix text when the current month is above 1 MB (absent when mode is off or no history exists).
- Growth statement (module docstring, numbers): about 100 bytes a record; 50 changes a day for a year is about 50 * 365 * 100 = 1.8 MB in total across 12 monthly files (~150 KB a month, far below the 1 MB warning); a burst month is the case the warning exists for. Readers open one month. State the 10x / 100x behaviour: reads stay one month; only `diff` is linear in map size (note the cost for 30,000 nodes measured with the test).
- Registries: `docs/launch/write-surface.json` row for the append (gate: mode not off; append-only), `tests/test_script_help.py` allowlist, no new marker literal, doc sentence where the map is described (grep docs for `dag.json`), CHANGELOG entry under `## Unreleased` (no duplicate lines in that section).

## Test list (`tests/test_dag_history_1622.py`)
1. diff of two fixture maps yields exactly the expected records for edge added, edge removed, node resolved, node deleted-marked (table test; control: omit one kind -> red, each kind on its own).
2. chain lifecycle: active -> completed when all members resolve; merge of two components supersedes both and names the successor; split supersedes and names both successors; a growing one-to-one chain is not superseded.
3. structural test: scan `dag_history.py` for delete/truncate/rewrite of a history path (`unlink`, `remove`, `rmtree`, `truncate`, `open(..., "w")`, `write_text`, `replace`) and find none; control: add one to a temp copy -> red.
4. same save twice appends nothing the second time (through `dag_store.save`).
5. synthetic year at 50 changes per day: size within the stated bound; doctor row warns above 1 MB in one month.
6. records contain only numbers, event names and timestamps (scan test over every record kind).
7. `dag.py history --month` prints that month only and opens no other history file (count `open` calls via monkeypatch).
8. mode `off`: no history file or directory is created; `dag_history` is not loaded on the save path.
9. a history failure (read-only directory) never fails the save.
Each guard seen red once, each clause on its own.

## Risks
- `dag_store.save` becomes a reader of the previous file: one extra read per save (state the cost).
- Concurrent writers: appends are single-line writes; refresh and insertion are already serialised by the map lock.
