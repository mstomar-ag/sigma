# Plan 932: receipt-key parity under the upkeep gate

## Goal
One landing PR is recorded once however it is first observed. While the upkeep gate is open both
unit-landing observers key it by the unit's branch; with the gate closed every path is byte-identical.

## Files
- `skills/sigma-loop/scripts/merge_observation.py`: new `landing_owner_id(branch)`, the one owner-id rule.
- `skills/sigma-loop/scripts/unit_completion.py`: loads the gate; `_record_unit_landing_merge` and the
  dormant receipt-sharing twin in `_draft` use the helper only when the gate is open. A legacy lookup keeps
  a landing already delivered under the bare unit key on that key.
- `tests/test_receipt_key_parity.py`: new.
- `CHANGELOG.md`: one entry.
- The rebase landing helper keeps its branch-form key unchanged (its persisted receipt path and test pin stay
  valid); it does not import the loop module, so parity is proven by a test, not a shared import.

## Behaviour
- Gate closed (absent, false, text, number, invalid block): owner id is the bare unit, as today.
- Gate open: owner id is the branch. Delivery file name derives from the entry key, so both observers share
  one idempotency file. If the branch-key file is absent and a bare-key file exists, the bare identity is used,
  finishing any pending sink and otherwise writing nothing.

## Test list
- helper returns the branch and refuses empty or non-text input
- gate open: unit side then rebase side gives one merged entry, one delivery file, the branch-derived key
- gate open, reverse order: same result
- gate closed (four variants): bare-unit key, byte-identical
- legacy bare-key delivery then gate-open unit side: no new entry, no new file
- dormant twin and live site both go through the helper (structural)
- controls: unit side forced to bare key, legacy lookup disabled, gate ignored; each must go red

## Risks
- The rebase side is ungated and cannot see the bare key, so a landing recorded under the bare key and later
  observed by the rebase helper can still be recorded once more (PROVISIONAL limit; the other order is safe).
- Existing tests for unit completion, verify merge, the gate and the registry inventory stay green.
