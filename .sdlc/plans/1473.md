# Plan: goal 1473 - the legacy-label migration must never arm an upkeep finding

## Approach
1. `handoff.py`: a constant `UPKEEP_FINDING_MARKER = "<!-- sigma:upkeep-finding -->"`. When `create_tracked_issue(upkeep_finding=True)` files, it stamps the marker onto the body (on its own trailing line, before the unit stamp). The marker name is stable; sibling goals reuse it.
2. `promote.py`: a copy of the marker (`_UPKEEP_MARKER`, pinned to the handoff constant by the existing marker test) plus the body-line fallback "Filed by Sigma's rebase upkeep for unit". `classify_population` returns `upkeep_finding` when either is in the BODY, checked before the follow-up label test (the gate-hold comment markers keep priority: they carry a registry decision).
3. `plan_for`: `upkeep_finding` maps to `Park`, never `Arm`: qkind `needs_decision` for a direct-commits finding (title "Direct commits on" or the "no pull request accounts for" body line), else `merge_conflict`. Placed before triage, so triage cannot arm it. Unresolved blockers and holds still park first with their own kinds.
4. Docs: `docs/decision-rulebook.md` migration section and `docs/label-model.md` runbook population list name the upkeep population and its destination; the "nothing writes the legacy label any more" claim is caveated (upkeep findings still carry it).
5. CHANGELOG line under Unreleased.
Out of scope: priority of findings (#1484), legacy label on findings (#1490), pick-time guard (optional, skipped).

## Test list
- handoff: upkeep_finding=True body contains the marker once; upkeep_finding=False body does not.
- promote: marker constants equal across modules; classify returns `upkeep_finding` for marker, for the legacy body line, and before `followup`; a hold comment still wins.
- promote: plan_for gives Park merge_conflict for a conflict finding, needs_decision for direct commits, never Arm even with an arm-worthy body.
- promote: migrate dry run and apply on a fake source: row action park, outcome would-park/parked, `sdlc:goal` never added.
