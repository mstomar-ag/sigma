# Plan 974: doctor detects a missing verify interpreter and a branch-creation ruleset

## Approach
A new small library module (landing_preflight, in the loop scripts folder) holds two pure checks; the
doctor gets two thin call sites. Both rows are SILENT when fine.

1. Interpreter. Take verify.command, skip leading NAME=value words and an env word, take the first
   word. A bare name must resolve on PATH (the doctor's existing which seam). A path with a slash must
   be an executable file when absolute; a relative path is left to the existing relative-path row. Shell
   builtins and keywords (cd, export, source, set, exec, test and similar) and an unparsable command say
   nothing. A miss gives a MISSING row naming the word, with an arrow hint (install it, or put an
   absolute interpreter path in verify.command).
2. Ruleset. Only when work.enabled, the run is not the cheap session-start one, and gh exists. Resolve
   the repository from the work remote URL (via the existing feature_sync slug parser). Read the
   branch rules for the probe branch named branch_prefix + "probe" through gh_api.branch_rules. For each
   rule of type creation or update, take its ruleset id and read that ruleset through a new gh_api
   function (ruleset, GET rulesets/<id>), then read current_user_can_bypass (a value on the rule itself
   is used if present). Bypass of always or exempt is fine; anything else (never, pull_requests_only) is
   a blocker. A MISSING row names each blocking ruleset by NAME (never its id) and the arrow hint. Any
   failed or malformed read, or a blocker whose bypass state cannot be read, gives one advisory
   could-not-check row (ok true, text shown) and never a crash.
3. Doctor wiring: the interpreter row beside the existing verify rows (any mode that has a command);
   the ruleset rows beside the other gh preflight rows. Reads go through the doctor's raising gh adapter
   so they inherit the bounded timeout.
4. Register the new module in LIBRARY_ONLY (test_script_help). Add one CHANGELOG entry under Unreleased.
   Update the doctor skill reference only if a rows list exists there.

## Review amendments (plan review)
- Tests for the interpreter row pass an explicit which seam that returns None for the missing word (the
  injected-run default makes every word resolve and the check could never fail). Also one real, uninjected
  run with a nonexistent interpreter.
- Words with a dollar sign, tilde, backtick, or command substitution, compound commands (cd x then
  command), wrappers (time, sudo, a leading paren or brace, a bang) and shlex failures stay silent;
  pinned by tests, and stated: a cd-prefixed command is never checked.
- The remote is read with git -C against the project root and work.remote (default origin); a missing
  slug gives a could-not-check row, never the placeholder owner/repo. A public slug wrapper is added in
  feature_sync (or the private parser is called explicitly; the builder picks the smaller change).
- The could-not-check row is hand-built (ok true, text shown). The ruleset block is skipped on the
  cheap session-start path with a test that it makes zero gh or git calls.
- Rulesets from an organisation source are read at the organisation ruleset endpoint; blockers are
  deduped by ruleset id (one row per ruleset). exempt counts as bypass.
- gh_api.ruleset gets unit tests (malformed payload, non-numeric id) and a test that it is not a write.
- Fixtures use synthetic names (o/r, a ruleset called protect-sdlc); no real ids.

## Provisional defaults
- pull_requests_only counts as a blocker (a push creating the branch is not covered by it).
- A blocker whose bypass flag is absent is reported as could-not-check, not as MISSING.
- An update-only restriction is reported with the same row (it blocks later pushes to the branch).
