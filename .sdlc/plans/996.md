## Behaviour
- One record per file, `<store_dir>/<id>.json`, created exclusively, so parallel worktrees add distinct files and never edit a shared one. Id is a UTC timestamp plus random suffix: time-ordered and writer-unique.
- `append` returns None (and writes nothing, not even the folder) unless `records.enabled` is true. Invalid records raise ValueError; an existing id raises FileExistsError.
- Public visibility removes the free-text keys (choice, reason) from the file; ids and enumerations remain. Private keeps them.
- The login is stored for audit only; no code in the new modules reads it (AST scan, allow-list empty until later slices add the authority checks).
- Index is a rebuildable cache under a flock with a bounded wait; on timeout the rebuild is skipped with a reason. Lookups fall back to a directory scan when the index is stale.
- Archive (person-run) folds records older than the configured age into `archive-<year>.json` (atomic replace), then removes the folded files; ids are preserved and still found by `get`.
- Config defaults (provisional): folder `decisions` under the state dir, lock wait 20 s, archive after 180 days, warn above 5000 files. A bad value reads as the default.
