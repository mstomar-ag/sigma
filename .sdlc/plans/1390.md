# Plan 1390 - stamp applied_at per ask from an advancing clock

## Files
- `skills/sigma-loop/scripts/applier.py`: `tick` builds a clock = tick `now` plus monotonic seconds elapsed since tick start (`monotonic_fn` injectable, default `time.monotonic`); `apply` takes `clock=None` and stamps `applied_at` from `clock()` after the gesture has landed (right before the status write), falling back to `now`. `main` unchanged.
- `tests/test_applier_applied_stamp.py` (new), `CHANGELOG.md` under Unreleased.

## Behaviour
Each ask's `applied_at` is the moment its gesture succeeded, so `read_vetoes` (period = window after applied_at) accepts a `no` posted shortly after the applied comment even in a long tick. With a fixed fake monotonic (0 elapsed) the stamp equals `now`, so existing tests stay unchanged. Gate closed: `tick` returns [] before anything.

## Test list
1. Three asks, fake monotonic advancing 100 s per apply: stamps are distinct and increasing, third is ~now+200 s.
2. Long tick: ask stamped late; an owner `no` 10 s after that stamp is read as a veto by `read_vetoes` at a later now (red before the fix: stamped at tick start so the `no` predates/ends window).
3. Closed gate: tick returns [] and monotonic never called.
4. Existing applier tests still pass.

## Risks
`now` also used for `decision_store.append(now=...)`, veto and cap math: keep tick `now` there; only `applied_at` uses the clock.
