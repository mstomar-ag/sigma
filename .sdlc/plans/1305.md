# Plan 1305: single-issue board verbs no longer back-fill the whole board

Goal: a verb about ONE issue (mark in progress, park, hand-off stamp) touches only that issue's card. The
full-board back-fill moves to the watcher tick, capped per tick and skipped when GraphQL is low.

## Design
- `GitHubSource._ensure_board(exclude, sync=True)`: the two single-issue callers pass `sync=False`, so the first
  board write per process still finds-or-creates the board and loads the card list but runs no `_sync_backlog`.
  The full-board sweep caller (archive) is unchanged.
- `_sync_backlog(..., cap=None)`: `cap` bounds card writes (new card, stale Backlog, blank Status); None = unbounded.
- New `GitHubSource.backfill_board(cap=None)` returns cards written: board off or GraphQL unavailable -> 0; cap from
  `discovery.github.project.backfill_cap` (PROVISIONAL default 20, 0 turns it off); reads `gh api rate_limit`
  (REST, free) and skips when GraphQL remaining is below `project.backfill_min_graphql` (PROVISIONAL default 1000)
  or unreadable (fail closed, retried next tick).
- `reconcile_tick.tick` calls it after the reconcile steps (existing watcher tick entry; no new tick script).
  Gate: source github and project enabled; otherwise nothing runs, output byte-identical.

## Test list
- single-issue verb on a board with many uncarded goals: item-add count is 1, not N (control red before the change).
- backfill_board adds at most the cap per call; a second call continues; cap 0 adds nothing.
- backfill_board skips with zero project calls when remaining is low or unreadable.
- reconcile_tick with board off or source local: no gh calls, same summary as before.
- existing board tests that expected inline seeding now call the backfill gesture.
