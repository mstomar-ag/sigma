## Behaviour
- Record gains `run: {"state", "heartbeat", "cycle", "picked", "closed", "stuck"}`; `approve` stamps `approved_at`; a non-dry `arm` that finished with no failed action stamps `armed_at`. `run` refuses (exit 2, nothing written, no process) unless state is approved and armed_at is set.
- `run(sdlc_dir, chain, session_pid=None, pick=None, now=None, config=None, run=None)` is ONE cycle, re-callable (foreground driver; no daemon, no loop, no `claude -p`): refuse checks; refuse if state is `stopped`; auto-unpark sweep via the existing sweep entry (injectable `sweep`); `chain_spend.admit` before the claim: refused -> state `capped`, reason recorded, NO pick call; re-read closure via the existing plan code and report members added since the last cycle (report only); closed members since last cycle advance the heartbeat; then `pick(label)` (default: subprocess of the loop's own `loop.py next-batch <sdlc_dir> --label chain:<root> --session-pid P --skip ...`, the only process spawned). Non-empty pick -> record picked numbers, state `running`, heartbeat now, exit 0 printing the claimed goals. Empty pick: every member closed -> `done` with a closing summary (exit 0); otherwise STUCK, exit 3, with ONE reason from the closed list decided from the member verdicts of a fresh label-drain plan: `decision` (a parked member, name the lowest-numbered one), `held-gate`, `claimed` (in progress by another writer), `external` (open prerequisite outside the chain), `rate-limit`, `degraded-read` (a read failed), `capped`. Nothing outside the label is ever picked: the pick is label scoped.
- `stop` sets state `stopped` (local only); `resume [--cap N]` clears stopped/capped/stuck back to `approved-running` after recording a new `chain.max_goals`-style cap in the record (cap stored in the record, passed to admit through the config copy); re-running after a kill never double-claims because the pick itself is lease-based and the record only stores numbers already claimed; `run` skips nothing it holds.
- Gate: `run` only exists behind the chain record; with `discovery.dag.mode` off existing paths are unchanged (no existing function is edited except approve/arm stamps).
