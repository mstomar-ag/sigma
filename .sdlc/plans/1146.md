# Plan for #1146: a base deletion of a path the branch only inherited is not "dropped"

## Goal
In `skills/sigma-loop/scripts/feature_rebase.py`, `dropped_paths` stops treating a base-deleted path
as lost when the branch carries it byte-identical to the fork point.

## Design
- Collect deleted (kind D) paths. If any: one guarded `git merge-base before after`, then one guarded
  `git diff --raw -z --no-renames <fork> before`. A deleted path not listed (either end) is inherited
  and excluded. No single fork point (failure, empty, several) keeps the old refusal. An exhausted
  budget still raises.
- New helper `_inherited_unchanged`. Wording updated in `_would_drop_body` and `refuse_losing_push`.
- Docs: `docs/branching-model.md` section 3b (carve-out, cost at 10x/100x) and section 15 (the
  remaining limit: a base revert of work already on the base at the fork point reads as inherited and
  is not refused; PROVISIONAL, owner to ratify). `CHANGELOG.md` line under Unreleased.
- Cost: 2 extra reads, only when the replay deletes something; diff output is linear in the branch's
  own changed paths (10x, 100x: linear, one read), bounded by the guard deadline.
- No SKILL.md or reference additions.
