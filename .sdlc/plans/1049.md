## check.py design
- Pattern hash (pinned definition): the first 10 hex characters of sha256 over the UTF-8 text
  `"<flags>:<pattern>"`, where `<flags>` is `rx.flags & (re.I | re.S | re.M | re.X)` as a decimal
  integer (masked so an interpreter-added flag bit, e.g. the always-set unicode bit, cannot move
  it) and `<pattern>` is `rx.pattern`. Helper `pin_hash(rx)`. The literal 10-char hash sits in the
  table so a regex edit shows as a diff; a mismatch prints the new hash so the update is one line.
- Table representation: module constant `TABLE`, a tuple of 5-tuples, one per live entry, in the
  live order: `("name", "hash10", gen_fn, "commit_expect", span)`. A comma after the name, never a
  `name: value` mapping, and no variable or keyword named for a credential word assigned a 4+
  character value (use `hit`, `span`, `body`): research finding 3, the commit gate's anchored
  assignment rule would otherwise refuse `check.py` and the test file. `commit_expect` is one of
  `refused` (the entry's own name fires), `accepted` (no rule fires), `refused-by:<rule>` (a
  sibling fires, nothing under the entry's own name). `span` is `0` (whole match is the secret) or
  `1` (group 1 is, as for `url-password`, `slack-webhook`, the quoted assignment); slice 2's tail
  check needs it, slice 1 only checks the span group is non-empty on the generated value. The
  Authorization-header entry is `refused-by:credential-assignment`, the suffix entry `accepted`.
- Generators: plain functions `gen_<n>(rng)` returning the full planted text. Each builds the
  value from fragments at call time: provider prefix split across two adjacent string literals,
  filler from a seeded `random.Random` over an alphabet without look-alike characters (the style of
  `_tok` in `tests/test_scrub.py`), fixed-width suffix shapes using the exact count (npm 36, google
  35, aws 16), variable ones a count above the minimum; PEM from a run of dashes plus split
  `PRIV`/`ATE KEY` and 64-char base64 body lines (the unterminated entry omits the END line); JWT as
  three runs of 12; URL, webhook and assignment shapes as in research. `sk-` plain shape is
  alphanumeric only. The aws alphabet omits `I` and `O` so the exempt value cannot be produced.
  `generate(entry)` seeds `random.Random` from the entry name plus hash, so output is deterministic.
- Pure functions, each taking the scrub module (or its spec list) as an argument, returning a list
  of finding strings: `load_scrub(path)` (raises `Refusal`), `live_specs(scrub)`,
  `check_two_way(live, table)`, `check_shape_subset(scrub)`, `check_generators(live, table)`
  (every entry has a callable; value is matched by the live regex of its own `(name, hash)` key and
  the span group is non-empty; no generated value contains a `COMMIT_FIXTURE_VALUES` member, plain
  substring), `check_commit_outcomes(scrub, table)` (per planted line `commit_secret_hits`, line by
  line for the multi-line PEM; outcome compared with `commit_expect`), and `run(scrub, table)`
  concatenating them. `main(argv=None, scrub_path=None)`: findings print to stdout as
  `check.py: FINDING <kind> <name> <hash>: <detail>`, exit 1; `Refusal` prints
  `check.py: REFUSED: <reason>` to stderr, exit 2; clean prints one `check.py: ok` line with counts
  derived at run time, never typed. argparse with no options so `--help` works.
- Default scrub path: repo root two parents up from the file, `skills/sigma-loop/scripts/scrub.py`.
  The live list is read as `scrub._SECRET_PATTERN_SPECS` (spec-injectable); a missing attribute is
  a Refusal, not a pass.
- Module docstring states: the documented gesture on its own line, `python3 evals/safety/check.py`;
  exit codes 0/1/2; what it adds beyond per-shape tests (a two-way pin that sees a removed
  duplicate); the limit that the two assignment entries do not leak when removed alone (the suffix
  entry redacts the same text), so only the pin sees them removed and a behavioural probe cannot;
  that slice 1 proves the pin and the commit outcome, not the sinks. Cost/scale note per the
  Ceilings section below.

4. Make `check_shape_subset` return nothing; its test goes red. Restore.
5. Drop one entry's generator from `TABLE`: gesture exits 1; the dropped-generator test red.
6. Point one generator at the exempt fixture value (assembled from fragments in the scratch copy):
   exits 1 on D-3; remove the substring check and the test goes red.
7. Change one pattern in the scratch `scrub.py` so the generated value no longer matches: exits 1 as
   drift; make `check_generators` skip the match test and its test goes red.
8. Flip one `commit_expect`, and separately make the scratch `commit_secret_hits` return `[]`:
   exits 1; remove the compare and the test goes red.

10. Run the documented gesture WITHOUT a mutated tree and confirm exit 0 (the green leg). Confirm

## Ceilings
Cost is O(shapes): 23 regex searches, 23 generator calls and about 60 `commit_secret_hits` lines,
well under a second on a laptop (to be measured and printed in the PR, not claimed here). Linear at
10x and 100x shapes; the only superlinear piece is the quadratic name-by-name compare, trivial at
these sizes. No network, no model, no subprocess, writes nothing (stdout/stderr only), spawns no
background process. Not measured: Python 3.10 on CI (local runtime is 3.9); nothing used is
version-sensitive.

## Recovery
Exit 2, never a pass, when `scrub.py` cannot load, the live list or a name it relies on is absent,
or the table is malformed (wrong tuple width, unknown `commit_expect`). A finding is not self-
healing by design: the lever is a one-line table edit, and the mismatch prints the new hash so it
is cheap. The check holds no state, so a crash mid-run leaves nothing behind.
