## Behaviour
1. `session_end` (the CLI verb is what the success-stop path calls): before removing the marker, read its `in_flight` list. For each goal that is unstarted (no work record/worktree from `work.py`, no agent heartbeat marker from `agent_start`), call the same release path the over-capacity release uses (`_release` with reason "claimed but not started: session ended"), which posts the "claimed but not started" comment and appends a ledger release plus an action-log `released` entry carrying actor and reason. A started goal is left alone. Release failures never raise out of `session_end`.
2. `_prune_dead_session_entries`: for a dead session entry (same liveness check it already uses) older than a bounded grace (a config key with a documented default, 15 minutes; add to the config template and docs), release its unstarted in-flight goals the same way before pruning the file. Live sessions are untouched.
3. A bare session-end with a mismatching generation stays a no-op (do not release another owner's goals).
4. Gate: both behave only when the source supports release (GitHub source); local source path must stay byte-identical (test).
