# Plan #1988: `dag.py rebuild` reads every outside number

## Files
- `skills/sigma-loop/scripts/dag_collect.py`: `collect` and `refresh` take `outside_max` (default `OUTSIDE_MAX`, 25, unchanged); new `REBUILD_OUTSIDE_MAX = 500` and `OUTSIDE_HARD_MAX = 2000`, stated with call counts in the docstring; a value over the hard cap is clamped to it.
- `skills/sigma-loop/scripts/dag.py`: `rebuild(sdlc, outside_max=None)` passes `REBUILD_OUTSIDE_MAX` (or the clamped `--outside-max N`); the `rebuild` parser gets `--outside-max`; the report line, when unread is not 0, ends with what to run (`run dag.py rebuild again` / `--outside-max N` when the cap bound it).
- Tests in a new `tests/test_dag_rebuild_outside_1988.py`; `docs/dag.md` one sentence; CHANGELOG `## Unreleased` line; script help / write-surface registries as touched.

## Behaviour
- The periodic refresh (`dag_refresh`, watcher) keeps 25 reads per run: cost unchanged.
- Calls at 10x and 100x outside numbers (one REST read each): 250 and 2,500 outside numbers cost 250 reads (10x, under the 500 default) and 500 reads at 100x with the rest left `unread` (2,000 at most with `--outside-max 2000`); the rebuild is explicit, so the cost is the person's choice.
- `--outside-max 0` reads none; negative or non-integer is refused by argparse.

## Test list
1. rebuild with 60 outside numbers reads 60 (`unread 0`).
2. refresh (periodic path) with 60 reads 25, unread 35.
3. `--outside-max 10` honoured: 10 reads, unread N-10, report says what to run.
4. hard cap holds: `--outside-max` over it is clamped (reads = cap) with a note.
5. report with unread 0 has no hint; with unread > 0 names `dag.py rebuild`.
Controls: break the default (rebuild uses 25), the clamp, the periodic path sharing the big default, the hint condition.

## Risks
`dag_refresh` and ledger callers call `dag_collect.refresh` positionally: keep the new parameter keyword-last.
