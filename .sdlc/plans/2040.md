# Plan: #2040 a filing park caused only by the count cap waits for the counter, not a person

Unit: filing-cap. Builds on #2039 (landed): `ai_filed_counter.cap_cause` / `cap_reason` give the cap text.

## Design (defaults chosen)
1. **New question kind `filing_cap`** in `qkind.QKINDS` (and every registry that pins QKINDS: ledger reason classes, `unpark.QUESTIONS`, doctor's kind set, `docs/decision-rulebook.md` kind list; let the pinning tests in tests/test_qkind.py, test_unpark.py, test_ledger.py, test_docs.py tell you which). `handoff._triage_plan` sets `plan["qkind"] = "filing_cap"` ONLY when the park's sole cause is the per-goal or per-run count: move the depth-limit check BEFORE the cap check so a depth park keeps `needs_decision`; deny-list (hardstop kind), permission-marker, unreadable-counter parks keep their current kind. An evicted victim (parked solely by the per-goal cap) is parked with `filing_cap` too (`_triage_finish` eviction branch).
2. **The park comment carries the origin**: for `filing_cap`, `_triage_finish._park` appends one machine line `sigma-filing-goal: <key_goal>` (the counter key, "" -> `none`) after the kind line, so the sweep can re-count it against the right goal. A small parser lives in `qkind.py` next to `parse_hardstop` (same style).
3. **`ai_filed.on_cap`**: `limits()` accepts `"park"` (default, PROVISIONAL, owner to ratify) and `"defer"`; anything else reads `"park"`.
4. **Defer re-arm in the auto-unpark sweep** (`auto_unpark.py`): new `compute_filing_cap_rearms(sdlc_dir, config, source, issues, run)` plus a call in `sweep_unpark`, active ONLY when `on_cap == "defer"`. Candidates: issues carrying `parked_label` whose newest Sigma park comment declares kind `filing_cap` (use `qkind.resolve`), not exempt (`_is_exempt`), no gate-hold. Order: priority label P0..P4 (none last), then issue number. Room check per candidate with `ai_filed_counter.over_cap(counter, goal_from_machine_line, run_id, config)`; stop at the first candidate that does not fit only for its own goal (others may still fit); never more re-arms in one sweep than `max_per_run - (entries already counted for this run)`; with no run id the bound is `max_per_run` for the pass. Each re-arm: one `swap-label` (add goal label, remove parked label; same primitive as the dependency path, board card moved when active), then `ai_filed_counter.bump(...)` with run/goal/issue/prio, ONE ledger entry (`ledger.safe_append`, an existing event kind, `why` naming the cap that parked it) and ONE issue comment via `source.note`. An unreadable counter re-arms nothing. A dry run (`apply` false) reports and writes nothing. Reuse `_fetch_parked_issues_status`'s list (already includes parked-label issues).
5. **Unpark review** (`unpark.py`): `QUESTIONS["filing_cap"]` = one route question that quotes the park reason (`{reason}` already holds the count text, e.g. `per-goal cap: 5 of 5 ...`) and offers `["arm it", "leave it parked"]`, gestures `unpark` / `keep-parked`. It never contains the words "real blocker". `brief()` must not insert the `kind` question for a declared kind (already so). Check `BULK_NEVER`/`route_slot` handling: `filing_cap` is allowed in bulk.
6. Docs: `docs/configuration.md` documents `ai_filed.on_cap: "defer"` (what it does, that it needs the auto-unpark sweep to be on, default `park`); `docs/decision-rulebook.md` lists the new kind; CHANGELOG entry under `## Unreleased`.

## Test list
- test_handoff: per-goal cap park, per-run cap park, eviction victim -> kind `filing_cap` (3); depth-limit, deny-list match, quoted permission marker, unreadable counter -> unchanged kinds (one test per kind, 4); depth+cap together -> depth kind.
- test_ai_filed_counter: `limits` on_cap `defer` accepted, junk reads `park`.
- test_auto_unpark: with a fake source and a fake counter: `park` default re-arms nothing; `defer` re-arms when room; highest priority first; per-run bound (max_per_run 2, three candidates -> two armed); per-goal full -> that candidate stays parked, another goal's candidate arms; unreadable counter -> none; each re-arm = one swap-label, one ledger entry, one note; exempt/non-filing_cap parks untouched; dry run writes nothing.
- test_unpark: the filing_cap question text shows the count and offers to arm; no "real blocker"; registry pins pass.
- test_docs / registries: configuration + rulebook mention.
- Break-it controls (each clause alone): qkind set for per-run only; depth ordering; priority sort reversed; per-run bound removed; room check removed; default flipped to defer; question text containing the old phrase.

## Risks
- Many registries pin QKINDS; run test_qkind, test_unpark, test_ledger, test_auto_unpark, test_handoff, test_docs, test_doctor, test_script_help, test_decision_*.
- A re-arm must not re-park on the next filing: bump records the re-arm, so the cap stays honest (documented).
- Scalability: one counter read per sweep, candidates bounded by parked list already fetched.
