# Plan 1300: upkeep job pushes with a backup and stops after a refusal

Files: `skills/sigma-loop/scripts/feature_upkeep_pass.py` (`unit_callables.push`), `skills/sigma-loop/scripts/feature_upkeep_job.py` (`run_engine`), `CHANGELOG.md` (Unreleased), the write-surface inventory and never-delete guard only if a new push shape appears.

Behaviour:
1. `unit_callables.push` sends the rewritten commit through `feature_backup.push_unit` (source = the new sha, expect = the tip the pass read; unit name = branch minus the feature prefix), so one atomic push moves the branch under the lease and keeps the old tip under the backup namespace. Any outcome other than PUSHED raises, so the pass records a failure.
2. `run_engine` runs the unit pass only when the older pass outcome is not in the failure set (`feature_upkeep_state.FAILURE`, which includes direct-commits); otherwise `unit_pass` reads `skipped`. The job record keeps the older pass's true outcome.
PROVISIONAL: the older pass stays the single authority on direct commits and acks; the unit pass does not re-derive them.

Test list: push goes through the backup push (backup ref present on a local bare remote); a stale lease leaves the branch unmoved; direct-commits outcome means the unit pass callable is never called; gate closed means no change (byte-identical output of the job entry); control: revert fix, see red.
