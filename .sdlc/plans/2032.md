# Plan 2032: read-only scan of agent host config

Plan sha256: pending

## Behaviour
- New `skills/sigma-doctor/scripts/host_config_scan.py` (stdlib only): `scan(project_root, home=None)` -> list of findings {file, rule, severity, fix} plus `not_scanned` rows {host/file, reason}. Reads only files that exist, opened read-only (`open(..., "r")`), size-capped (e.g. 1 MB), JSON via json, TOML via tomllib when available else `not scanned: toml reader unavailable`. NEVER stores or prints a config value: findings carry the file path (home paths shown with `~`), rule id and a fixed fix sentence; a matched literal is never echoed. No network, no subprocess.
- Files: Claude Code `.claude/settings.json`, `.claude/settings.local.json`, `~/.claude/settings.json`, `.mcp.json`, installed-plugin `hooks` (hooks.json under the plugin cache dir if readable); Codex `~/.codex/config.toml`, repo `AGENTS.md` scaffold (presence only); Cursor `.cursor/mcp.json`, `.cursor/rules/` (presence + scan of rule text for nothing: presence only, reported as scanned). A file that exists but cannot be read/parsed -> `not scanned: <reason>`; a host with no files -> no row (nothing to scan), never "clean".
- Rules (each its own id, each independently removable): R1 allow rule granting everything (`Bash(*)`, `Bash`, bare tool name with no pattern); R2 hook/MCP command that downloads and executes (`curl|sh`, `wget|bash`) or runs from a world-writable path (/tmp, /var/tmp); R3 MCP server from an unpinned package (`npx pkg`, `@latest`, no exact version); R4 literal credential in a config `env` block - reuse the existing secret content rules (find them in work.py's content scan / secret patterns; import or call, do not write new patterns); R5 sandbox/approval settings fully off on a host that supports them (Codex `approval_policy = "never"` with `sandbox_mode = "danger-full-access"`; Claude Code `bypassPermissions` default mode).
- doctor.py: one row per finding (file, rule, severity, fix) + a `not scanned` row per unreadable config; reuse the row printer #1913 extended (level word).
- `/sigma-loop` start: print the findings once and continue (hook in loop.py `start` or the session-start path that already prints notices; informational, never blocks, never parks).
- docs/threat-model.md: one new row (host-config risk, scanner, limits: report only, does not block, prompt/skill prose not scanned, rule set provisional).
- Measure scan time: this repo + synthetic config (100 permission rules, 20 MCP servers) with time.perf_counter in a test helper script run once; report numbers in the PR/changelog.
