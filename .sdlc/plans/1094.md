# Plan 1094: triage core must not park ordinary prose as cannot-tell

## Files
- skills/sigma-loop/scripts/file_triage.py (the only source change)
- tests/test_file_triage.py (new tests)

## Behaviour
The deny step runs the shell hard-stop classifier over free prose. A shell parse failure on prose
(odd apostrophe) returns the cannot-tell class with pattern id parse-error, parking every filing.
Fix at the triage seam: a cannot-tell result whose pattern id is exactly parse-error is treated as
no stop, because the text is prose, not a command. Every other cannot-tell (detector-error, error,
not-text) and every matched class still parks. hard_stop.py is untouched, so other callers keep the
fail-closed contract.

## Test list
- prose with apostrophes and quotes arms at bucket priority
- hand-off, decompose child and design child shaped bodies arm
- dangerous commands inside a body with an odd apostrophe still park (force push, drop table, curl pipe shell)
- a non-parse cannot-tell (raising detector) still parks
- non-string title/body still ends in park or arm without raising

## Risks
A command-shaped line that also fails to parse escapes only the parse-error path; the class regexes
run before the parse check, so dangerous shapes are caught first.
handoff.py does not call the triage core in this tree, so no handoff test is pinned or un-pinned.
