# Plan: /sigma-dag and `dag.py report` (goal 1954)

Spec: the issue body (Proposal + Done when). Unit: rollout-fixes.

## Behaviour
- `dag.py report <sdlc_dir> [--goal N] [--md|--json]`: read-only, from the stored map only (no network, no
  rebuild, no write). Markdown default. Sections: mode, age, node/edge counts, usable?; the doctor's freshness
  verdict and shadow comparison line (reuse the doctor's functions, do not re-derive); stuck chains (most
  freeing first); active chains; cycles; completed this month; where the files live (`.sdlc/state/dag.json`,
  ledger branch `DAG.md` when the ledger is on). `--goal N`: the chain behind N (reuse the `chain` verb's markdown).
- Missing map, stale map, mode `off`, or a repo whose config does not write `discovery.dag.mode`
  explicitly: ONE line with the exact fix (`dag.py rebuild`, `dag.py refresh --force`, or the config key to set;
  for the unwritten key: that the automatic refresh and doctor rows start only once it is written). Never empty.
- `skills/sigma-dag/SKILL.md` (+ `references/selection.md` like sibling skills): runs `dag.py report`, relays
  stdout verbatim; `--html` / `<N> --html` run `dag.py html --all` / `--goal N` and print the path of the index
  or page (open it where the host can). Keep SKILL.md short; the context-budget ratchet must be offset
  (trim an equal amount from an existing SKILL.md sentence if the ratchet test requires it).
- Register the skill everywhere a sibling (e.g. sigma-velocity / sigma-time) is registered: evals skill card,
  tests that enumerate skills (test_skill_prompts, test_legacy_compat, test_packaging_slice4 ...), docs/features.md,
  script help (tests/test_script_help.py), plugin manifests if any list skills. Discover by grep for a sibling name.
- docs/dag.md "Reading the map" section opens with `/sigma-dag`; CHANGELOG `## Unreleased` one line of its own.

## Test list
1. golden markdown for the full report and for `--goal N` on a fixture map (generic fixture issues).
2. missing map, stale map, mode off, unwritten key: each prints its one-line fix; each red when its branch removed.
3. `--json` is valid JSON with the same facts; report writes nothing and does no network (assert no subprocess/gh).
4. skill registry tests pass with the new skill; context-budget ratchet passes.
Break controls, each clause on its own: remove the missing-map branch; the stale branch; the mode-off branch;
the unwritten-key branch; the stuck-chain ordering (plain membership vs most-freeing-first).

## Risks
New skill touches many registries and the context ratchet; discover failing registry tests by running them.
