# Plan 1967: map history cut independent of writer clocks; no read_all per save

Files: skills/sigma-loop/scripts/dag_history.py, dag_store.py, tests/test_dag_change_id_1958.py (and the 1956 snapshot test if it asserts the id), CHANGELOG.md.

Behaviour
1. `history_through` becomes per-file byte marks `{"YYYY-MM/<file>.jsonl": size}` taken by `stat` only (new `dag_history.marks(root)`), so a save no longer reads the whole ledger history. Writer files are append-only, so "after the marks" is: bytes past each file's mark, plus every file the marks do not name. A record published late with an older `t` lands past a mark or in a new file and is applied; no writer clock is consulted. `read_all(root, after=<marks dict>)` does that; the old string `after` (a 12-hex id) still works as before for snapshots written by 1.0.18 and is documented as clock-ordered.
2. `dag_store.snapshot_through` returns the marks dict (validated: strict key shape, non-negative ints) or the legacy id or None.
3. A change that repeats an earlier change's (event, numbers, u) in this writer's local history (add, remove, add with the issue's updated_at unmoved) gets a disambiguator `k` = number of earlier local records with the same base id, folded into the id. Two writers with the same local history agree on k. A writer that missed the first add gets k=0 and folds into it: documented. Lookup runs only when a diff is non-empty.
4. Docstring states the measured per-save stat cost at 1x/10x/100x files.

## Test list

Risks: partial last line at a mark (single O_APPEND write per line: negligible, documented); marks grow with file count (one per writer process per month, same order as history files).
