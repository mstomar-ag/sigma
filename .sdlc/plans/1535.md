# Plan: upkeep sweep follow-ups (#1535)

## Goal
Three small follow-ups to the unseen-units slice (#1493): the sweep's ledger note carries the units
swept, a case-only name difference between a registered unit and its branch is covered by a test, and
the doctor's unmaintained-branch row tells a user how to exclude a branch that is not a unit.

## Research
- `feature_upkeep_job.run_sweep` records `sweep.counts` (outcome word -> number of units run) and
  `units_listed`. `feature_upkeep_sched.write_outcome_note` turns the job record into a ledger note via
  `feature_upkeep_pass.ledger_note`, whose ref is `upkeep:<outcome>:<sha12>`; a sweep prints `none` as tip,
  so a zero-unit sweep and a real one read the same.
- `feature_upkeep_sched.unregistered_heads` already lower-cases both sides; no test pins it.
- The only exclude list is `upkeep.units.exclude` (glob, case-folded, wins over include). The doctor row
  does not consult it today, so naming it in the remedy would be false.

## Steps
1. `ledger_note` takes an optional `units` count; when given, the ref gains a `:units=<n>` suffix.
2. `write_outcome_note` passes `sum(sweep.counts.values())` for a sweep record (zero when none ran).
3. `_unmaintained_row` in the doctor drops heads matched by `upkeep.units.exclude` and its remedy names that key.
4. Tests for each; CHANGELOG line.

## Test list
- sweep note for a zero-unit sweep ends `units=0`; one with two units run ends `units=2`; a plain unit note has no suffix.
- registered `Foo` with remote `feature/foo` (and registered `bar` with `feature/BAR`) is not listed unregistered.
- doctor row remedy names `upkeep.units.exclude`; a branch matched by it is not counted.

## Risks
Note ref grows a suffix for sweeps only; per-unit refs are unchanged. Exclude filtering is display-only.
