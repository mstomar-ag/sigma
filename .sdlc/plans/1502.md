# Plan #1502 - shared rolling weekly and monthly spend cap

## Goal
One shared spend ledger read by the import classifier and the drift judge before every call. Optional keys
`rulebook.spend.weekly_usd` and `rulebook.spend.monthly_usd`, unset by default (byte-identical when unset).
Rolling windows (7 and 30 days). A call that would cross a cap is refused with one line, counted, shown in doctor.

## Files
- NEW `skills/sigma-loop/scripts/spend_cap.py`: `caps(config)` (positive numbers only, wrong type reads unset),
  `append(state_dir, source, usd, now)` (append-only JSONL under the sigma state folder, one write per line, fsync-free
  atomic append; prune lines older than 30 days when the file passes a bound, via write-temp-then-rename),
  `read(state_dir, now)` (ignores a torn or garbage last line), `check(state_dir, config, now)` ->
  `{ok, window, cap, spent, reset_at}` (reset_at = when the oldest in-window record ages out enough to get below the cap).
- `drift_judge.py`: before a call, `spend_cap.check`; refused -> typed not_judged reason `spend_cap_reached`; after a call, append
  the real cost (same value the daily ledger records).
- `decision_import.py` `classify_model`: before each call check; refused -> stop like the run ceiling, `info["cap_refused"]`
  set; `main()` prints one line `spend cap reached (weekly $X of $Y, resets HH:MM): ...`. After each call append the charged cost.
  Plan (call is None) sends nothing, appends nothing.
- `doctor.py`: one row when a cap is set: cap, spend, reset time. Nothing when unset.
- `rulebook_cfg.py`: no behaviour change for existing keys; add the `spend` block reader if cfg module owns key vetting.
- `skills/sigma-init/templates/config.json.tmpl`: `rulebook.spend` {weekly_usd: null, monthly_usd: null} + `_rulebook_spend` note.
- `docs/decision-rulebook.md`: Spend ceilings section + key table rows (own lines). CHANGELOG under Unreleased, own line.
- `docs/launch/write-surface.json`: register the new ledger file write; run tests/test_write_surface.py, tests/test_bk_gate.py.

## Test list (new file tests/test_spend_cap.py)
1. Caps unset: classify_model and judge calls, ledger file never created, outputs identical to before (byte-identical).
2. Weekly cap set: stub classifier cost per call; second caller (drift judge) refused once shared total crosses; line printed once.
3. Rolling window: records older than 7 days not counted; reset_at computed.
4. Ledger bounded (old lines pruned) and torn last line ignored (crash mid-write); unreadable ledger with a cap set fails closed.
5. Doctor row shows cap, spend, reset time; absent when unset.
6. Scenario through the real verb: `decision_import.py apply` on a temp repo with stub classifier, then drift judge call.
