## Behaviour
- Fake gh handles only: GET pulls/N (REST shape with `merge_commit_sha`, `head.sha`, `auto_merge`), PUT
  pulls/N/merge with merge_method merge or squash and a sha pin (409 and exit 1 on a stale pin), GET
  commits/SHA (parents list). A `merge` method builds a real two-parent commit on the bare remote and moves the
  base; squash builds a one-parent commit. `auto_merge` is null unless the state arms it.
- Any other call is appended to an unmatched log, written to stderr, and exits 1.
- `strict_runner(handlers)` has the existing `(cwd, argv)` contract; an unmatched call is recorded in
  `.unmatched` and raises (a non-zero gh), instead of answering an empty string.
- `rest_merges(calls)` matches `pulls/<n>/merge` with PUT (either method spelling) and `pr merge`/`git merge`;
  ignores the GET merged-check.
- `spy_landing(monkeypatch, gh_api, verify_merge)` records the four verify_merge names, `gh_api.merge_pr`,
  `merge_pr_pinned`, and the default runner's argv, so a REST merge from any entry is seen.

## Test list

3. PR object carries `auto_merge` (null, and armed when the state says so).
4. unmatched call: fake exits non-zero, logs it; the log names the call.
5. strict_runner records and raises on an unmatched call; matched calls still answer.
6. `rest_merges` sees a PUT via `merge_pr_pinned`, and via `merge_pr`; ignores a GET.
7. `_merges` in test_unit_completion sees a REST PUT (control: matcher reverted to CLI only, seen red).
8. chat spy sees a REST merge through gh_api (control: spy hook off, seen red); the chat never-lands test keeps
   `calls == []`.

## Risks
- git merge-tree --write-tree needs git 2.38 or newer; the fake skips (not passes) below that.
- A spy that patches names can be blind to a new entry; the default-runner hook covers argv at the seam.
- Hygiene: no names, paths, URLs or emails in committed text; git identity set by env in the fake world.
