## Behaviour (scenario)
Chain of four: end goal 1 waits on 2, 2 waits on 3, 3 waits on 4. Goal 4 (deepest) is parked, goal 2 is unarmed, goal 3 is in another unit (cross-unit edge), a prerequisite (goal 5, blocking 3) is filed mid-run. Flow: plan, sheet, answer --defaults plus cap, approve, arm, repeated run until done; members close deepest first (4,5,3,2,1 order respecting waits). Deterministic: same outcome and call log across 3 runs in-process.

## Four guard controls (each broken alone, seen red, gesture from the docs)
1. exclusive pool: pick without the chain label scope claims an outside armed goal -> scenario fails.
2. STUCK not DONE: empty pick with open members mapped to done -> fails.
3. fail-closed cap: unreadable spend ledger with a cap set treated as zero spend -> fails.
4. no write before approval: arm/any write path before approve allowed -> fails.
Each break is a monkeypatch/clause toggle applied in a control test (`test_control_*`) that asserts the scenario helper FAILS when the break is applied (run the scenario function inside `pytest.raises(AssertionError)`), plus a log of the red runs in the PR body.
