# Plan 1406: shared blocker-priority rule

## Goal
One pure helper every writer can call; the promotion pass uses it; default mode becomes the full rule.

## Files
- `skills/sigma-loop/scripts/discovery.py`: add `blocker_required_ranks(edges, ranks)` next to `blocker_promotion_rank`. `edges` is an iterable of `(blocker_ref, blocked_ref)`; `ranks` maps ref to current rank (missing or unreadable means lowest, the unprioritised rank). Returns `(required, cycles)`: `required` maps each blocker whose rank must rise to `(new_rank, cause_ref)` with the cause the most urgent direct dependent (resolved transitively); `cycles` is a sorted list of refs in cycles, reported once, no loop. Raise-only. Docstring documents the signature plainly (child F builds on it).
- `DEFAULT_BLOCKER_PROMOTION_MODE` becomes "always" (the full rule, no carve-out); "smart" stays accepted; explicit "off" is byte-identical to today.
- `skills/sigma-loop/scripts/sources.py` `_promote_blockers`: in the non-smart path use the shared helper; edge scan no longer requires the blocker to be a corpus member: a missing blocker's labels are read by one bounded REST read (cap per pass); an issue carrying the confirmation label is never a blocker; a blocker that cannot be written (another repository, read failure) is reported on stderr once. Smart path stays as is.
- `docs/backlog.md`: update the mode paragraph. `CHANGELOG.md` entry under Unreleased on its own line.

## Behaviour
Worked cases: P0 blocked by P3 raises P3 to P0; P3 blocked by P0/P1/P2 no change; equal stays; chain C->B->A raises C to A's rank; cycle reported once; unknown priority raised.
