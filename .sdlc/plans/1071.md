# Plan 1071: upkeep follow-ups

## Goal
Two review findings on the resolved-push path in `skills/sigma-loop/scripts/feature_rebase.py`: the runtime
acknowledgement file does not heal after a partial write, and the backup descriptor is checked after the proof.

## Files
- `skills/sigma-loop/scripts/feature_rebase.py`: `_write_runtime_acks`, new `_acks_well_formed`, `_rebase_feature`.
- `tests/test_upkeep_level1.py`: three new tests.
- `CHANGELOG.md`: one Unreleased entry.

## Behaviour
1. `_write_runtime_acks` no longer returns early on "nothing fresh" when the existing file is not a whole document
   (unparseable, or not an object with an `acked` list). It rewrites the file whole, keeping any parseable entries (none
   for a truncated file). A healthy file with nothing new is untouched. The write stays a plain `write_text`: no new
   delete-shaped or rename call, so the write-surface inventory is unchanged.
2. In `_rebase_feature` the `backup is None` refusal moves above `_prove_level1`. Same refusal code and text.

## Test list
- descriptor missing: `_prove_level1` is never called, nothing pushed, refusal names the descriptor (red before the move).
- truncated runtime ack file plus a resolved report with nothing to ack: file becomes `{unit, acked: []}` (red before).
- healthy runtime ack file with nothing new: bytes unchanged (guards over-eager rewrite).

## Risks
- Acks held only in a truncated file are lost; that fails towards refusing a pick (costs a pass, never data), as the
  existing `_acked` contract says.
- The rewrite happens only on the resolved-push path, so a damaged file with no resolved push stays until one occurs;
  readers already treat it as no acks.
- Not atomic: a crash mid-rewrite re-truncates, and the next resolved push heals again.
