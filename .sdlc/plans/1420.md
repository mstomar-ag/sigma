# Plan 1420: hold a goal whose open blocker the mirror cannot see

## Behaviour (smaller design, PROVISIONAL)
- `loop._pick_dependency_hold`: after the existing mirror resolution (and the hold refresh), if `unknown` is non-empty, resolve those refs LIVE with one REST issue GET each (`gh api repos/<repo>/issues/<n>` through the source's own `_run`), deduplicated and cached in the per-call `cache` so each ref is read at most once per `_next` call. REST has no multi-get; "batched" means one pass per pick over only the unknown refs.
- Live state open -> goes to `holding` (covers other-owner and no-goal-label blockers). Closed -> releases. A pull request, a read error or a malformed answer stays unknown: still claims, prints the existing stderr line (fail open).
- Zero extra gh calls when `unknown` is empty (common path, the pays-nothing test stays green).
- Cross-repo refs never reach here (read_refs/extract drop them); only same-repo refs are read.
- `backlog_check.cross_check`: after the corpus is built, any declared blocker ref (`_referenced_blocker_refs`) absent from the corpus is added to `degraded` as `blocker_unresolved:<n>` instead of being skipped silently.
