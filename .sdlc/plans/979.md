# Plan 979: harden the bounded runner before its first caller

## Approach
Five small fixes in the shared runner and the git runner, each with a red-then-green control.
1. The lifeline is told `done` only when the process group is confirmed gone (leader reaped,
   group probe negative within the reap bound). Otherwise the pipe is closed with no `done`,
   and the lifeline treats end-of-file as a dead caller and stops the group.
2. GitTimeout.argv is redacted to the program and the verb. The message was already clean.
3. The lifeline TERM-then-KILL escalation is pinned in tests, with a kill-first and a
   no-escalation control.
4. Each repository-location variable is pinned by name (set equality, strip, refusal text).
5. Split-mode memory was measured under a 300 MB flood: a 64 MiB cap peaked near 227 MiB
   (about 3.2 times the cap). The cap is now 16 MiB (peak near 74 MiB); comments say so.

## Files
- skills/sigma-loop/scripts/bounded_run.py and unattended_git.py.
- tests/test_bounded_run_hardening.py (new), test_unattended_git.py (argv assertions),
  test_bounded_run.py (one control variant also tells the lifeline done).

## Test list
- A second interrupt during the stop leaves no running group (red before the change).
- Lifeline: SIGTERM first with a graceful exit seen; SIGKILL after the grace for a TERM-ignorer.
- Location variables: set equality, one case per name for strip and refusal.
- Flood: peak memory under 128 MiB, and the old cap exceeds it (control).
- GitTimeout carries no argument text.

## Controls
Kill-first lifeline, no-escalation lifeline, dropped location name, old 64 MiB cap, and the
pre-change code for the done-after-gone and argv cases.

## Done when
Targeted bounded_run, unattended_git and hardening tests are green.
