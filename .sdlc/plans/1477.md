## Behaviour
- Candidates carry origin: transcript {kind, profile, folder, file, line, cwd}; comment {kind, issue, comment_id}. On a public repository (repo_visibility public) profile/folder/cwd are replaced by short sha1 hashes. Records and imported watch files copy the origin.
- plan/apply print per-folder counts (candidates, new records); non-own folders flagged "extra".
- require_repo_cwd (config) / --only-in-repo (flag): keep only transcript answers whose cwd is inside the repo root; report dropped count. Off by default: existing output and records byte-identical (test).
- `remove --project-dir X [--profile P] [--apply]`: dry-run lists matches; --apply unlinks only imported records and watch files whose origin folder (and profile when given) matches. Records without origin are left untouched and counted ("N legacy records have no origin; not removed"): the re-scan fallback for legacy records is a follow-up issue.
- Docs: every --project-dir is imported in full with no relevance check; how to remove.
