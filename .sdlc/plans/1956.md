# Plan #1956 map slice 1: snapshot on the ledger, DAG.md from it

## Files
- `skills/sigma-loop/scripts/dag_store.py`: `snapshot_path(ledger_root)`, `publish_snapshot(sdlc, doc, config)` (called by `save` after the local write; never fails a save), `load` falls back to / prefers the ledger snapshot, `load_with_source(sdlc, config)` -> `(map, why, source)` with source `local|ledger|none`; `load` keeps its `(map, why)` shape.
- `skills/sigma-loop/scripts/dag_render.py`: `render(records, snapshot=None, now=None)`; with a snapshot the snapshot is turned into edge/resolved facts and folded by the existing code, then a provenance block is added.
- `skills/sigma-loop/scripts/sync.py`: `publish` stages `dag/map.json` when present; `_write_dag` renders from snapshot + history (also when only a snapshot exists).
- `docs/dag.md` (one paragraph), `docs/launch/write-surface.json` (new writer), `CHANGELOG.md` (Unreleased), `tests/test_dag_snapshot_1956.py` (new).

## Behaviour
- Snapshot file `dag/map.json` in the ledger worktree: `clean(doc)` output, `schema: "dag/1"`, plus one top-level `built_by` = the writer's host token (`ledger._host_token`, no pid, aliased/salted as the entry files are). Atomic write (`state.atomic_write_text`). Only when `ledger.enabled` is true, mode is not `off`, and the ledger worktree exists. A title or any non-whitelisted field in the handed map never reaches the file (the same `clean`).
- `sync.publish`: `dag/map.json` joins the staged list when it exists, so a change that is only the snapshot still pushes.
- `DAG.md`: sections as today, chains/stuck/cycles/counts from the snapshot (a node whose state is not `open` is resolved; every edge counts), "Completed this month" from history; first lines say `Built by <token> at <built_at>` and `Snapshot age: <Nh Nm>` when `now` is given. Without a snapshot the output is byte-identical to today's (existing golden tests stay green).
- `load`: local ok and no/older ledger snapshot -> local. Local missing, corrupt, truncated, wrong schema, or older by `built_at` than a valid ledger snapshot -> the snapshot. The source is reported by `load_with_source`; the doctor/report wording is slice 4. Ledger off: no ledger path is touched, results identical to today.
- PROVISIONAL (owner to ratify): a corrupt local file falls back to the snapshot (the spec names missing/older); the snapshot is untrusted input and goes through `clean` and the same schema/shape checks on read.
