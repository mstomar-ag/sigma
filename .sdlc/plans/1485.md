and `pinned board #N reachable` rows must read "(cannot verify)" with wait-for-reset advice, never
"not logged in" / "does not exist" with an interactive login or create-a-board command.

## Behaviour
- Pinned board: rate-limit marker in failure text -> "unverifiable". "could not resolve to a" -> "gone".
  Bare "unknown owner type": REST owner lookup via `preflight.check_owner_type`; owner found -> new state
  "refused"; owner not found (REST 404) -> "gone"; lookup itself fails -> "unverifiable".
- Caller emits a non-pass row `pinned board #N reachable (cannot verify)` for "refused", fix text says GitHub
  refused the board read (usually the GraphQL rate limit), wait for the reset, re-run /sigma-doctor.
- `check_gh_auth`: after the existing rc 127/proxy/124 branches, retry once after a short injected pause;
  still failing -> `gh api user --jq .login`. A login, or a rate-limit marker in the text, gives ok=None,
  no commands, interactive=False, wording from the wizard transient fix. Only a REST 401 (or an
  unclassifiable REST failure with no marker) keeps "not logged in".
- `gh project scope` row follows through the existing blocker-ok-None branch (asserted, no code change).
