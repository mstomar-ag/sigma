## Rulings that bound this plan
- No real model call, ever. The resolver CLI probe (B7) is NOT run. Every test builds its own fake `claude` executable.
- A flag the design never probed is labelled UNVERIFIED in a code comment and in the docs. The launcher refuses any flag not in its confirmed-flag table. The table ships with only flags already used in the tree (`-p`, `--output-format`, `--model` as an alias only) marked "in use in the tree, not probed here"; every other design flag is listed as UNVERIFIED and refused.
- Feature optional, off by default. Gate closed means byte-identical: the module is imported by nothing until the upkeep pass calls it behind its gate.
- Tests use no network. Any new write, delete or push site is registered in `docs/launch/write-surface.json`.

## Behaviour
1. `launch(request)` returns a `Result` (outcome word, cost charged, changed-file verdict, reason); it raises only on a programming error. Order: gate closed returns `closed` and touches nothing; Windows or no process-group host returns `refused` naming the platform; model not in the catalog (or the placeholder id) returns `refused`; any requested flag not in the confirmed table returns `refused` naming it UNVERIFIED; the resolver directory fails the ancestor check or is inside the real home or the repository returns `refused`.
2. Ceilings, cheapest first: per-machine store behind a flock (unreadable means closed); then, only if that passed, count the ledger entry files with a directory listing; above 10,000 files park with the named reason and do not read (D-18); else `read_all` and sum 24 hours of `upkeep:resolver-spend:` notes; unreadable means closed. N-8: the limit is derived from a time budget on the machine (a measured per-file read cost from a short timed sample of the listing, scaled to a stated budget in seconds), with 10,000 kept only as the hard ceiling of record; the docs state the measured figures (0.2 s at 1,000 files, 0.5 to 1.8 s at 10,000, one warm local disk) and that cold or network disks were not measured.
3. Environment built from nothing: a short basic-variable list, a fresh configuration directory under a scratch root, no `GIT_*`, no `CLAUDE_PROJECT_DIR`; the credential variable is passed only when the operator chose it and only to the realpath-verified binary (D-12). The configured credential route is a refusal until chosen: the launcher never reads a secret into a file or log.
4. The prompt goes on stdin; untrusted blocks (hunks, bodies, stage contents) are nonce-delimited.
5. Wall-clock cap with group kill (TERM, grace, KILL) at the deadline, after a normal exit and on parent death. `--max-budget-usd` is a runaway guard only (D-13); the caps of record are the wall clock and Sigma's own metering.
6. Post-run check in Python: hash every file in the resolver directory before and after; any change outside the conflicted set, any new, deleted or renamed file, symlink or mode change discards the result and still charges.
7. Charging: a normal run is charged its metered cost (discarded and charged if it exceeds the per-run cap); a killed run (timeout, signal, parent death, missing or unreadable transcript) is charged the full per-run cap (D-19: a turn in flight at kill never reaches the transcript). The charge is written locally and as the ledger note, every time.
8. Output is bounded; nothing the model printed reaches a log unscrubbed.

## Test list
Each control is run once with the guarded line broken, seen red, then restored. Gesture: python -m pytest on the new launcher test file with -q, the same one the docs give.
1. Confinement: the fake edits an unlisted file, adds a file, swaps a file for a symlink, and flips a mode; each is discarded and charged. Break: skip the post-run hash compare and see all four go red.
2. Killed means full cap: the fake sleeps past the deadline, spawns a child, and in a second case exits with no transcript. The group is gone, and the charge equals the cap, not the metered amount. Break: charge the metered amount on a kill and see it red.
3. Confirmed flags only: a request carrying an UNVERIFIED flag is refused before the fake is spawned (the fake records an invocation marker; the marker must be absent). Break: delete the table check and see the marker appear.
4. Ceilings and guard: per-machine ceiling met refuses; 10,001 synthetic entry files refuses without calling `read_all` (a counting wrapper); an unreadable ledger refuses. Break: raise the guard to infinity and see the wrapper called.
5. Gate closed and environment: with the gate closed nothing is spawned or written (an `attempt_trap.AttemptTrap` shows no process, network or write) and the module's import is inert; with it open, the fake's recorded environment holds no `GIT_*` and no inherited credential, and the prompt arrived on stdin only (argv has no prompt text). Break: pass `os.environ` through and see the environment half red.

## Risks
- The transcript path and format a real `claude` writes are UNVERIFIED; the fake writes the shape `price_transcript` already reads. A real session may differ, so a missing or unparsable transcript charges the cap (safe side, never under-counts). Proof against the real CLI belongs to B7 and is out of scope.
- The `--model` value form (full id versus alias) is unconfirmed; the catalog ships the placeholder id until D-16 is settled, which keeps the resolver closed. The mismatch between the bench's pinned id and the pricing map's id is documented, not fixed here; changing the rate card is a separate goal.
- Team ceiling is eventually consistent: N clones can overshoot by up to (N - 1) times the per-run cap (D-18). Documented.
- The 10,000-file guard is a ceiling of record from a warm-disk, single-machine measurement; the time-budget derivation is the safeguard, and cold disks are unmeasured.
- Copying `refuse_ancestors` means two copies can drift; a small test pins their ancestor-file list equal.
- Pins in `tests/test_upkeep_pins.py` count importers of upkeep modules; the new module must be registered or those fail.
