## Behaviour
1. Reads: outside open blockers first (as today), but when corpus blockers exist at least min(len(inside), cap//2)
   of the cap is reserved for them. Inside blockers are read stalest-first (last-read epoch, 0 = never; ties newest
   ref first). After an apply pass the refs read are stamped. So with more than 10 legacy-labelled corpus blockers,
   ceil(n/slots) passes strip the same set as today's path. Dry pass and preview stamp nothing. Store bounded (500,
   newest kept), write failure costs only order.
2. Corpus rule: map life in goal/blocked/blocking/in-progress; a parked issue (even carrying the goal label) is not
   in it, as the label model says parked stands alone. Ratified PROVISIONAL (owner to ratify).
3. Other-repository notes: the map holds no text, so not produced. Result gets `map: True` on the map path only;
   `blockers_cmd` appends "(other-repository notes not counted on the map path)" when set. Old path output unchanged.
