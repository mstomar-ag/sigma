# Plan: biggest-chain-first order on both pick queues (1620)

Feature: dag. Epic 1606. Blocked-by 1619 (landed).

## Behaviour
A new sort term `chain_rank(issue_number)` = `(-open_dependents, -depth)` for a goal in the stored map, `(0, 0)` for
anything else (not in map, map unusable, `discovery.dag.order: off`, source `order: created`).
- dependents = count of open transitive dependents (`dag_core.open_dependents`).
- depth = longest chain of open dependents above the goal (new helper, memoised, cycle-safe: a cycle counts as one step).
Position: label path `_pick_key` tuple becomes (priority, feature_rank, chain_rank, not_a_bug, number); board path
Ready sort key becomes (card_rank, blocking, feature_rank, chain_rank, pos, n). The blocking split is structural on
the label path (a separate query) and the explicit 2nd element on the board path, so it is never crossed.
`order: created` returns a same-length tuple with a sentinel in the new slot.

## Files
- new `skills/sigma-loop/scripts/dag_order.py`: `chain_ranks(sdlc, config, cache, now) -> {number: (-deps, -depth)} | None`
  reusing `dag_pick._entry`'s usability gate (usable map and a change check within 600 s); None when order is `off`,
  the map is unusable or any error. Computes the table once per call (linear), kept in `cache`.
- `sources.py`: attribute `self.dag_chain_ranks` (default None) read by `_pick_key` and the board sort; `_chain_rank(n)`.
- `loop.py`: where the pick sets per-batch attributes (near `_dag_first_pick`/`_dag_check_pick`), set the source
  attribute once per `next`/`next_batch` call, only for a GitHub source and `discovery.order == priority`;
  mode `off` or no `state/dag.json` file: dag_order is not even loaded.
- docs: one paragraph in the DAG doc (`docs/` file that documents `discovery.dag`) incl. the 200-oldest-window limit and tie order;
  CHANGELOG line under Unreleased; config template/script help only if a registry test demands it.
