# Plan 1089: liveness guard for settling a never-called pending landing record

## Files
- skills/sigma-loop/scripts/feature_upkeep_landing.py: LIVENESS_SECONDS constant (with reasoning) and a guard in settle().
- tests/test_upkeep_landing.py: new tests; two existing tests moved to an old-enough `now`.

## Behaviour
A record with no call recorded and `started_at` younger than LIVENESS_SECONDS (600) is another process's landing that
may still be between begin and the merge call. settle() returns Verdict(unconfirmed, landing-in-flight) with no
reads and no write; the record stays pending, so a concurrent begin is still refused (unsettled-record). An older
never-called record settles as before (refused crash-before-merge) and the retry lands. Records with a recorded call
are unaffected. A future-dated record (clock skew) counts as young. Gate closed: unchanged (settle returns None).
The threshold reasoning is in the constant's comment and the module docstring.

## Test list
- young never-called record: unconfirmed landing-in-flight, no reads, record still pending, begin refused.
- record exactly at the threshold settles as crash-before-merge and the next begin succeeds.
- future-dated record counts as young.
- crash-window retry through run_landing at an old-enough clock still lands merged.
- existing recorded-lost-call and closed-gate tests unchanged.

## Risks
- A real crash blocks the unit for up to ten minutes; accepted, and the doctor row shows the age.
- Clocks differ between processes; the guard errs towards leaving the record.
