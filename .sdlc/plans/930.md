## Behaviour

1. Tip and base ref resolve through `git rev-parse --verify`; a failure is UNKNOWN with a reason.
2. `git merge-base --is-ancestor`: rc 0 LANDED (via ancestry); rc 1 not an ancestor; any other rc says nothing.
3. Only if not LANDED: `gh api repos/<slug>/pulls?head=<owner>:<branch>&state=all&per_page=30&page=N[&base=]`,
   projected with a jq filter (number, state, draft, merged_at, created_at, merge_commit_sha, head sha, base ref),
   paged to a short page or 4 pages, sorted by (created_at, number), with a truncated flag.
4. A PR lands the tip only if merged, head sha equals the tip and base ref equals the base.
5. NOT_LANDED only when ancestry said rc 1 and the PR read was clean and complete; otherwise UNKNOWN. A merged PR
   with a different head is reported as `merged_head` (D-13); nothing consumes it here.
6. Runner: built on `bounded_run.run_group` (split mode): rc preserved, process group stopped on timeout (124),
   missing binary or unrunnable platform 127, location variables scrubbed, `LC_ALL=C`, timeout from
   `SIGMA_WATCH_CALL_TIMEOUT` (default 120, minimum 5).
7. Slug: `feature_sync.repo_slug` then a check that `git remote get-url` names the same repository (case-folded).
8. Gate closed: `drift_watch` output and calls are unchanged; the predicate is not run.
