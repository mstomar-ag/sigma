## smoke.py design
- Load `evals/skill_structure.py` by path (`importlib.util.spec_from_file_location`, as
  `tests/test_skill_structure.py` does) for `COMPACTION_TOKEN_CAP`, `CHARS_PER_TOKEN` only;
  `sys.path[0]` is `evals/skills` when run as a script. Kept prefix = first `CAP*CHARS` chars.
- argparse: `--root` (skills dir, default `<repo>/skills`), `--cards-dir` (default
  `evals/skills/cards`), `--help`. Repo root for producer paths = `--root`'s parent.
- Discovery: `sorted(p.name for p in root.iterdir() if p.is_dir() and not p.name.startswith("."))`
  (plain files and dot-dirs ignored); cards = `cards_dir/*.json` (absent dir = no cards).
- Card: `{skill, kind: exercised|pinned|described, gates[], scripts[{path, role: gesture|library,
  fixture?}], artifacts[{path, producer}]}`.
- Findings (each names skill + item): dir without card; card without dir; dir without `SKILL.md`;
  gate not in kept prefix; producer neither an existing repo path nor literal `agent`; `exercised`
  with no passing fixture run (derived by running the fixture via subprocess with timeout; card
  says `described` otherwise); on-disk `skills/<s>/scripts/*.py|sh` in zero or 2+ entries; entry
  with no file; role `gesture` without fixture is a finding, role `library` exempt; bad kind/role
  and malformed JSON are findings, not tracebacks.
- Output: one row per skill (kind), findings, footer (counts found, never a literal), own wall
  time. Exit 1 on any finding, else 0.

## Steps (test-first, one rule per step)
1. Write `tests/test_skill_smoke.py` helpers (`_tree(tmp_path)` builds skills + cards) and the
   first test (clean tree green); stub smoke.py; see it red.
2. Per rule: write test, see red against a stub, implement, see green (list below).
3. README section + gesture tests. Gesture is the fenced `python3 evals/skills/smoke.py --root
   <skills> --cards-dir <cards>` line; the test extracts it from `evals/README.md`, substitutes
   the two placeholders with fixture paths, runs it with `cwd` = repo. Prose says the bare
   real-tree form stays red until cards exist (slice 3). Files named as code spans, not links.
4. Control (documented in the PR, not committed code): break each rule in smoke.py once (drop the
   both-way compare, read whole file instead of prefix, accept any producer, skip the exercised
   check, skip the scripts check, count `iterdir` through `skill_dirs`), see its named test red,
   restore. Also run the README-copied gesture with the `--cards-dir` omitted from the doc line to
   confirm the test would go red on the wrong gesture.
5. Run `python3 -m pytest tests/test_skill_smoke.py tests/test_documented_gestures.py
   tests/test_doc_links.py tests/test_third_party_imports.py -q -p no:cacheprovider`, then the full
   suite by the CONTRIBUTING gesture; `python3 tools/leak_scan.py` clean; `smoke.py --help` works.

## Scalability / resiliency / safety
Cost is linear in skills plus one subprocess per `exercised` fixture (timeout-bounded, so a hung
fixture is a finding, not a hang). Read-only on the tree; no network, no background process.
Measured wall time is printed by the tool itself; no ceiling claimed here (slice 4 sets it from
CI runs). Not measured: behaviour on the real tree (no cards yet).
