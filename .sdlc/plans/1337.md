# Plan 1337: level-4 spot check is a counter

Plan sha256: pending
## Behaviour
In `applier.tick`, replace `_spot_check(ask id)` (hash sample) by a per-(qkind, area) counter. State: `<applier folder>/spot-counter.json` mapping `qkind|area` to the number of silent-eligible applies so far. For a silent-eligible action (level 4, silent allowed) the next count n = stored + 1; it comments when `n % spot_check_one_in == 0` (N=1 comments every time); otherwise silent. Within one tick, count actions in plan order. The file is written (atomic, existing `_write_atomic`) only when `apply_actions` is true and only after the actions were applied (count only results of done). Missing or unreadable file reads as empty. Closed gate: untouched (`tick` returns [] first). Keep `_spot_check` removed or unused-safe; do not change text.
PROVISIONAL (owner to ratify): the second half of the suggestion (refuse silent mode when an apply does not match its option) is not done; the counter is the smaller design.
