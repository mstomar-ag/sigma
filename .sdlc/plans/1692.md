## Behaviour
1. Session mode (plan host session path) skips the protected-path, structural, merge-stop and count-limit refusals in eligibility(). Non-session (legacy) mode stays byte-identical (test it).
2. Stops with missing stages (add/add, delete/modify, rename) are given to the session with the stage versions; the engine applies the outcome (git add or git rm). Existing proofs (no unit/base line dropped, verify, independent review) stay the gate. A protected path keeps an extra rule only where proofs cannot cover it; the park says why.
3. Retry inside the session: a refused proof (markers, dropped line, outside edit) feeds the reason back to the same session, bounded by timeout_minutes, before parking; the park finding names why the last try failed.
4. Attempt record is keyed by unit tip + base tip: a moved base starts fresh; old entries age out; a started entry that never settled (sweep cap or crash) is not counted as used.
5. Count limits: a replay that fits timeout_minutes is not refused; any limit that remains names its reason.
