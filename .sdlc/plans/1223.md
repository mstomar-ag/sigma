## Behaviour
- Transcripts: for each profile dir read `projects/<repo folder>/*.jsonl`. An `AskUserQuestion`
  tool_use is held by its id; only the tool_result with that same id is read, and only the answer
  text. Every other tool_result is ignored.
- Comments: through `sources.fetch_comments` (injectable), the fenced `sigma:unpark-qa` span gives
  question/answer pairs and the decision lines (kind, choice, reason) of a record comment.
  Comments are read only when `import.comments` is true; the default scan is local only.
- Candidate: source, when, question, options, choice, reason, issue, id (sha1 of file name plus
  line and question index, or comment id plus index). Same input gives the same ids.
- Later differing answer for the same issue and question marks the earlier one `superseded`.
- Malformed line or file: skipped and counted. Caps: a file over the size cap is skipped and a
  refusal line names it; reaching the candidate cap stops with a refusal line.
- `scan` prints per source counts and at most 10 sample lines, question and choice clipped to 60.

## Test list
- ids are stable across two runs and the answer pairs with its question
- a secret in another tool_result never reaches any candidate
- malformed line and malformed file are skipped and counted
- file size cap and candidate cap print a plain refusal

- unpark-qa and decision span parsed via an injected comment reader; closed comments flag reads nothing
- scan CLI: counts, at most 10 clipped samples, no full text, writes nothing to the tree
