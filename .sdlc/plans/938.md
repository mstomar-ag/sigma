## Behaviour
1. Gate first (`upkeep.evaluate(config, "project")`); closed returns the closed verdict with no read, no write.
2. Last re-read: unit tip must equal the verified head and the base tip must equal the one verified against, else
   `refused:tip-moved`. A base that moves after this read cannot be prevented (D-11): the read-back reports it as
   merged-with-warning.
3. The guard is the LAST gate: `feature_land_approval.authorize` (attended consent, or the single-use approval
   consumed create-once, bound to the head). A denial is `refused:guard`.
4. `feature_upkeep_landing.run_landing` writes the pending record BEFORE the call (no record, no call), makes the
   call, reads the pull request and the merge commit back, classifies, settles the record.
5. The call is `gh_api.merge_pr_pinned(run, slug, number, head, merge_method="merge")`: explicit method, 40-hex head
   pin, no auto-merge, no admin flag, no branch delete. A moved head makes the host refuse (status 409) and the
   read-back shows still open: outcome refused.
6. Record once: on merged or merged-with-warning, a create-once marker `<unit key>.recorded-<pr>.json` in the
   pending store is taken before the observation writer is called; a second run finds the marker and records nothing.
7. Branch-existence check after the call: a unit branch gone from the remote is reported loudly with a restore hint
   and never recreated. Landing never deletes the branch.
8. Outcomes: `merged`, `merged-with-warning`, `armed`, `refused:<reason>`, `unconfirmed:<reason>`.
