# Plan 1338 - acceptance record required before verify runs
Plan sha256: (set by tool)

## Behaviour
Root cause: `loop.py verify` tolerates a missing acceptance record (digest None); `work.py pr` then demands one, and writing it changes `acceptance_sha256` so `state.done_refusal` says "acceptance record changed since verify" and verify must re-run.
Fix: in `loop.py verify_goal`, when `state.enforce_enabled(config.get("verify"))` (the same gate `work.pr` uses) and the acceptance record is missing, refuse BEFORE running the command, exit 4, message names `acceptance.py record .sdlc <goal> --draft <file>`; write an actionlog/ledger event like the STALE path. With enforce off, nothing changes (byte-identical).

## Files
`skills/sigma-loop/scripts/loop.py` (verify_goal), `CHANGELOG.md` (Unreleased), new `tests/test_verify_requires_acceptance.py`; adjust any existing verify test that runs enforce-on with no record (record one in the fixture).

## Test list
- enforce on, no record: verify exits 4, proving command never ran (red before fix).
- enforce on, record present: verify runs once and a later commit and pr need no second verify.
- enforce off, no record: verify result identical to before.
- Control: remove the new check, first test goes red.
