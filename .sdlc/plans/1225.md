# Plan 1225: run the upkeep due-check once after Sigma's own successful merge

Feature: rubric-wiring

## Goal
After `work.merge` lands a PR (the `PR #N merged (...)` return), run the scheduler's decision once so a unit behind the
merged base is considered at once on THIS machine. Other machines keep the watch tick and the session-start report.

## Design (smallest that meets the issue)
- `feature_upkeep_sched.py` gains a `decision <sdlc_dir>` command (`main`): reads the config, calls `scheduler_tick`
  with `started_by="trigger"`, prints nothing. Same gate, cooldown, per-unit claim and job lock as the tick.
- A trigger pass is quiet by construction: it does not rewrite the tick status file (that file's age is the tick
  liveness, so a trigger must not mask a dead watcher) and does not collect outcome notes (the long-lived watcher
  is the one writer of those).
- Every pass that starts a job writes `state/upkeep/last_start.json` with `by` (trigger, tick or pick), unit, run id, time.
  The doctor shows it as the row "upkeep last start".
- `work.py`: one helper `_upkeep_merge_trigger` called last in `merge()` on the landed path. Gate first
  (`_feature_upkeep().enabled(config)`); closed means no call and no output. Open: one spawn through
  `run_with_timeout.py` (timeout from `SIGMA_WATCH_CALL_TIMEOUT`, default 120), own try-guard, failure or
  timeout logged once on stderr, return value of `merge` untouched.

## PROVISIONAL (owner to ratify)
- The `pick` value is in the vocabulary but no pick path calls the scheduler today (pick only runs the per-goal
  `_rebase_upkeep`), so nothing writes it yet.
- The trigger writes no tick-status file; the cost is that a trigger-only pass is visible only in the last-start row.
- Only the success return of `merge` triggers; armed auto-merge and the reconcile pass do not (merge not yet a fact).
- Stderr is the log (merge has no watch log); the machine door is left to the decision itself.

## Test list
- gate closed: merge output and calls identical, trigger helper never invoked
- gate open: one timed call, argv through run_with_timeout.py and `decision`; merge output unchanged
- trigger raising, or timing out (exit 124): merge output unchanged, one stderr line
- scheduler: trigger pass starts the due unit once, tags `trigger`, leaves the tick status file alone
- control: merge source without the trigger call fails the test; without a trigger the unit waits for the next tick,
  which starts it tagged `tick`
- two passes in a row start one job (cooldown/claim)
- doctor row shows the last start's tag
- CLI `decision` with the gate closed prints nothing
