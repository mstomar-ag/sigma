# Plan 1947: records never commit onto the default branch

## Design (docs/decision-rulebook.md says why)
Chosen: a dedicated local records branch `sigma/records`, built with git plumbing so the root checkout never moves; Sigma never pushes it. Why not the ledger branch: it is a separate sharing feature that may be off. PROVISIONAL (owner to ratify).

## Files
- skills/sigma-loop/scripts/decision_store.py
  - `publish()`: when HEAD is the default branch (short name of `_default_ref`, else main/master) return `{"committed": False, "reason": "default-branch", "command": <the one command>}` and commit nothing. Other branches behave as before.
  - New `publish_branch(sdlc_dir, config)`: commits the records, autonomy and rulebook paths onto local branch `sigma/records` using a temporary index (GIT_INDEX_FILE) plus `commit-tree`; parent = existing `sigma/records` tip, else the default ref tip, else a root commit. Never checks out, never pushes, nothing-changed (tree equals parent tree) => `{"committed": False, "reason": "nothing-changed"}`. Returns `{"committed", "reason", "branch", "push": "git push <remote> sigma/records"}`.
  - `main`: `publish <dir> --branch` runs `publish_branch`; the printed command in the refusal is `python3 decision_store.py publish <dir> --branch` with its real absolute path.
- skills/sigma-loop/scripts/decision_record.py: `write_all` keeps the best-effort call; when the result reason is `default-branch` it prints one stderr line with the command.
- docs/decision-rulebook.md: the design and the one command (replace "commits, never pushes" wording where it claims a commit lands on the current branch); CHANGELOG under Unreleased; update the usage line and any help/registry test that lists the verb.
- tests/test_decision_publish_default_branch_1947.py (new).

## Behaviour
On main: gesture makes no commit, `git pull --ff-only` still works, a hint line names the command. On a non-default, non-unit branch: unchanged local commit. `--branch`: creates/advances `sigma/records` without touching HEAD, index or working tree.

## Test list
- on main with a bare origin: record a human decision; `main` tip unchanged, `git pull --ff-only` succeeds; red if the default-branch clause is removed from publish().
- publish() on a feature-less non-default branch still commits (guards the clause is only the default branch).
- default-branch detection: origin/HEAD names `trunk` => `trunk` refused, `main` not refused; red under hardcoded main/master only.
- `--branch`: sigma/records has one commit containing only the evidence paths, HEAD/index/status unchanged; second call with no change makes no commit; a change advances it with the old tip as parent.
- hint printed once to stderr by write_all.

## Risks
Records stay untracked in the root working tree after `--branch`; a later merge of the records PR can make `git pull` refuse over them. Documented: the same command's docs say to run `git checkout`-free cleanup is NOT done by Sigma; owner follow-up if needed. Registries: write-surface inventory, test_feature_registry decision_store line, script help.
