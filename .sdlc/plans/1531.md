# Plan: bounded hold on claimed-but-unstarted goals (#1531)

## Goal
A goal claimed by a live session but never started (no work record, no agent marker/beat) is
handed back by the next pick in ANY session once it has been held longer than a bounded hold.
next-batch never keeps more claims than its session's free slots.

## Research
- `loop._release_unstarted` / `_goal_started` (from #1529) already release unstarted goals through
  the shared `_release` (label off, "claimed but not started" comment, ledger release, action log).
- `_session_entries` lists every session's registry entry; `_session_pid_live` says which are live.
  Registry holds goal ids only, no claim time; the action log's `claimed` entry carries a timestamp.
- `next_batch` fills `max_concurrent` slots per call and ignores goals the session already holds.

## Design
1. Config `session_release.hold_minutes` (default 30; 0 or false turns the hold off; a bad value reads as the default). Documented in the config template and
   docs/action-log-and-ledger.md.
2. `_release_held_unstarted(sdlc_dir, config)`: GitHub source only, hold enabled. For each goal in
   any LIVE session's `in_flight`, read the newest `claimed` action-log entry; if its age exceeds
   the hold and `_goal_started` is False, release via `_release_unstarted(..., "claimed but not
   started: held past the hold")`. No timestamp found means keep. Fail-open, returns the released set.
3. Called from `next_batch` prologue and from `_next` when it is a standalone pick; the released
   set joins the pick's skip set so the goal is not re-claimed in the same call.
4. `next_batch`: free = max_concurrent minus the goals this session already holds in its own entry.
   The cap is applied before the pick loop only (no separate surplus release). It applies only when
   the hold is on, max_concurrent comes from config, and the ceilings branch (whose admitted count
   already includes in-flight goals) did not already subtract. At 0 free slots one probe pick still
   runs so a terminal (DONE/BUDGET/HANDOFF) prints as before; a goal it claims is handed back.

## Test list
- goal held past the hold by a live session (other pid) is released by another session's pick
- a goal with a work record, an agent marker, or inside the hold is kept
- hold_minutes 0 releases nothing and next_batch output is unchanged
- next_batch with 2 of 3 slots held returns at most 1 goal
- neighbours: tests/test_session_unstarted_release.py, test_loop.py (batch/session areas),
  test_write_surface.py, test_no_direct_gh.py

## Risks
Claim time comes from the action log; with the log off nothing is released (safe default).
Default-on hold changes GitHub behaviour only for goals idle over 30 minutes.
- hold off with held goals: next_batch pick count/output as before
- ceilings case: held goals are not subtracted twice
- 0 free slots: terminal line still printed, no goal kept
