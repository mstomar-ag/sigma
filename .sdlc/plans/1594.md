## Behaviour
- `chain.py status [<chain>] [--json] [--rebuild] [--leftovers]`; no chain argument = every record in `.sdlc/state/chains/`.
- Closed state set: planned, approved, running, stuck(<reason>), paused(decision), capped, done, stopped. Derived from the record: no run block -> planned/approved by record `state` (awaiting-answers reads planned); run.state running/approved-running -> running; stuck -> stuck(run.stuck) except reason `decision` -> paused(decision); capped, stopped, done as recorded.
- `last_progress_at` = run.heartbeat (else null) and its age. A `running` chain whose heartbeat is older than `chain.stale_minutes` (default 30; invalid value -> 30) prints `running STALE`; done/stopped/capped/stuck/planned/approved are never STALE. A running chain with no heartbeat at all uses `armed_at`.
- Stopped or stuck prints ONE root-cause line from the record's members and reason: `X, Y, Z wait on #N's decision; /sigma-unpark #N` (numbers only; for a non-decision reason the line names the reason and the member number).
- `--rebuild`: regenerates the local record from the chain label and the recorded Q&A: `plan()` rebuilds members and edges from the label and map; the answers kept in the old record (or an `--answers <file>`) are re-applied through `answer()`. Approval and the run block are NOT regenerated (re-approve). PROVISIONAL (owner to ratify): the issue names no other Q&A store.
- `--leftovers`: chain labels (from the records) with no open member, read through an injectable gh runner; read only, removing one is the person's step.
- Slot facts: `slot_facts(status)` returns a render.py slot dict (marker by state: running 🔵, stuck/paused 🔴, capped/stopped ⏸️, done ✅, planned/approved ⚪; phase token `P5 IMPLEMENT`; description <= 20 words) so the existing renderer builds the line; no new block shape.
- Doctor row `chain: <state> (<age>)` informational ok=True; STALE/stuck is ok=False with the fix `chain.py status`. No chains -> no row.
- Read-only toward GitHub and the record, except `--rebuild`.
