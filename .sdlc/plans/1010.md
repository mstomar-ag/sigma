# Plan 1010 - migrate-confirmation verb (decision rubric, slice 20)

## Goal
`promote.py migrate-confirmation <sdlc_dir> [--dry-run|--apply]`: one-time move of every issue still
carrying the confirmation label either to armed (`sdlc:goal`) or to an ordinary park, through the same
triage (`file_triage.decide`), the same blocker and gate predicates `apply` uses, and the atomic
label swap in `sources.py`. Dry run is the default and makes zero writes.

## Files
- `skills/sigma-loop/scripts/promote.py`: new region before `_USAGE` (migration), main() dispatch, usage line.
- `skills/sigma-promote/SKILL.md`: document the verb.
- `tests/test_promote_migrate.py`: new, fake source only, no network.
- `CHANGELOG.md`: one line under Unreleased.
- No new REST/GraphQL/gh call site: reads go through `sources.fetch_issues_rest` and
  `source._read_issue`, writes through `source._swap_labels`, `source._issue_comment`,
  `source._set_board_status`. The write-surface inventory and the direct-gh ratchet are re-run to prove no row is due.

## Behaviour
- `migrate(source, config, apply=False, sdlc_dir=".sdlc") -> report dict`
  - refuses (no calls) when the source cannot do label swaps or when `ai_filed.triage.enabled` is false
    (the queue is then still the intended state).
  - fetches ALL labelled issues, state all, by REST paging (`fetch_issues_rest`, cap `MIGRATE_FETCH_CAP` =
    10000, overridable by `ai_filed.migration.max_issues`; PROVISIONAL), not the 200 backlog window.
    M = number fetched; a fetch that hits the cap is reported as incomplete.
  - per issue: closed -> untouched; live re-read says label already gone -> noop; else
    `classify_population` -> `plan_for` -> (dry: report) / (apply: one `_swap_labels`, then one comment).
  - N (covered) = every issue handled without a read or write failure. Exit 1 when N < M, a fetch error,
    or truncation; 2 when refused or bad flags; else 0.
- `classify_population(issue)`: ownership flag comment marker -> `ownership_hold`; scope-expansion marker ->
  `scope_hold`; `sdlc:followup` label -> `followup`; otherwise `human`.
- `plan_for(issue, config, unresolved=(), hold=None) -> Arm | Park`: holds and populations that carry a
  registry decision always park; an unresolved blocker or a gate hold parks (qkind dependency / needs_decision);
  followup -> `file_triage.decide(..., {})` bucket priority (an existing lower priority is kept); human ->
  `decide(..., {human_confirmed, priority})` keeps its own priority, no priority parks.
- Swap: arm = add goal (+ priority label if changed), remove confirmation (+ old priority); park = add parked,
  remove confirmation (and goal if drift). ONE mutation each, so never a pair.
- Comment: first line is a marker; says armed or parked, the population and the reason; parks carry a qkind line.
  Skipped if the marker is already on the issue. Posted after the swap, best-effort, reported on failure.
- Second run: label gone, so nothing fetched (or live noop): zero writes.

## Controls (max 5)
1. remove the blocker predicate -> blocker test red. 2. page cap at one window -> paging test red.
3. swap split into two calls -> pair test red. 4. dry-run flag ignored -> dry run test red.

## Risks
- Marker strings are copied literals (heavy module loads avoided); a test pins them to the owning modules.
- Priority label may not exist in the repo: `_swap_labels` raises before any write, so the issue reports failed, untouched.
- PROVISIONAL: cap 10000, keep-lower-priority rule for follow-ups, owner and scope populations always park.
