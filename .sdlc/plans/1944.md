# Plan: deps.py report across a label or a chain (goal 1944)

Spec: the issue body. Unit: rollout-fixes.

## Behaviour
- `deps.py report <sdlc_dir> --label <label>` and `deps.py report <sdlc_dir> --chain <N>`; the existing
  `report <sdlc_dir> <goal>` form is unchanged byte for byte.
- Batch output: one JSON object per member per line (the exact single-goal object, `sort_keys`), ordered by
  issue number; a final summary is NOT added to stdout (keeps each line identical to the single form).
  Chain members = the goal N and every open prerequisite the chain planner already computes (reuse
  `chain.py`'s member listing; do not re-implement the walk).
- One process, one listing read: member bodies (and comments where the listing carries them) come from the
  existing label listing the label-drain uses; where comments are not in the listing, they are read inside the
  same process with the existing `_read_issue`, bounded, never a subprocess per member. The module docstring
  states this honestly (what is one read and what is not) with the measured process count, not a claimed speedup.
- An unreadable member prints its line as `{"goal": N, "error": "..."}` and the exit code is 2 at the end;
  no member is skipped silently.
- Help text (USAGE) and `docs/dag.md` name the new forms.
