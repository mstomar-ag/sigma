# Plan 1402 - back-fill stops after a refused project call
Plan sha256: (set by tool)

## Behaviour
In `GitHubSource` (sources.py): count consecutive refused `gh project` calls on the instance (`_project_refusals`). A call counts as refused when `_run` raises for a project call after its retries and the error is the rate-limit refusal or the bare owner-lookup text; any successful project call resets the count to 0. `backfill_board` returns 0 without writing when the count is at or above `project.backfill_max_refusals` (PROVISIONAL default 1, owner to ratify; a bool or non-positive int means the default), trusting this over the rate-limit counter. Inside one tick, a refusal raised during `_sync_backlog` already aborts the rest of the card writes because the exception propagates out of `backfill_board`; add a test that proves exactly one refused call is made after the first refusal. With backfill off, board off, or no refusal, behaviour is byte-identical. Document the key in the config template only if the other backfill keys are listed there (same line style).
