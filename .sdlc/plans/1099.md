# Plan 1099: de-flake test_timeout_kills_the_group_and_charges_the_cap

## Cause
`bounded_run.run_group` starts its wall-clock budget right after the spawn. The test uses a 1s budget and then reads
`child.pid`, which the fake `claude` writes only after python has started and spawned its grandchild. Under suite load
startup exceeds 1s, the group is killed first, and the pid file is missing. Same shape as #1073 (board phase).

## Files
- tests/test_upkeep_launcher.py only. No production change: the launcher and `run_group` are correct; the test's
  assumption (child ready within 1s of spawn) was the defect.

## Behaviour
- The fake gains a `delay` mode key (seconds slept before it spawns its grandchild).
- `_budget_starts_when_ready` wraps `subprocess.Popen` so the spawn of the fake binary returns once `child.pid` is
  written (bounded 30s wait, not a raised timeout); the budget then starts from a running child.
- The kill test uses it; the 1s timeout is untouched.

## Test list
- test_control_a_slow_starting_child_is_what_made_the_kill_test_flaky: delay 2s vs 1s budget; ungated, killed with no pid
  recorded (old shape racing); gated, pid recorded and outcome killed.
- test_timeout_kills_the_group_and_charges_the_cap: gated; same assertions as before.
- Full file under pt.sh, then 10 repeats with -n 4.

## Risks
- Popen wrapper matches argv[0] to the fake binary only, so the lifeline process is unaffected.
- If the fake never writes the pid the wait ends at 30s and the test fails with the original missing-pid error.
- The ungated control relies on a 2s sleep vs 1s budget: deterministic, costs about 2s.
