# Plan 1940: Chain reads three more dependency wordings

Unit: rollout-fixes. Spec: the issue body (Done when list); no owner ruling on it. The two wordings with no
issue number ("built in S7", "depends on rulings in the <name> item") stay a documented limit: nothing to resolve.

## Behaviour (all in `chain_waits.py`; `blocker_scan` and the gate/map/drain stay untouched)
1. Slice codes. `find()` collects, per text, a code map from `<code> (#N)` (code = letter + digits + optional
   letters, e.g. S2a; the number in parentheses straight after it). A written chain "S2a, S2b, S2c must precede S2d"
   (also "S2a, S2b and S2c precede S2d", "... must land before S2d") is read as: S2d waits on each of S2a..S2c, but ONLY
   when EVERY code of the chain resolves through the map; one unresolved code reads nothing from that sentence.
   Form name `slice-chain`. The "X on Y (#N)" wording ("S4b on S4a (#N); S4a starts only once ... has landed")
   is covered by the same `<code> (#N)` map plus the existing `only-once`; plus a new form `code-ref`: "<code> (#N)"
   after "on"/"per"/"after" read as a wait (unconfirmed) when the sentence names THIS issue's own code... keep it
   narrow: ONLY the slice-chain and "X on Y (#N)" shapes in the table are in scope, nothing broader.
2. Comments. New forms `waiting-on` ("waiting on #N", any subject, only in a trusted comment: the assignee or an
   OWNER/MEMBER/COLLABORATOR, as today) and `gates` ("#N gates #M"; PROVISIONAL (owner to ratify): both #N and #M are
   read as unconfirmed waits). Both only from comments, never from a body or an untrusted author; always unconfirmed
   (asked on the sheet, never silently trusted).
3. Reversed. New form `reversed-waits-on`: "the <noun> #N waits on" at a clause end = this issue waits on #N.
   Not matched when "waits on" is followed by a reference ("the story #N waits on #M" says #N waits on #M).
Negation and own-subject rules keep applying where they do today. Add the form names to `FORMS` and the module docstring
table; every consumer that lists forms (sheet text, docs/chain.md form list, tests that pin `FORMS`) is updated.
