# Plan 1134: call the ledger pointer writer from the record writers

## Files
decision_record.py (`write_all` after a stored id), handoff.py `_record_ack` (stores via `decision_store.append` directly), tests.

## Behaviour
- After a record is stored, `ledger_pointer.write_pointer(sdlc_dir, [(id, qkind, how)], config)` is called. It is already inert when its own gate is closed and never raises; wrap anyway so a ledger problem never touches the gesture.
- Batching is the pointer library's (queue plus daily budget); callers only hand over triples.
- Closed pointer config: zero bytes written, zero calls that write.

## Test list
- Real gesture (unpark with stubbed source, ledger on, pointer on) leaves a pointer entry on the ledger that `ledger_pointer.parse` reads back.
- Same for ack and sweep path through write_all or the store append.
- Pointer closed: no ledger entry, no pointer state file.
- Pointer failure does not change the gesture result.
