# Plan 2021: auto-unpark sweep caches comment reads

Plan sha256: pending

## Behaviour
- auto_unpark.py: a read-through cache `(issue number, updated_at) -> scrubbed comments`, stored in `.sdlc/state/auto-unpark-cache.json` (atomic write, bounded: entries for issues not in the current parked set dropped each sweep; entry cap documented). A hit needs the list payload's `updated_at` equal to the cached one; mismatch or missing updated_at -> re-read. Placed at the two auto_unpark read sites (around :382 and :507) sharing ONE read per issue per sweep (in-sweep memo); NOT inside `_fetch_scrubbed_comments` (shared with backlog_check, whose goal_doc has no updated_at).
- Interval gate: `discovery.auto_unpark.interval_minutes` (PROVISIONAL default 10, owner to ratify; 0 = every pick, today's behaviour). State file `.sdlc/state/auto-unpark-last.json` records last sweep time and session id; first pick of a session always sweeps. Gate lives in or beside `sweep_unpark` (not only loop._auto_unpark_sweep) so chain.py's direct call is covered.
- Failure to read/write cache or gate state fails open (sweep runs, no crash).
- Fix the config template note claiming two list calls per pick.
- Use the #2019 counter (gh_calls) in the test to assert request counts, not a wall-clock claim. Measured saving: only what the test counts on a fake runner; "not measured" against the real repository.
