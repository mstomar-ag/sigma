# Plan 1932: a stopped writer's ledger entries file is published, and never blocks a pull

Unit: rollout-fixes. Spec: the issue body (Done when list), no owner rulings on it.

## Behaviour
1. Dead-pid sweep (sync.py). New `_dead_pid_paths(path, who, config)`: entries files in the ledger worktree
   named `<actor>-<host>.<pid>.jsonl` whose host token equals THIS machine's token (`ledger._host_token(config)`),
   whose pid is not this process and is dead (`ledger.pid_alive` False, any actor name, per the `_this_clones`
   precedent: actor can resolve differently between runs). A live pid's file, another host's file, and a
   legacy pid-only name are never swept. `publish()` adds the swept paths to `mine` (so the early
   "nothing to publish" return sees them) and stages them with the rest.
2. Clean shutdown publish (watch_daemon.py). `cleanup()`/`_install_cleanup()` take the sdlc dir; after the
   ownership check and before removing the pidfile, once per process (guard flag), run
   `sync.py publish <sdlc>` through `run_with_timeout.py` (same SIGMA_WATCH_CALL_TIMEOUT bound, output to the
   watch log), best effort, never raises. A publish that loses the index lock just defers; the sweep in (1) is
   the backstop on the next start.
3. Pull is not deferred after a sweep: a test shows the dirty dead file blocks pull before, publish commits it,
   then pull succeeds.

## Test list
- dead pid file, same actor, untracked: next publish commits it; a following pull is not deferred.
- dead pid file with a different actor name but this machine's host id, swept (red when host/any-actor clause removed).
- live foreign pid's file (spawn a sleeping child, use its pid, same host): left alone, not staged.
- other host token's file with dead pid: left alone.
- publish with ONLY a swept file (no own file) does not return "nothing to publish".
- watcher cleanup: SIGTERM'd daemon publishes its own file before exit (real subprocess, stubbed-free on a real ledger fixture), and the
  publish step is bounded.
- Break controls (each clause alone): drop pid_alive check -> live test red; drop host check -> other-host test
  red; drop the sweep from `mine` -> sweep tests red; drop cleanup publish -> shutdown test red.

## Risks
- Sweeping a live process's file: guarded by pid_alive (fails toward True when unknowable).
- Signal-handler publish racing the tick's own publish: both go through git's index lock; loser defers.
- Registries: write-surface inventory / script help if a new CLI surface appears (none planned).
