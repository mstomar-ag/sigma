# Plan 1618: DAG pick-time miss test and fresh-child run (R1, R2) -- the offline harness

The live runs need throwaway tickets on a private clone (owner ruling 8 on the epic: private clone, never the public repo). This slice builds and proves the harness offline; the live results are owner-gated.

Files: `tools/dag_miss_test.py` (new, host-agnostic Python), `tests/test_dag_miss_test.py` (new), `docs/dag-miss-test.md` (new, short), CHANGELOG line under Unreleased.

Behaviour
- Config file (`--config`, JSON `{"repo": "<owner>/<name>"}`, never committed) names the one repository the harness may touch. The harness refuses (exit 2, nothing run) unless the clone directory's configured remote URL resolves to exactly that repo AND the repo is not the public repository (`Agrim-Intelligence/sigma`, matched case-insensitively, also as ssh/https/.git forms).
- A `Backend` seam: `create(title, labels, body)`, `add_label`, `remove_label`, `close`, `reopen`, `comment`, plus `run(args)` for reads (the same `gh`-style runner `dag_collect.refresh` and `dag_check.check` take). Real backend = `gh api` REST against the declared repo; fake backend (tests) keeps issues in memory with `updated_at`/ETag semantics.
- R1: `r1(backend, rounds>=40)`: each round applies ONE of six mutations (label add, label remove, close, reopen, comment, hand-filed ticket carrying a `Blocked by` marker) to a ticket at P0..P3 (cycling so all six mutations hit all four priorities within the rounds), then immediately runs a shadow pick: update the stored map with `dag_check.check`, compute the map's decision (open `sdlc:goal` tickets not blocked by an open ticket, ordered by priority then number, first 3) and compare it with a decision computed from a fresh full read (`dag_collect.refresh` into a scratch state dir). A miss = the two decisions differ. Output: result table (round, mutation, priority, hit/miss) + total.
- R2: `r2(backend, runs=3)` per mode `off`/`on`: a fresh child = clean scratch state dir; between picks change dependencies, labels, states; measure wall time to the first three pickable tickets (off = full read each pick; on = stored map + `dag_check.check`); print the three times and the median per mode. Docs state only a measured number; the doc states none until a live run is posted.
- Fallback: `--strategy wide` makes the map decision re-read with `since` widened and re-lists the open P0/P1 tickets before each pick; used only when R1 shows a miss; repeat until zero. The report states which case happened.
- Cleanup: the harness records every ticket it creates; `cleanup(backend)` closes exactly those and prints them. A scan test: the harness source and its output contain no home path, and ticket text from the clone is never written to a committed file (results table has numbers, mutation names and priorities only).

## Test list
- refuses a clone whose remote is not the configured repo; refuses the public repo even when configured; refuses a missing config. Control: remove the refusal, test red.
- R1 against the fake backend: 40+ rounds, all six mutations at all four priorities, zero misses with the real `dag_check`; a fake backend that hides a change from the `since` query (a deliberate miss) is reported as a miss and exit 1. Control: compare nothing, test red.
- R2 against the fake: 3 runs per mode, median computed, a fresh state dir each run.
- cleanup closes exactly the created tickets and prints them; skipping cleanup leaves them open, test red.
- hygiene scan test (no home path, no ticket text in the table).

Risks: `dag_check` needs the map `cursor`/ETag semantics in the fake; keep the fake faithful to `issues?since=` and 304.
Owner-gated: the live R1/R2 runs and the posted table (they create tickets on a private clone).
