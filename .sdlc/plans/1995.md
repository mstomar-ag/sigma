## Behaviour
The reverse read of ref R (one read per non-mention ref, unchanged cost) decides direction: the goal G must be named in R's own text as something R waits on (G is the blocker, R the dependent), using the same forward phrases the edge parser uses for R's side, plus a reverse-only set `prerequisite(s)` / "stays a prerequisite of". The edge parser's own phrase tables are NOT changed (a test pins its output byte-identical).
- R is an `edge` / `comment-edge` and R waits on G: `reverse: true` (a real two-way wait).
- R is `weak` and R waits on G: `likely-dependent: true`, never `reverse`; the sheet says "probably waits on this goal; the weak read is likely the wrong way round".
- R closed: not reverse-read; the report counts them in `reverse_skipped_closed`; the sheet prints the count.
- Read cost on a 63-goal band is stated in the docstring: one reverse read per non-mention ref (bounded by REVERSE_READ_MAX 10 per goal), closed refs cost nothing extra beyond the state they already read.
