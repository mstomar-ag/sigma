# Plan 1616: DAG instant insertion and refusal of cycle-making edges

Spec: the issue body (7 Done-when bullets), epic "Instant insertion" and "Cycles: Sigma refuses to write one". Map API: `dag_store` (`load`, `save`, `mode`, `refresh_lock`, node/edge schema, `EDGE_SOURCES`), `dag_core` (`build`, `edges_from(text, self_ref)`, `open_dependents`, `closure`, `cycles`), `dag_chain._graph`, `dag_cycles.py` (landed: reports cycles from the stored map).

## Files
- NEW `skills/sigma-loop/scripts/dag_insert.py` (library; add to the script-help library allowlist in `tests/test_script_help.py`):
  - `insert(sdlc, config, number, *, body=None, blockers=(), blocked=(), life="goal", prio=None, unit=None, now=None)` -> status string (`inserted`, `off`, `nomap`, `busy`, `error`). Under `dag_store.refresh_lock` (a `busy` lock or no stored map means skip: the next refresh reads it), loads the stored map, adds or refreshes the node (open issue, `in_corpus` true) and adds the edges (a `Blocked by` edge means `(blocker, blocked)`; edges parsed from `body` with `dag_core.edges_from`, plus the explicit `blockers`/`blocked`), dedupes, saves atomically. Never raises; on an internal failure prints ONE stderr line and returns `error`. Mode `off`: returns `off`, touches nothing, no file created.
  - `closing_members(sdlc, config, blocker, blocked, *, reader=None)` -> sorted member list when adding the edge `(blocker, blocked)` would close a cycle, `[]` when it would not, `None` when it cannot be decided (`unchecked`). With a usable stored map: the cycle exists iff `blocker` is reachable from `blocked` through dependents; members = the nodes on any such path plus both ends (use the open-only walks of `dag_core`). With no usable map: a bounded LIVE walk of the blocker's own blockers through `reader` (default: the `gh_api` issue read with a hard cap of 25 reads; each read's body parsed with `dag_core.edges_from`); reaching `blocked` is a cycle; the cap or a failed read returns `None`.
  - `record_unchecked(sdlc, blocker, blocked)` / `take_unchecked(sdlc)`: a small `state/dag-unchecked.json` list of number pairs (numbers only, bounded to 200), written atomically; `dag_refresh.refresh_if_due` clears it after a SAVED refresh (the refreshed map and `dag_cycles` then examine the edge), so the file cannot grow.
  - class `CycleRefused(ValueError)` carrying `.members`; message names every member as `#N`.
- `skills/sigma-loop/scripts/sources.py` (GitHub source only; the local source is untouched):
  - `create_dependency`: after the new number is known call `dag_insert.insert(..., body=<the body passed in>)` inside try/except; a failure prints one stderr line and never changes the return value or delays the filing.
  - `append_to_body(goal, marker)`: if `marker` carries `Blocked by #N` (use `dag_core.edges_from`), run `closing_members` BEFORE the write; members found -> raise `CycleRefused` and write nothing; `None` -> allow, write, `record_unchecked`; otherwise write, then `insert` the new edge. Callers already turn exceptions of this call into warnings (`handoff.create_tracked_issue`); confirm and, if one does not, make the refusal visible there. A marker with no `Blocked by` is written exactly as today with no map access.
- `skills/sigma-scope/scripts/compile_plan.py`: no new behaviour of its own; its issues enter the map through `create_dependency`'s body parsing (their edges are the `Blocked by` lines it already writes). Prove with a test that the in-plan cycle failure (`_validate_and_order`) still fires with ZERO side effects (no create, no map file) and that a good plan's issues and edges are all in the map after one pass.
- `skills/sigma-loop/scripts/dag_refresh.py`: clear the unchecked list after a saved refresh.
- Registries: `docs/launch/write-surface.json` rows for the new file writes (gate: mode not off + a stored map), `legacy.py` markers only if a new marker literal is added (prefer none), `tests/test_script_help.py` library allowlist, `tests/test_no_direct_gh.py` ratchet unchanged (use `gh_api`/the source's own reader, never a raw `gh issue|pr|project|label` call), docs sentence in the map doc where the map is described, CHANGELOG `## Unreleased` entry on its own line.

## Behaviour contract
- Mode `off`: no map file read or written, no `dag_insert` import on the filing path (test), existing filing tests unchanged and green.
- A filing is never failed or delayed by the map: insertion errors are one stderr line.
- Cap 25 live reads; over it the write is ALLOWED and `unchecked` recorded.

## Risks
- Two writers of the stored map (refresh and insertion) are serialised by the same non-blocking lock; insertion yields to a running refresh (the refresh reads GitHub after the filing in most interleavings; a lost insertion is repaired by the next refresh).
- The live walk reads issue bodies of third parties' goals: numbers only are kept.
