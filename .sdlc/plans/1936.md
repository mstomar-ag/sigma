# Plan 1936: Chain plans in one session share an on-disk read cache

Unit: rollout-fixes. Spec: the issue body (Done when list). No owner ruling on it.

## Behaviour
A plan's per-member read of body + newest comments (`chain_waits._read`: one issue GET + up to 2 comment pages, ~3 calls
per member) is the repeated cost across neighbouring chains. Add a short-lived on-disk cache of that answer.
- New library `skills/sigma-loop/scripts/chain_read_cache.py` (no main): file `.sdlc/state/chain-reads.json`.
  Entry per issue number: `{updated_at, saved_at, issue, comments, maybe_older}`. API: `load(sdlc_dir, now)`,
  `get(store, number, updated_at)`, `put(store, number, updated_at, got, now)`, `save(sdlc_dir, store)`.
  Bounds, stated as constants: MAX_AGE_SECONDS (900), MAX_ENTRIES (400), MAX_BYTES (8 MiB); oldest entries are dropped
  first. Atomic write (temp file + os.replace). Fail-open: a missing, corrupt, wrong-version or unwritable file reads as
  an empty cache and is never an error; nothing here can fail a plan.
- Hit rule: the caller supplies the issue's CURRENT `updated_at` (from the closure's issue on the live path, from the
  map node on the map path). Hit only when the cached `updated_at` equals it exactly, both are non-empty, and
  `now - saved_at <= MAX_AGE_SECONDS`. Anything else reads fresh and overwrites the entry. No `updated_at` known
  => never a hit (read fresh).
- Wire into `chain_waits._read` / `collect` / `attach` by an optional `disk` argument (None = today's behaviour,
  byte for byte), created once per `chain.plan` call (`plan()` loads, passes down, saves at the end; save errors ignored).
  The in-memory per-call `cache` dict stays in front.
- Read-only for GitHub: no write exists on this path, so no invalidation-on-write is needed; a changed issue changes
  `updated_at`, which is the key.
- Docs: `docs/chain.md` states, for its existing offline plan scenario, the call count before (the current figure in the
  doc) and after (counted from the fake's call log on a second overlapping plan), and says the live saving is not
  measured until it is. CHANGELOG line under `## Unreleased`.

## Files
skills/sigma-loop/scripts/chain_read_cache.py (new), chain_waits.py, chain.py, docs/chain.md, CHANGELOG.md,
tests/test_chain_read_cache.py (new), the write-surface inventory / `.sdlc` writer registry if a registry test names the state file.

## Test list
- two overlapping chains on a counting fake host: the shared members' comment reads happen once in total (red when the cache is bypassed / `disk=None`).
- a member whose `updated_at` moved is read again on the next plan.
- age past MAX_AGE_SECONDS reads again (clock injected).
- no known `updated_at` => never a hit.
- corrupt / wrong-version / unwritable cache file: plan still succeeds, same output.
- bounds: more than MAX_ENTRIES entries keeps the newest; file stays under MAX_BYTES.
- plan output with the cache hot is identical to the output with it cold.
- Break controls, each clause alone: drop the updated_at equality; drop the age check; ignore the empty-updated_at guard; skip put.

## Risks
- Stale hit: bounded by exact updated_at equality plus 15 min age; comments added bump updated_at.
- Concurrent plans (several processes) writing the file: atomic replace, last writer wins, worst case a missed hit.
- State registry tests (write-surface, shared writer registry) may list state files: update them.
