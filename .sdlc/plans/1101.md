# Plan: goal 1101, one owner for the unit rewrite in a job run
Files: skills/sigma-loop/scripts/feature_upkeep_job.py (run_engine, one constant), tests/test_upkeep_sched.py, tests/test_upkeep_entry.py.
Behaviour: in run_engine, when the older pass (feature_rebase.upkeep) reports outcome `rebased` (it moved the unit), the new unit pass is NOT called and the printed line carries unit_pass `skipped`. Choice: skip-after-rebased, not run-only-when-idle: it keeps the new pass active for every case where nothing was moved (current, conflict, lease-refused, no-branch, failed, busy), so no coverage is lost and the only double-write window (both rewriting one unit in a run) is closed. The older pass stays the owner because it holds the per-unit lock and the lease push. The gate decorator is untouched, so a closed gate returns before any of this.
Parity: valid_ref is compared with git check-ref-format (refs/heads/<name> and --branch) over a table of about 36 names; assert valid_ref(x) implies git accepts x. Stricter is allowed, looser is a failure.
## Test list
- rebased -> unit pass not called, unit_pass skipped (fake); every other outcome word still calls it.
- local bare remote: older path rebases and force-pushes, unit pass untouched, remote tip equals reported unit_tip.
- valid_ref never looser than git over the table; table is not vacuous.
- existing closed-gate tests (machine door, project door) unchanged and green.
## Risks
- The `rebased` word is shared with feature_rebase constants; a rename there would silently re-enable double passes. Mitigated by the fake-driven test using the literal word.
- Skipped unit pass means a unit rebased this run gets its unit rewrite next run; accepted (latency, not data).
- Not done: the real unit pass is not exercised end to end on the bare remote (injected fake), because it needs the full pass wiring.
