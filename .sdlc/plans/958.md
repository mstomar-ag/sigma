# Plan for #958: never-delete guard parity with the write-surface scanner

## Files
- `tests/test_no_autonomous_feature_branch_deletion.py`: widen the guard's line regexes.
- `tests/test_never_delete_guard_scanner_parity.py`: new parity and known-limit tests.
- `CHANGELOG.md`: Unreleased entry.

## Behaviour
- `_UPDATE_REF_DELETE_RE` accepts any flags or message arguments before `-d` or `--delete`.
- New `_PUSH_MIRROR_RE` makes `push --mirror` a `push_delete` hit.
- New `_STRING_FORM_RE` flags a one-string `git push` with `-d`, `--delete` or `--mirror`, and a
  one-string `git update-ref` with `-d` or `--delete`.
- The guard keeps its per-line scan; it does not import the scanner, so the two stay independent checks
  tied together by the parity test.

## Test list
- Every scanner-flagged shape (update-ref message flag, push mirror, both orders) is a guard hit.
- String-form commands are guard hits.
- Known limit: the scanner does not classify string-form commands (pinned).
- Known limit: a flag built by concatenation is invisible to the guard (pinned).
- Nearby non-deletes stay quiet.
- Existing guard and backup-ref tests stay green, including the six pinned real call sites.

## Risks
- A broader regex could add a hit on a real call site; the real-tree test would go red.
- String-form regex may over-match prose inside code strings; accepted, a hit only asks for review.
