# Plan 1017: upkeep pass follow-ups

## Goal
Close three of the four batched findings. The fourth (no shipped caller supplies the rewrite and push callables) is a
separate feature slice and is left as a follow-up.

## Files
- `skills/sigma-loop/scripts/work.py`: in `rebase()`, after a successful rebase (both the plain and the changelog
  union-merge return), call a small helper that runs `state.reanchor_content` only when the upkeep gate is open, and
  never raises. Gate closed: nothing runs, so behaviour is byte-identical.
- `skills/sigma-loop/scripts/feature_rebase.py`: `_acked` and `_unacked` take an optional `config`; when a config is
  given and the upkeep gate is closed, the runtime acknowledgement file is not read. `config=None` (old callers and
  tests) keeps today's behaviour. The two production callers pass their config.
- `skills/sigma-rebase/scripts/rebase_brief.py`: in `attempt_rebase`, the lease tip read moves inside a try block; an
  unreadable tip returns a FAILED outcome with the reason instead of raising.
- New `tests/test_upkeep_followups_1017.py`.

## Behaviour
1. Open gate: a rebased goal has its content fingerprint re-recorded, same as the BEHIND path already does.
2. Closed gate: a leftover acks file is ignored by the loss check.
3. `attempt_rebase(..., lease=True)` with a failing tip read returns `{"outcome": FAILED, ...}`, pushes nothing.

## Test list
- rebase with the gate open calls the re-anchor once
- rebase with the gate closed never calls the re-anchor
- leftover runtime acks are ignored with the gate closed and read with it open
- attempt_rebase returns FAILED rather than raising when the lease tip read fails

## Risks
- Re-anchor after a rebase could hide an unverified edit: it only re-records what the loop itself just replayed, the same
  rule the BEHIND path applies; the existing launder control stays.
- Ignoring leftover acks fails toward refusing a push, which costs a pass and never data.
