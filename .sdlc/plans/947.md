## Behaviour
1. Entry. In `_rebase_feature`'s conflict branch, when strict and the level is mechanical or agent, and the stop is
   Level-1-eligible (one conflicted path, the changelog, base stage present), call the Level 1 step BEFORE the
   existing `return CONFLICT` and before `_describe_stop`. Not eligible, or any refusal: fall through to the existing
   describe-and-park path unchanged (the stop state is untouched on refusal).
2. Level 1 step (inside the live scratch worktree, loop capped by the existing stop and pass limits):
   a. snapshot `stage0_listing` and the unmerged set; b. union through `_union_for`; c. `empty_commit_about_to_land`
   check; d. per-stop checks C (stage-0 form), D (markers on the resolved blob, whitespace vs original), E; e. stamp
   with `stamp_commit(level=1)` (original author kept, hooks and signing off); f. `git -c core.editor=true rebase
   --continue` through the pinned runner; g. a further stop repeats from a, up to the cap, then parks.
3. `prove` runs once, after the rebase completes and before any push: reads the originals and replayed ranges once
   (`read_commits`), `pair_commits` with the recorded stop keys, the cumulative `multiset_differences` on every path
   outside the conflicted set, `dropped_paths` (already the outer guard), then `verify` through part A's shared
   runner when a verify command exists. No verify command: Level 1 proceeds only with
   `conflicts.mechanical_without_verify` true, else park with a named code. Any refusal -> park (nothing pushed).
4. Push. Only `_pushed_with_backup` with the backup descriptor already built by `_rebase_pass`; if the descriptor is
   None while resolved content exists, refuse (park) rather than take the legacy path. This is the guarantee that nothing
   resolved is pushed before a backup ref exists; the atomic push makes backup and branch move together.
5. After a successful push only: write the resolution record, the ledger note and (if a prior finding exists) the
   comment-then-close from #946. A failed or lease-refused push writes none of them.
6. Ack recomputation (decision below). 7. Outcome stays `REBASED`; `report["resolved"]` carries the level and run id so
   `clause()` can say it; a new outcome word is added only if the existing wording table cannot say it (decide in
   implement, with its drift pin).

## Decisions
- D-9 lever. The 120 s guard budget is `guard_deadline()`, read from the operator environment variable
  `SIGMA_WATCH_CALL_TIMEOUT`. The lever is that variable: raising it is an explicit operator act, bounded because it is
  a number the operator types, polite because it applies to the next pass and starts nothing. This slice changes no
  constant; the refusal text names the variable and the current value so a unit refused for budget is not refused
  silently forever. A per-unit override is not added (it would be a new tracked setting with its own growth and
  fold inventory rows); it stays deferred and is recorded as a follow-up, not hidden.
- Ack / S-50 / D-30. The landed code has no runtime union ack file (`grep` of the engine finds none): `_acked` reads the
  tracked file plus the integration-branch copy only. This slice adds it: a per-unit JSON under the runtime state
  directory (already covered by `setup.RUNTIME_IGNORES`), path built beside `ack_path` with the same name guard and the
  `unit_key` fold, and `_acked` unions it in. Entries are written only after a successful backup push, for each
  (original, replayed) pair from `pair_commits` where the original was acked (by sha or patch-id): the replayed sha and
  its patch-id. The tracked store is never edited. The stamp is never read. A commit that arrived with a pull-request
  trace in its subject needs no ack, because the subject is unchanged by a resolution.
- DIRECT_COMMITS does not lock a resolved unit because `direct_commits` runs on the ORIGINAL commits before the replay
  and judges by subject only; the resolved commit keeps its subject. Pinned, with the red control below.
- Continuation commit / S-49 / D-29. The stamp commit uses `--no-verify --no-gpg-sign` (landed) and `rebase --continue`
  runs with `core.editor=true` under `pin_env` (signing and rerere pinned off). Repository hooks that fire on
  `--continue` itself (post-rewrite, post-commit) are not suppressed by `--no-verify`; this slice runs the continuation
  with `core.hooksPath` pointed at a nonexistent directory, the way the sync module does for its own commits, applied to
  that one command and not added to `REPLAY_CONFIG` (so the pick-time call list is unchanged). Measure it on a real
  repository with a failing hook before trusting it.
- PR-arrival rule. The regexes and `\Z` anchor are not changed. The edit is the docstring of
  `arrived_through_a_pull_request` stating that a body trailer cannot change the verdict, plus pins.

## Test list
1. Gate closed: a CHANGELOG conflict returns CONFLICT with the exact old call list, no new file, no stamp (byte-identical).
2. Level off: same as 1 with the gate open and `conflicts.resolve` off.
3. Happy path on real git (scratch repo plus bare remote): CHANGELOG-only conflict resolved, stamped, continued, pushed;
   the remote holds the backup ref and the branch moved in one push; author name, email and date equal the original's.
4. Non-CHANGELOG conflict, a second conflicted path, a missing base stage: parks, remote untouched, worktree gone.
5. Each proof refusal parks with its code: edit outside the conflicted set, new marker, new whitespace finding, key
   collision, unaccounted original.
6. No verify command and `mechanical_without_verify` false: parks with a named code; true: proceeds.
7. Descriptor None with resolved content: refuses, and a spy on the runner sees no push.
8. Taken backup name and stale lease: nothing moves, no record, no ack written.
9. Ack recomputation: acked original -> replayed sha and patch-id appear in the runtime file; `_unacked` returns none
   for them; the tracked ack file is byte-identical before and after; a resolved commit with a pull-request subject is
   not reported as direct.
10. Stamp trailer after a blank line leaves the commit arrived; a stamp joined to the subject reads direct.
11. Budget refusal text names `SIGMA_WATCH_CALL_TIMEOUT`; setting it larger lets a slow-guard fixture pass.
12. Continuation with a failing repository hook and a signing-required config still completes.
13. Write-surface and pin tests list every new site; the ratchet for direct `gh` call sites does not grow.

## Risks
- Hooks on `--continue` (S-49) are unmeasured until test 12; if the nonexistent hooks path does not hold on the oldest
  supported git, refuse Level 1 there (loud) rather than run weaker.
- The test counter reads Python only and a CHANGELOG-only Level 1 rarely reaches it; do not claim coverage it lacks.
- A same-second same-subject pair collides and parks (known, D-41). Stop-record pairing is exact only for stops.
- The ack file grows with resolved units; the prune and the pass caps bound it, measured in test 9 at 100 pairs.
- The union cannot see a semantically wrong merge; verify is the only check on that, hence the no-verify default park.
- Sensitivity: nothing here moves a probabilistic race test across a performance boundary; the lock paths are untouched.
