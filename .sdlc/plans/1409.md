## Behaviour
1. Label path: when `blocking_priority_override` is on and order is priority, merge the pool and the blocking query result (dedupe by number), then stable-sort by `(rank, 0 if blocking else 1)` followed by the rest of `_pick_key`. A lower-tier blocker no longer passes a higher tier. Override off: unchanged code path, byte-identical.
2. Board path: sort key becomes `(card_rank, 0 if blocking else 1, feature_rank, pos, n)`; with override off the second element is a constant so order is identical.
3. Transitive: blocked issues carry the blocked label and are excluded by the existing eligibility rules; add a test that a blocker that is itself blocked is not picked and the deepest unblocked one is. Parked blockers are never picked.
4. No stale snapshot: confirm no cache of the pending queue survives `mark_blocked` within one source instance; test that a pick after `mark_blocked` plus blocking label returns the blocker.
