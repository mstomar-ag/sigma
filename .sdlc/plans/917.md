## Why the tests are shaped this way (gate mechanics, verified in `skills/sigma-loop/scripts/red_green.py`)

1. Whole-file byte binding. `_hashes` (lines 84-94) hashes the WHOLE FILE of each planned node; `observe` stores each red
   with that `file_hash` (lines 169-175); `refusal` (lines 188-225) credits a red only if its `file_hash` equals the
   file's sha256 at the green and it predates the green run. So no file that contains a planned node may change between
   the red verify and the green verify.
2. Every collected node under every listed selector needs its own credited red (`missing = set(nodes)`, line 204; refusal
   at lines 221-222), and every listed node must PASS at green in a clean environment (line 178: `passed == set(nodes)`;
   a skipped node has no `PASSED` line). A selector may therefore name only tests that fail by assertion before Part 2
   and pass after it. A test that is green in Part 1 can never carry a red and is not listed.
3. Only assertion failures qualify, by one of two routes. (a) The short summary (lines 156-166): the line
   `FAILED <id> - <reason>` is cut by pytest at 80 columns (the width it assumes when it cannot see a terminal;
   `COLUMNS` overrides it), so `AssertionError` survives only when the id is short: measured, an id of 53 characters
   still prints ` - AssertionError...`, a longer one loses it; with the `CI` variable set the reason is not cut. (b) The
   traceback join (lines 97-129), which is switched off by ANY `Captured stdout/stderr/log` block anywhere in the run
   and fails closed when several failed nodes share one function name. Both routes are armed here: ids of at most 53
   characters, silent tests, unparametrised tests with function names unique within their file.
4. Collection must succeed at Part 1 (`collect`, lines 72-81, raises on a non-zero exit), so a name Part 2 defines is
   reached only through a helper that asserts it exists, inside the test body.
5. `## Tests` holds 1 to 25 selectors (line 59); a file selector covers every test in the file.

Consequences, applied throughout: the three planned files contain ONLY tests that are red by assertion before Part 2
(a file selector is then safe); each begins with a call that asserts the thing under test exists (`gate()`,
`gate_with()`, `source()` or `template_cfg()` in `tests/upkeep_support.py`), so the first failure is an `AssertionError`
with a stated message and never a `KeyError`, `ImportError` or collection error; no planned test is parametrised, prints,
skips, or captures output; a control that catches `AssertionError` calls `gate()` BEFORE its `try`, so a missing gate
cannot make it pass; green-before-Part-2 tests live in `tests/test_upkeep_harness.py`, which is not listed.

Measured on a scratch copy of the pre-change tree (Python 3.13, the project's clean verify environment), by importing
`red_green.py` and calling `observe` and `refusal` on a scratch plan whose `## Tests` lists the three files: the
pre-change run reported 52 failed, 52 of 52 credited as assertion reds, at the default width, at `COLUMNS=30`, at

## The five properties (AGENTS.md), answered for this change

- RELIABILITY: every claim is a test that was seen red (the ledgers below). The trap's own channels are controlled: planted
  process, model, network and file attempts are each seen, and the fully enabled controls assert each channel is non-empty,
  so an audit event that does not exist on some Python version turns a control red rather than silently passing the closed
  runs. Measured: the trap, the probe and the closed and enabled runs behave identically on Python 3.11.15, 3.13.2 and
  3.14.7 (a scratch driver without pytest); 3.10 and 3.12 were not available here and are covered only by the controls
  (CI runs 3.10 to 3.13). The module parses as 3.10 (a planned test).
- SCALABILITY: the gate is one pass over at most 17 schema keys plus the keys actually present (a block over 64 keys is
  refused without iterating it; lists are length-capped at 200 entries of at most 200 characters before they are walked).
  Cost is per decision, not per unit, and the gate does no I/O, so it is the same at 10x or 100x units. Measured once
  (Python 3.13, macOS, best of five repeats, not asserted by any test): 1.3 microseconds with no block, 6.3 for
  `{"upkeep": {"enabled": true}}`, 18 for the full shipped block, 35 with both name lists at their caps, about 100 for the
  worst malformed block (64 keys, five full sections, every key unknown). No store, no growth.
- RESILIENCY: stateless and total. Recovery from a closed gate is editing the config; `problems` names the key. There is no
  partial write, retry or lever.
- SAFETY: off by default, fails closed, three independent opt-ins named, no value echoed, no import that can spawn, connect or
  write (pinned by an AST test; `inspect` is the one non-trivial import and only reads a signature). Nothing is limited by a
  constant copied from a laptop: the bounds are range checks on user input. No test can start a real model (P10).
- LIVENESS: no long-running component here. `evaluate` returns `missing` (which opt-in is absent) so a later doctor row can tell
  "closed on purpose" from "invalid"; the doctor row itself is a later slice.
- Host-agnostic: pure Python in the library; no hook is load-bearing.

def _tname(value):

def _edits(left, right):
    """Edit distance (insert, delete, replace) between two short texts, or None when it exceeds MAX_NEAR_EDITS."""
    if abs(len(left) - len(right)) > MAX_NEAR_EDITS:
        return None
    row = list(range(len(right) + 1))
    for i, a in enumerate(left, 1):
        nxt = [i]
        for j, b in enumerate(right, 1):
            nxt.append(min(row[j] + 1, nxt[j - 1] + 1, row[j - 1] + (a != b)))
        row = nxt
    return row[-1] if row[-1] <= MAX_NEAR_EDITS else None


def _hint(key, known):
    """The known key name nearest to `key` within MAX_NEAR_EDITS edits, else None. Only an ASCII text key of at most
    MAX_HINT_KEY_CHARS characters is compared at all, so nothing else is ever echoed."""
    if not (isinstance(key, str) and key.isascii() and len(key) <= MAX_HINT_KEY_CHARS):
        return None
    best = None
    for name in sorted(known):
        distance = _edits(key, name)
        if distance is not None and (best is None or distance < best[0]):
            best = (distance, name)
    return None if best is None else best[1]

                and all(type(item) is str and 0 < len(item) <= MAX_NAME_CHARS for item in value)):
            return None

        if hint is not None:

        elif isinstance(key, str):
            found.append("%s: unknown key at position %d (text, %d characters)" % (label, position, len(key)))
        else:
            found.append("%s: unknown key at position %d (%s)" % (label, position, _tname(key)))
    return found


def read(config):
    """The whole decision, total. -> Reading(enabled, settings, problems). Closed readings carry DEFAULTS as settings."""
    block = config.get(BLOCK, _ABSENT) if isinstance(config, dict) else _ABSENT
    defaults = _defaults()
    if block is _ABSENT:
        return Reading(False, defaults, ())
    if not isinstance(block, dict):
        return Reading(False, defaults, ("upkeep: expected an object, got " + _tname(block),))
    if len(block) > MAX_BLOCK_KEYS:
        return Reading(False, defaults, ("upkeep: more than %d keys" % MAX_BLOCK_KEYS,))
    problems = _unknown("upkeep", block, {"enabled"} | set(_SECTIONS))
    sections = {}
    for name in _SECTIONS:
        got = block.get(name, _ABSENT)
        if got is _ABSENT or (isinstance(got, dict) and len(got) <= MAX_BLOCK_KEYS):
            sections[name] = got
            if got is not _ABSENT:
                known = {key.split(".")[1] for key in SCHEMA if key.startswith(name + ".")}
                problems += _unknown("upkeep." + name, got, known)
        else:
            sections[name] = _BROKEN
            problems.append("upkeep.%s: expected an object of at most %d keys, got %s" % (name, MAX_BLOCK_KEYS, _tname(got)))
    values, bad = {}, set()
    for key in SCHEMA:                                    # per-key checks: ALL of them, before any cross-check
        scope, _, name = key.rpartition(".")
        holder = sections[scope] if scope else block
        if holder is _BROKEN:
            bad.add(key)
            continue
        raw = _ABSENT if holder is _ABSENT else holder.get(name, _ABSENT)
        if raw is _ABSENT:
            values[key] = defaults[key]
            continue
        why = check(key, raw)
        if why:
            problems.append("upkeep.%s: %s" % (key, why))
            bad.add(key)
            continue
        values[key] = list(raw) if isinstance(raw, list) else raw
    for keys, fits, why in CROSS_CHECKS:
        if any(k in bad for k in keys):
            continue                                      # already reported; comparing would raise on a wrong type
        if not fits(*[values[k] for k in keys]):
            problems.append(why)
    if problems:
        return Reading(False, defaults, tuple(problems))
    return Reading(values["enabled"], values, ())          # validated to be a bool, so this IS the boolean


def enabled(config):
    """The project opt-in: True only for a valid block whose `enabled` is the boolean true."""
    return read(config).enabled


def _ledger_on(config):
    """`ledger.enabled` is exactly true. Restated here because the ledger module's own reader raises on a truthy
    non-object block, and a gate must not (it is pinned equal on well-formed input)."""
    ledger = config.get("ledger") if isinstance(config, dict) else None
    return isinstance(ledger, dict) and ledger.get("enabled") is True


def _env_on(environ):
    """The machine variable is exactly the text 1, read from the injected mapping else the process environment."""
    env = os.environ if environ is None else environ
    getter = getattr(env, "get", None)
    return callable(getter) and getter(ENV_MACHINE) == "1"


def evaluate(config, door="project", environ=None):
    """-> {"open": bool, "door": door, "missing": [...], "problems": [...]}. `missing` lists the absent opt-ins in the order
    project, machine, ledger; the machine door needs all three. A closed gate with `problems` is invalid, one without is simply off."""
    if door not in DOORS:
        raise ValueError("unknown door %r; expected one of %s" % (door, DOORS))
    reading = read(config)
    missing = [] if reading.enabled else ["project"]
    if door == "machine":
        if not _env_on(environ):
            missing.append("machine")
        if not _ledger_on(config):
            missing.append("ledger")
    return {"open": not missing, "door": door, "missing": missing, "problems": list(reading.problems)}


def machine_enabled(config, environ=None):
    """The scheduler's question: project opt-in AND the machine variable AND the shared ledger switch."""
    return evaluate(config, "machine", environ)["open"]


def gated(door="project"):
    """Decorator for an entry point `fn(config, ...)`: the gate is its first action, and a closed gate returns
    {"closed": True, "door", "missing", "problems"} WITHOUT calling the body. Write it with parentheses and put it
    OUTERMOST (a static test enforces both). A machine-door entry point must declare `environ` as a keyword-only
    parameter, which is where the gate reads it from; any other shape is refused when the function is decorated, so an
    `environ` passed positionally can never be silently ignored."""
    if door not in DOORS:
        raise ValueError("unknown door %r; expected one of %s" % (door, DOORS))

    def decorate(fn):
        if door == "machine":
            parameter = inspect.signature(fn).parameters.get("environ")
            if parameter is None or parameter.kind is not inspect.Parameter.KEYWORD_ONLY:
                raise ValueError("a machine-door entry point must declare environ as a keyword-only parameter: "
                                 + getattr(fn, "__name__", "?"))

        @functools.wraps(fn)
        def guarded(config, *args, **kwargs):
            verdict = evaluate(config, door, kwargs.get("environ") if door == "machine" else None)
            if not verdict["open"]:
                return {"closed": True, "door": door, "missing": verdict["missing"], "problems": verdict["problems"]}
            return fn(config, *args, **kwargs)
        guarded.upkeep_door = door
        return guarded
    return decorate

## Risks and rollback

Risks (R1 to R13), each with its mitigation:
- R1 Strict unknown-key policy (P3): an older installed plugin reading a newer committed config that carries a key it does not
  know reads the block CLOSED. Closed is the safe state and `problems` names the key, but the symptom is "the feature is off for
  that person". Mitigation: later slices add their keys to `SCHEMA` in the same change that adds the config, and the template
  note says unknown keys close the block. If plan-review prefers ignore-and-report, the change is the single `_unknown` call in
  `read` plus two tests (`test_unknown_keys_close`, `test_problems_no_echo`).
- R2 Audit events on Python 3.10 and 3.12 were not measured (3.11, 3.13 and 3.14 were), and the trap sees only the thread that
  opened it (a future entry point that launches from a worker thread would be missed; none exists here). Mitigation: the enabled controls assert
  all four channels non-empty, so a missing event makes them red on CI instead of letting the closed runs pass vacuously; the
  trap is thread-filtered and returns at once when idle.
- R3 Numeric bounds (P6) are guesses. A later slice that needs a wider range edits `SCHEMA` and `EXPECTED_SCHEMA` together; the
  lock test makes that a deliberate two-line change. Because the planned files are bound by the gate, such a slice edits them in
  its own red-to-green cycle.
- R4 Any `/` operator in the module (even arithmetic) makes the fold inventory demand a classification. Mitigation: no division is
  used; `test_fold_inventory` names the cause; G12 proves it.
- R5 Template note scanners: release-shaped numbers and "records done" sentences. The note was checked against the version scan
  (measured: `tests/test_readme_first_run.py` passes with the block). The note says "RESERVED" and "nothing runs"; the
  registry-tied test forces the first slice that registers an entry point to rewrite it.
- R6 `tests/test_docs.py` helper change: defaults reproduce today's behaviour; the three pick-cost tests are unchanged and run in
  the full verify.
- R7 Cross-test imports by name (`test_docs`, `test_feature_registry`) follow `tests/test_doc_links_sdlc_moot.py`; they are lazy,
  so collection never fails.
- R8 Gestures that edit shipped files must be restored. Mitigation: after the ledger, `git status` and `git diff --stat` must list
  only the Part 1 and Part 2 files; the orchestrator's second full verify catches any leftover break.
- R9 Out of scope but real: four existing config readers raise on a truthy non-object block (`ledger.py` 520 to 526, `work.py`
  1145 to 1155, `drift_watch.py` 89 to 106, `sync.py` 921 to 933). They are not changed (behaviour change). Follow-up for the
  orchestrator to file (not part of this change): make them total, and a repository-wide "every key the code reads is in the
  template" check beyond `gates.*`.
- R10 Gate attribution. The 52 planned nodes are silent and unparametrised, with ids of at most 53 characters, so both credit
  routes work; a harness test enforces the rules. If the red verify credits fewer than 52 although all visibly failed by
  assertion, re-run it at a width of at least 80 columns rather than editing a planned file.
- R11 Immutable planned files. A defect found in a planned file or a helper after the red verify costs a repeat of Part 1's red
  verify; this is why the controls were written once, fully, in Part 1 and measured.
- R12 Cost: the 52 planned tests run in about 8 seconds serially, the harness in about 3 seconds; the closed proof drives 70
  cases through a temporary project each.
- R13 The pinned files depend on the supplied copy: if it is missing or a digest differs, Part 1 stops and reports, and nobody
  retypes the files.

Rollback: revert the single squashed change. Nothing consumes the gate, no state or store is created, the template change only
affects projects scaffolded after it merges (existing configs are never rewritten), and an unused registry entry is inert. A
project that copied the block can delete it with no effect. A half-applied state (Part 1 without Part 2) is red by
construction and cannot merge, because the pull request is gated on the full verify.
