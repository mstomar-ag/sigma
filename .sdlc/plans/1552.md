# Plan 1552: land verb measures the sibling half itself

Root cause: `feature_land.main` calls `land()` without `landed`, so `cross_repo.unit_sibling_check` always refuses ("nothing was supplied to measure") for any unit with a second repository.

## Files
- skills/sigma-loop/scripts/feature_land.py: when `landed` is None, build a default measurer from `env.landed.merged_pull_requests(env.run, env.cwd, repo, branch)`: True only if some row has `merged_at`; False if rows read and none merged; any error/truncation -> None (unmeasurable -> refuses). Refusal detail also lists the remedy: land the sibling first, or remove that repository from the unit's registry entry.
- skills/sigma-loop/scripts/cross_repo.py `unit_sibling_check`: refusal strings for not-landed / undetermined / no-branch name the goal(s) recorded for that repo in the registry entry (`goals` list) as "goal #N".
- tests/test_feature_land_front.py: scenario through `land()` with fake runner.
- CHANGELOG.md: one line at END of Unreleased.

## Behaviour
Sibling merged PR -> proceeds. Not merged -> refused:sibling naming goal and repo. Gate closed (upkeep off) -> unchanged (guard returns early).

## Test list
- landed sibling (fake gh PR list with merged_at) lands (rehearsal) with no `landed` arg.
- unlanded sibling refuses, detail names goal #2, repo and remedy.
- gh failure refuses (fails closed).
- existing sibling tests still pass; test_cross_repo.py, test_feature_land_*.py, test_write_surface.py.
