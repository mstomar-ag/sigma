# Plan: engine hygiene under the gate (part B, slice 1)

## Goal
With the upkeep gate open, the unit rebase engine is immune to the operator's rerere and signing settings, a stop with no
conflicting file is FAILED, and the read helpers a later resolver needs exist. With the gate closed nothing changes.

## Files
- `skills/sigma-loop/scripts/feature_rebase.py`: `REPLAY_CONFIG`, `pin_argv`, `pinned_run` (the one seam), a `strict` flag on `_rebase_feature`, the gate loaded as `gate`.
- `skills/sigma-loop/scripts/conflict_state.py` (new library): `stage_map`, `conflicted_paths`, `stage0_listing`, `empty_commit_about_to_land`.
- `skills/sigma-rebase/scripts/conflict_walk.py`: `_empty_commit_about_to_land` delegates to the moved function.
- `skills/sigma-loop/scripts/feature_upkeep.py`: `conflicts.resolve` (enum, default off), `conflicts.mechanical_without_verify` (bool), `conflict_level`.
- `skills/sigma-init/templates/config.json.tmpl`: the `conflicts` block and a sibling note.
- `tests/test_feature_rebase_hygiene.py` (new), `tests/test_script_help.py` (library list).

## Behaviour
- `pinned_run(run, config)` returns `run` itself unless `upkeep.enabled` is true; otherwise each git call gets `-c` pins right after `git`. The runner is wrapped once in `_upkeep`, so every git process of the pass (including the goal-level replay) is pinned.
- `_rebase_feature(..., strict)`: after a failed rebase, a stop is CONFLICT only if the NUL-safe unmerged read is non-empty; empty or unreadable is FAILED. Not strict: unchanged. `rebase_stopped` is not edited.
- The existing argv-prefix stubs in the feature rebase tests run with the gate closed, so they never see the pins; the pinned argv is asserted in the new file.
- Defaults (provisional): `conflicts.resolve` off, `mechanical_without_verify` false. A typo in `resolve` closes the whole block, as every other bad key does.

## Test list
- pin_argv pins once, is idempotent, leaves other programs alone.
- Closed gate: runner identity over empty, template and near-enabled configs, under the recording trap.
- Open gate: every engine git call pinned; closed: none.
- rerere control (real git, recorded resolution): pinned sees the conflict; unpinned gives FAILED (measures D-8); closed gate keeps CONFLICT.
- Stub call-site matrix for strict/unmerged; unreadable set is FAILED; the predicate still says a stop with no unmerged path is in progress.
- Reader: odd paths, failed read propagates, stage 0 listing; emptiness check; walker delegation.
- Gate keys: level, typos, template block, note.

## Risks
- Wrapping the runner changes argv seen by injected runners, only while the gate is open.
- The emptiness check at a merge stop stays unverified (D-6) and over-refuses at worst.
- Part A's own runner is not in the tree yet; it should call `pin_argv`.
