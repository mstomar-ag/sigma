# Plan 1332: a person's `no` inside the applier window is honoured

Plan sha256: pending
## Behaviour
1. Pending-ask cancel: in `applier.tick`, when an ask is `pending` (before planning its apply), an owner comment whose body is exactly `no` (case-insensitive, trimmed) created at or after the ask's `opened` time cancels it via `answer(..., "no")` (state becomes answered, so the plan skips it). Comments come from the same `comments_fn` (built when any ask is pending or applied-unvetoed). Non-owner or older comments change nothing.
2. Late-tick veto: `read_vetoes` judges by the comment's time, not the tick's: a `no` created by `applied_at + window_minutes` counts even when the tick runs later. Reading stops at `applied_at + window_minutes + grace`, grace = `stale_after_intervals` x watch interval (reuse `_interval`/`settings`), so the comment reads stay bounded.
3. Closed gate: `tick` still returns `[]` before reading anything.
