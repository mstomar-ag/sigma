# Plan #1625: auto-unpark reads the map first

## Files
- `skills/sigma-loop/scripts/auto_unpark.py`: in `compute_unpark_actions`, before the comment fetch, an issue that carries `goal_blocked_label` (and not the parked label) is skipped when `_map_still_waiting(...)` is true.
- `_map_still_waiting(sdlc_dir, config, number, cache)`: false unless `discovery.dag.mode` is exactly `on` (shadow, off, typo, missing: false, `dag_pick` not loaded). Loads `dag_pick` lazily, calls `dag_pick.map_hold`; true only when it returns a non-empty list of open explicit blockers. Any exception or `None` (map unusable, stale change check, goal unknown): false, so today's full check runs. `cache` is one dict per compute call, so the map loads once.
- `tests/test_auto_unpark_dag.py` (new), `CHANGELOG.md` entry at the END of Unreleased, docs line in `docs/backlog.md` or the DAG doc if one names the sweep.

## Behaviour
- Map shows an open explicit blocker: no comment read, no state read for that issue.
- Map shows the issue free, goal unknown, map missing or stale, mode not `on`: identical to today (full check: keep-parked marker, dismissal comments, gate-hold kinds, comment-only blockers).
- Parked issues never resumed, `compute_blocking_actions` untouched.
- PROVISIONAL (owner to ratify): shadow mode does not change the sweep (the map acts only when written `on`), matching the picker's flip rule.
