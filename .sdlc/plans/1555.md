# Plan #1555: rulebook auto-approve mode

Plan sha256 is recorded by the loop. Unit: rulebook-learning. Gate: `rulebook.rules.auto_approve` (JSON boolean true only, default false).

## Behaviour
- Off: no code path changes. Seal bytes of every existing rule unchanged (the new fields join the seal body only when `auto` is true).
- On (and rulebook rules, autonomy, records parts enabled, and at least one owner in `rulebook.autonomy.owners`):
  - `rule_draft.auto_approve(sdlc_dir, config, now)` drafts a proposed rule for every non-blocked pair with a unique majority option at ANY level (no level floor, no held-out exam; shape-only options and pairs that already have a rule stay out), then approves it as the first configured owner with `auto: true`, `approved_by: <owner>`; writes one decision record (gesture `approve`, how `autonomous`, rule_id). Hard-stop kinds, `unknown`, non-bank kinds never.
  - It runs at the start of `applier.py main` (the watcher tick) before sync, and from `rule_draft.py list` and `suggest` (documented writers when the gate is on). Best effort, never raises.
  - Applier: for an auto-approved sealed rule the level-3 gate and the "own support" check are skipped in `_eligible` (ask armed at once), the arm step and the apply step. Window, daily cap, quota wait, due re-confirmation, owner `no` veto, person-wins and hard-stop kinds still apply. A veto recorded after the rule's `confirmed` time holds the auto rule (skip, reason "vetoed") until an owner reconfirms it by hand; the veto still lowers the pair via `autonomy.veto`.
- Doctor: warning row `rules: auto-approve ON (rulebook.rules.auto_approve)`; also warns when no owner is configured.

## Files
- rulebook.py: FIELDS (+approved_by, auto), validate (auto is True, approved_by str), `auto_approve_on`, `is_auto`, `_seal` (conditional), `approve(..., auto=False)`.
- autonomy.py: `vetoed_since(sdlc_dir, qkind, area, since, config)`.
- decision_record.py: gesture `approve` -> autonomous; NOT_PARK_ANSWERS += approve.
- rule_draft.py: `draft(..., auto=False)`, `auto_approve`, CLI list/suggest call it.
- applier.py: `_auto_rule`, level helper at the three level checks and the support check, main calls auto_approve.
- doctor.py: warning row. Config template, docs/configuration.md, docs/decision-rulebook.md, CHANGELOG (Unreleased), docs/launch/write-surface.json if a new write is registered.

## Test list
- off: auto_approve returns [], rulebook file unchanged, tick on a level-1 pair does nothing, existing rule seals identical.
- on: level-1 pair drafted+approved with approved_by/auto/seal, record gesture approve how autonomous; applier ask armed at once, applied after the window by main/tick, one comment; scenario through `rule_draft.py list` CLI and `applier.py` main with fake gh.
- hard-stop pair and `unknown` pair not drafted; no owner configured: nothing; tie: nothing.
- veto after auto-apply: parked again, veto file, pair lowered, further parks not auto-applied until reconfirm.
- hand-edit of `auto` breaks the seal; question-bank 25-rule shape stays valid and sealed.
- window/cap still honoured; doctor row present only when on.
