# Plan 1310: classifier timeout is retried, configurable, group-killed

## Files
- skills/sigma-loop/scripts/decision_import.py: `default_call` returns None on no answer and takes `timeout_s`; `classify_model` counts those rows in `info["timed_out"]`; `apply` passes the configured timeout and reports `timed_out`; the CLI prints one line when it is nonzero.
- skills/sigma-loop/scripts/rulebook_cfg.py: `timeout_s` joins the import limits (default 60, positive number, longer allowed).
- skills/sigma-loop/scripts/feature_judge.py: `_run_group` runs the child in its own process group and SIGKILLs the whole group on overrun; `ask_claude` calls it.
- skills/sigma-init/templates/config.json.tmpl: shows `timeout_s: 60`.
- tests/test_feature_judge.py: the mock seam moves from `subprocess.run` to `_run_group` (same kwargs).
- tests/test_decision_import_timeout.py (new); CHANGELOG.md.

## Behaviour
- Cause: `ask_claude` returns (None, 0.0) on a timeout, and `default_call` turned that into a dict with no kind, which `classify_model` cached and stored as unknown. Now None flows through the existing "no answer" branch: not cached, not stored, retried.
- The count is reported in `apply` output and in `info`. It counts every unanswered call (timeout or failure); `ask_claude` does not tell them apart.
- `rulebook.import.timeout_s` defaults to 60; invalid values fall back to 60.
- A timeout kills the child's whole process group, as `run_with_timeout.py` does; no new write surface.
- Gate closed: `apply` returns the same dict as before (the new keys are added only after the gate check).

## Test list
- A default_call whose ask_claude gives no payload returns None; a re-run after a timeout sends the row again and stores nothing.
- `apply` output reports `timed_out` equal to the number of unanswered rows.
- `timeout_s` default is 60; a configured 300 reaches `ask_claude`; junk falls back to 60.
- `_run_group` on a child that spawns a grandchild: after the timeout the grandchild is dead.
- Closed gate: `apply` returns exactly the old dict and calls nothing.

## Risks
- Existing tests that mock `subprocess.run` in feature_judge move to `_run_group`.
- A persistent failure now re-sends the row on every run, bounded by the existing per-run ceiling and candidate cap.
- Windows kills the direct child only, as before.
