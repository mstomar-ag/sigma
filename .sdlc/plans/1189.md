# Plan 1189: a person's no after an applied ask reaches the veto

## Change
`applier.close_for_issue` gains `refuse`: with it, an applied ask of the issue inside its window and
not yet vetoed is passed to `answer(..., "no")`. The unpark verb passes it for keep-parked; promote
passes it on demote (and now calls close for a demote). Failures stay swallowed by the callers.

## Test list
- keep-parked via unpark.resolve vetoes an applied ask
- demote via promote vetoes an applied promote ask
- plain unpark and out-of-window no do not veto; closed gate changes nothing
- a raising applier never blocks keep-parked
Control: the refuse branch disabled turns the first three red.

## Risks
Default behaviour of close_for_issue is unchanged (refuse defaults False).
