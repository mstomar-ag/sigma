## Why the tests are shaped this way (gate mechanics, verified in `skills/sigma-loop/scripts/red_green.py`)

1. Whole-file byte binding. `_hashes` (lines 84-94) hashes the WHOLE FILE of each planned node;
   `observe` stores each red with that `file_hash` (lines 169-175); `refusal` (lines 188-221) credits a
   red only if its `file_hash` equals the file's sha256 at the green and it predates the green run.
   So no file that contains a planned node may change between the red verify and the green verify.
2. Every collected node under every listed selector needs its own credited red (`missing = set(nodes)`
   at line 204, refused at line 221). A selector may therefore name only nodes that fail by assertion
   before Part 2 and pass after it. Pre-existing tests and green-by-design controls were green at
   baseline, can never get a red, and cannot be listed; they run as regression in the full verify.
3. Only assertion failures qualify (lines 161-167, and the traceback join at lines 97-129). A
   collection error, an `AttributeError`, an `ImportError`, `pytest.fail` or a skip earns nothing.
   A parametrised function with several failing ids is credited only when pytest's short-summary line
   keeps the `AssertionError` text, which depends on the terminal width (80 columns by default, or the
   `COLUMNS` variable) and the `CI` variable (read in the installed pytest's
   `_get_line_with_reprcrash_message` and `_format_trimmed`; the traceback fallback fails closed when
   several ids share one function name, and is switched off by any captured output).
4. Collection must succeed at Part 1 (`collect`, lines 72-81, raises on a non-zero exit).

Consequences, applied throughout: planned nodes are function-level selectors of UNPARAMETRISED tests
(a table is looped inside one function and every failing id goes into one assert message); tests print
nothing and never skip; every name that Part 2 defines is read with `getattr(..., None)` inside the
test body followed by an assert, so Part 1 collects and fails by assertion; green-by-design controls
(stay-quiet, known-limit, lookalike) are separate nodes that are NOT listed in `## Tests`.

## Conventions for the two new test files (Part 1)

- Header docstring in each file says: planned tests for #918, loads the module under test by path, reads
  names that Part 2 defines with `getattr` so collection never fails, and `NG`/`NW` are bound by the gate
  and are not edited after the red verify.
- No `print`, no `pytest.skip`, no `xfail`, no network, no `gh`, no background process. Every
  `subprocess.run` in a test carries `capture_output=True` and `timeout=120`: captured child output keeps
  pytest's report free of "Captured stdout/stderr" sections, which would switch off the gate's traceback
  attribution (fact 3), and the repository guard rejects a constant timeout below 60 over the repo root.
  For the same reason `NG` does not use `G`'s `_make_tracked_repo` (its child processes inherit stdio); it
  builds its tracked trees with its own `_tracked_tree` below and calls only `G`'s scanner under test.
- Keep email-shaped literals out of EVERY tracked file (the repository exposure scan also covers
  `.sdlc/`): no `name`, at-sign, `domain.tld` string in a test, a comment or a fixture. If a fixture truly
  needs one, build it by concatenation at run time or use the reserved example domain the detector
  already exempts. Also keep out four-digit issue references written with a hash sign, absolute home or
  temp paths, and credential-looking names. Step 5.3 checks this mechanically.
- A planned test never raises: arrange it so a missing Part-2 name is an assertion failure, not an
  exception (`found = getattr(module, "name", None)` then `assert found is not None, "message"`).
- Table tests loop and collect: `misses = []`, one entry per failing id carrying the id, then
  `assert not misses, misses`. The id lists in "Case-id registry" are the only ids; use them verbatim.
- `NG` helpers (shape; names are fixed because steps refer to them):
  ```python
  GUARD_PATH = ROOT / "tests" / "test_no_autonomous_feature_branch_deletion.py"
  _cache = []
  _counter = itertools.count()        # `import itertools` at the top of the file

  def _guard():                      # lazy and cached: collection stays cheap and side-effect free
      if not _cache:
          spec = importlib.util.spec_from_file_location("never_delete_guard_under_test", GUARD_PATH)
          module = importlib.util.module_from_spec(spec)
          spec.loader.exec_module(module)
          _cache.append(module)
      return _cache[0]

  def _code(lines):                  # lines go inside `def f(run, cwd, remote, name, sha, ref):`
      return "def f(run, cwd, remote, name, sha, ref):\n" + "".join("    %s\n" % l for l in lines)

  def _tracked_tree(tmp_path, files):  # {relative path: text}; `git init -q`, write, `git add -A`
      def git(*args):                  # no commit and no identity are needed: ls-files reads the index
          subprocess.run(["git", *args], cwd=str(tmp_path), check=True,
                         capture_output=True, text=True, timeout=120)
      git("init", "-q")
      for rel, text in files.items():
          full = tmp_path / rel
          full.parent.mkdir(parents=True, exist_ok=True)
          full.write_text(text, encoding="utf-8")
      git("add", "-A")
      return tmp_path

  def _planted_kinds(tmp_path, code, path="skills/x/scripts/y.py"):
      sub = tmp_path / ("case%d" % next(_counter))          # a fresh sub-directory per case
      sub.mkdir()
      _tracked_tree(sub, {path: code})
      return {kind for _p, _n, kind, _l in _guard()._delete_call_sites(sub)}
  ```
- `NW` helpers (shape):
  ```python
  SCRIPT = ROOT / "tools" / "readiness" / "write_surface.py"

  def _module(): ...                 # same body as W's _module(): load SCRIPT by path

  def NEW(function, rule):           # the literal ratchet message
      return ("new write site a.py:%s %s -- add it to docs/launch/write-surface.json with its gate"
              % (function, rule))

  def _findings(module, tmp_path, source, held=()):
      (tmp_path / "a.py").write_text(source)
      inventory = tmp_path / "inventory.json"
      inventory.write_text(json.dumps({"entries": [
          {"path": "a.py", "function": f, "rule": r, "count": 1, "gate": "test gate", "risk": "high"}
          for f, r in held]}))
      return module.ratchet(tmp_path, inventory)
  ```
  `held` rows exist so a red is never red for the wrong reason (a brand-new push line would already be a
  new `git-push` site on the unwidened scanner).

## Risks and rollback

Risks:
- The widened guard is deliberately noisy for later slices: every backup-create or restore push is a
  `colon_refspec` hit, every prune a `push_delete` or REST hit. A second `:refs/` line in
  `feature_rebase.py` or `release_manifest.py` breaks the unpack tests. This is the intended forcing
  function; the slices that add those sites update the pin in the same change.
- Per-physical-line scope is a real ceiling: the recorded limits (split `push`/`-d`, split
  `update-ref`/`-d`, dynamic colon-empty builds, a `gh_api` receiver bound to a variable, a bare
  `from gh_api import ...` name, `tools/` and `.sh`) are pinned by tests, not fixed. The AST scanner covers
  the dynamic colon builds and `tools/`.
- Three definitions of "destructive push" still disagree (the scanner, the egress hook, the readiness
  drill). Not reconciled here; follow-up.
- The `finish` phantom row and the seven look-alike rows stay (module-wide name resolution is untouched by
  decision); the follow-up is issue #926. The rendered `write-surface.md` stays stale for the same reason as
  before (no row added).
- Gate attribution. The 14 LISTED nodes are unparametrised so the traceback path can credit them; that path
  is switched off by any captured output, and the short-summary path depends on the terminal width and `CI`.
  Tests print nothing. If the red verify credits fewer than 14 reds although all 14 visibly failed by
  assertion, re-run the red verify with a wide terminal (`COLUMNS=250`) rather than editing `NG` or `NW`.
- Immutable test files. A defect found in `NG` or `NW` after the red verify costs a repeat of Part 1's red
  verify; this is why the stay-quiet tables and controls were written once, fully, in Part 1.
- `_RULE_VARIANT_MIN_SHARED = 8` is tuned on today's tree (real maximum 1, weakest planted variant 12); a
  future file legitimately quoting half the sentence would need a listing or a reword.
- Python 3.10 floor: `str.removeprefix` (3.9+) and the inline `(?i:...)` flag group are both available.
- The pinned sentence states policy; the orchestrator should confirm the wording before Part 1 runs, since a
  later change means changing the constant in `G` and the pin in `NG` together (and `NG` is bound by the gate).

Rollback: nothing is committed by any step, so abandoning mid-way is discarding the changes to the three
modified files and deleting the two new test files in the goal worktree. After the single commit lands, a
plain revert of that commit restores the previous guard, scanner, tests and changelog; there is no data,
state or inventory migration to undo because the shipped inventory is unchanged. A half-applied state
(Part 1 without Part 2) is red by construction and cannot merge, because the PR is gated on the full verify.
