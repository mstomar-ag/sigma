# Plan: 1470 merge/empty-commit acks survive the upkeep replay

## Goal
An ack of a commit with no patch-id (merge, empty) must still match after `rebase --rebase-merges` re-creates it under a new sha.

## Files
- `skills/sigma-loop/scripts/feature_rebase.py`: `rewrite_key()` (hash of author, author date, raw message, parent count, plus remerge-diff patch-id for merges); `ack()` stores it when patch_id is empty; `_acked_entries`/`_acked_keys` (new, `_acked` keeps its 2-tuple so existing callers and tests are unchanged); `_unacked` matches by key; `pair_acked`/`_clean_pairs` and `_write_runtime_acks(pairs=)` carry acks across a clean REBASED pass; `_direct_body` text.
- `skills/sigma-loop/scripts/feature_upkeep_pass.py`: `unit_callables(..., sdlc_dir, unit)` rewrite returns `acks`; `ack_union` keeps `rewrite_key`.
- `docs/upkeep.md`, `docs/branching-model.md`, `CHANGELOG.md`.

## Test list
- regression: ack a "merge base into unit" commit, pass REBASED (merge re-created under a new sha), move base, second pass REBASED not DIRECT_COMMITS.
- a commit with a patch-id is stored without a rewrite_key.
- unit pass rewrite returns the carried ack for an acked commit.
- existing ack tests stay green.

## Deviation
The spec says `_acked()` returns a third set; that would break existing 2-tuple callers and tests, so a sibling `_acked_keys()` is used.

## Done when
Acceptance in `.sdlc/acceptance/1470.md` holds; red controls: drop key matching in `_unacked`, see the regression red.
