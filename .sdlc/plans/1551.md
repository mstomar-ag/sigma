## Design (owner/parent decisions kept: findings inside the receipt JSON, capped; no phase-context growth; POSIX-only liveness; explicit node ids in `## Tests`)
All logic is in `skills/sigma-loop/scripts/reviewer.py`, plus one branch in `phase_gate.py`. `work.py` is not edited: `run_review` gains only a keyword argument with a default.

1. **Receipt while running.** The receipt is `{outcome:"running", pid:os.getpid(), started_at:int(time.time()), timeout_seconds, run_id:uuid4().hex, route, plan_sha256, content_key}`.
   - `pid` is the RUNNER, not the setsid child. On the in-process path (`work.py:845-848`) that is the work.py process, which is correct: that process owns the run.
   - It replaces the pre-launch placeholder at reviewer.py:914-916 and is written through `_write_receipt`.
   - No stored `deadline`. Readers DERIVE it as `started_at + timeout_seconds + _RUN_GRACE`, so it cannot be NaN, inf or forged larger than the caps below allow. `wait` prints the derived value.
2. **Grace is derived from the code's own bounds (B2).** `_RUN_GRACE = 4 * int(_KEY_SECONDS) + 60`, which is 540 s.
   - After the reviewer ends, the runner still runs `_stop_review_process` (≤ 4 s: `communicate(timeout=2)` + `wait(timeout=2)`, reviewer.py:198-215).
   - On the `review` phase it then runs `_content_key` (reviewer.py:939). That function makes four sequential git calls, each with its own `timeout=_KEY_SECONDS` (:461-462; calls at :464, :466, :472, :475), plus hashing under one overall `_KEY_SECONDS` budget (:458, :266-270).
   - Worst case is therefore about 4 × 120 s. The extra 60 s covers the stop step, the hashing tail and the fsync.
   - The default deadline is 900 + 540 = 1440 s.
   - Cost: a reused pid, a zombie, or a restored backup can read "live" for up to that long. A dead pid is still detected at once.
3. **Clock caveat (stated, not fixed).** The runner's timeout is monotonic (`communicate`). The deadline is wall-clock.
   - On a suspended laptop, wall time keeps advancing while monotonic does not (macOS), so a live run can pass its deadline.
   - When that happens it reads `failed/not_completed`, which fails closed. The runner's later final write still lands, because the nonce matches.
   - Named as a ceiling: this occurs only after a suspend longer than the remaining deadline.
4. **ONE classifier inside `_read_receipt`** (reviewer.py:578-587), the single door every reader uses: `waiver_reason` :611, `failed_receipt` :651, `subagent_transcript_refusal` :675, `accept_inline` :716, `independent_run_refusal` :790, phase_gate through those, and `wait`. `_classify(got, now)` works as follows.
   - `outcome != "running"`: unchanged.
   - Running AND every clause below holds: stays `running` (live).
     - (i) `_int(pid)`
     - (ii) `pid` is not a bool, inside `_int`
     - (iii) `pid > 0`
     - (iv) `_int(started_at)`
     - (v) `_int(timeout_seconds)`
     - (vi) `timeout_seconds <= _MAX_RUN_SECONDS` (86400)
     - (vii) `started_at <= now + _CLOCK_SKEW` (60)
     - (viii) `now < derived deadline`
     - (ix) `_pid_alive(pid)`
   - Otherwise it becomes `outcome:"failed", failure:"not_completed"`, with detail `runner pid N gone | deadline passed | malformed running receipt`. Every existing failure path and message then applies unchanged, so fail-closed is preserved.
   - `_int(x) = isinstance(x, int) and not isinstance(x, bool)`.
   - A `timeout_seconds <= 0` is NOT a clause. It only moves the deadline earlier, which fails closed sooner.
   - `run_review` refuses `timeout > _MAX_RUN_SECONDS` with exit 2 before any receipt write. This extends the existing guard at :893-896 with the same message family.
5. **In-module pid probe (R4), no `_load("ledger")`.**
   - `_posix()` returns `os.name == "posix"`. It is the one platform seam.
   - `_pid_alive(pid)`: when not `_posix()` it returns True (never calls `os.kill` on win32; the deadline bounds it, and a receipt is only ever written on POSIX, :854).
   - Otherwise it calls `os.kill(pid, 0)`. `ProcessLookupError` returns False. `PermissionError` and any other `OSError` return True (fail toward alive; the deadline bounds it).
   - About 8 lines, no import churn, no new way for a reader to raise.
   - Zombie case: `kill(pid, 0)` succeeds on an unreaped zombie, so a SIGKILLed runner whose parent never reaps it reads live until the deadline (≤ timeout + 540 s).
6. **Gates treat a live running receipt as "wait"**: never approve, never park.
   - `_failure_applies` (:620-637) returns False for `running`.
   - Its route logic (subagent → False; inline or untagged → True; otherwise tag match, :631-637) moves into `_route_applies(receipt, route)`, which BOTH `_failure_applies` and the new `running_receipt` use (R2).
   - `running_receipt(sdlc_dir, goal, phase) -> dict | None` returns None when `review.independent:false` or when the route does not apply. It has the same structure as `failed_receipt`.
   - The wait text comes from one helper: `_wait_gesture(sdlc, goal, phase, run_id)` = `reviewer.py wait <sdlc> --goal G --phase P --max-seconds 20 --run-id <id>`.
   - Where each gate changes:
     - `independent_run_refusal`: a new branch after the subagent return (:795-796) and the unreadable check (:797-798), before `stale/applies`. A live running receipt with an applying route returns "reviewer still running for G P (pid N): wait with `<gesture>`; do not park". It is a refusal, not None.
     - `subagent_transcript_refusal` (:664-688): a live running receipt (when not transcript-verified) returns the wait refusal. This function is route-agnostic today, reading any non-ok receipt, so its running branch stays route-agnostic too.
     - `inline_review_refusal` (:737-753): a running branch before the failed branch.
     - `accept_inline` (:716-718): raises `ValueError("reviewer still running (pid N): wait for it or kill it first")` when a live run's route applies (inline).
     - `phase_gate.status` (phase_gate.py:149-153): load reviewer once and call `failed_receipt` once. This removes the double `_load` + double call (D-1). Then a new `elif rv.running_receipt(...)` sets `ok False`, detail "the independent reviewer is still running", and fix = the wait gesture, with no "park".
7. **Nonce-guarded final write, with a pre-launch mode (B1).**
   - `_finish_receipt(sdlc_dir, goal, phase, run_id, **fields)` re-reads the RAW JSON (not via `_classify`). It writes `fields + run_id` only if the on-disk `run_id == run_id`.
   - A missing file (cleared by `work.py finish`, work.py:7504) or a foreign nonce causes no write and one stderr line. The ok path then returns 1. The failed path returns its own code.
   - Inside `run_review`, `failed()` picks the mode from state. Before the running write (`run_id is None`, i.e. the `content_unbound` path at :910-913) it uses plain `_write_receipt`, so an unbindable checkout still overwrites an earlier `ok`, as today. After the running write it uses `_finish_receipt`.
   - TOCTOU between the check and `os.replace` is a ceiling of one atomic rename (microseconds), and is not locked. Two concurrent runs for one goal+phase is not a supported flow (D-3).
8. **Finalise everything after launch (R7).** Everything from the running write to `return 0` is wrapped in `try / except BaseException`.
   - It finalises `failed("not_completed")` through `_finish_receipt` and re-raises, but only if no final write has happened yet (a `finished` flag). An exception after the ok write, such as a broken stdout pipe, therefore does not overwrite the verdict.
   - The existing `_stop_review_process` on a `communicate` exception (:930-932) stays.
   - SIGKILL of the runner is covered by the dead-pid path.
9. **Findings persisted INSIDE the receipt JSON (R8)**, in a `findings` field on the ok write only.
   - The cap is on ENCODED bytes: `_FINDINGS_CAP = 32768`, measured as `len(json.dumps(text))`, since `_write_receipt` uses the default `ensure_ascii`.
   - It keeps the HEAD (findings precede the verdict line, and the verdict is stored separately), then appends `...[truncated N chars]`. That bounds each file to under 34 KB.
   - DEVIATION from "beside the receipt": same directory, file and lifetime, removed by `clear_receipts` (:532-537), and no new write/unlink site, so `docs/launch/write-surface.json` is unchanged. Stated in the PR body.
10. **`wait` verb.** `reviewer.py wait <sdlc> --goal G --phase P [--max-seconds N] [--run-id ID]`.
    - The default is `WAIT_DEFAULT_SECONDS = 20`, chosen to sit below the one measured Codex `exec_command` yield of 30.2 s (issue text) so that a `wait` call is itself not yielded (R1). It is clamped to 1..3600. A non-int value exits 2.
    - It is implemented as `wait_review(sdlc, goal, phase, max_seconds, run_id=None, sleep=time.sleep, clock=time.monotonic) -> (code, text)` and polls `_read_receipt` every 1 s.
    - Exit codes:
      - 0: FINISHED, whatever the verdict. Text: `FINISHED verdict=<v> (finished is not approved; only verdict=approve is)`, then the findings.
      - 1: `FAILED <kind>: <detail>`, with no park prose.
      - 2: usage, an unreadable receipt, a bad goal or phase, `--run-id` mismatch ("a different run is on record: <id>"), or a receipt still missing after the retry window.
      - 3: `RUNNING pid=.. run_id=.. elapsed=..s deadline_in=..s`, returned within the bound plus one poll.
    - A missing receipt is re-polled for `min(5, bound)` s before exit 2, which covers a wait issued at launch (R6).
    - The stale-prior-receipt window (a `wait` without `--run-id` issued before the new running write) is documented in USAGE. The hint always carries `--run-id`, so the gesture the docs give is exact.
    - A receipt that flips from running to crashed mid-wait returns 1.
11. **Launch hint from the CLI only (R3).**
    - `run_review(..., hint=False)` prints, right after the running write and only when `hint` is true, one stderr line: `reviewer run: running pid N run_id R, deadline in Ts. If this call yields, do NOT park: <wait gesture> (exit 3 = still running; 0 = finished, read the verdict)`.
    - `main`'s `run` branch passes `hint=True`. The in-process work.py caller (work.py:847) does not, so its captured `errors` (work.py:849-850) never carries the hint.
    - The hint costs no phase context and is host-agnostic.
12. **Prose**: 1:1 word swaps only, as before. The candidate is `skills/sigma-loop/references/running.md:136-138`, to name `reviewer.py wait` once.
    - Measure `python3 evals/phase_context_budget.py` before and after, and revert the swap if any ceiling would have to rise.
    - Prose never says "0 = ok"; the hint says "0 = finished".

## Scale / resilience / safety notes
- **Per-item cost**:
  - One receipt per goal+phase. A read is one JSON parse (≤ 34 KB) plus one `kill(pid, 0)`, with no module import.
  - At 100x goals nothing scans the directory.
  - `wait` polls at 1 s for at most 3600 s (20 s by default): one process, one file read per second.
- **Recovery**:
  - A runner crash, reboot or reaped session gives a dead pid or a passed deadline, then `not_completed`, then the existing park/re-run levers.
  - Pid reuse, an unreaped zombie runner, or a restored backup of a running receipt all read live for at most timeout + 540 s (1440 s by default), then failed.
  - A lost final write takes the same path.
  - Exceptions after launch are finalised (Design 8).
- **Unverified (state in the PR)**:
  - Whether Codex keeps the yielded `exec_command` alive after the turn ends. If it is reaped, the receipt correctly reads failed.
  - Whether the reading call shares the writer's pid namespace (a sandbox or container with its own namespace would read a live runner as dead and reproduce the false park).
  - The end-to-end yielded-shell run on Codex is NOT measured in this goal.
  - The 20 s default rests on ONE measured yield (30.2 s).

## Risks
- A reader on another machine or in another pid namespace sees a foreign pid space. That is single-machine by design, with the deadline as the backstop (R10).
- Phase-context budget: ceilings have 0-16 tokens of headroom. The prose is optional and revertable.
- TOCTOU on the nonce check (Design 7).
- The 540 s grace lengthens the pid-reuse/zombie window. This was accepted over a second "refresh" write.
- The new `_MAX_RUN_SECONDS` refusal changes behaviour only for `review.timeout_seconds > 86400` (the default is 900).

## Out of scope

- A doctor row (none exists).
- A new qkind.
- Refusing a second concurrent launch (D-3).
- A process-start-time (`ps lstart`) pid check.
- A wait heartbeat line (the default sits below the yield instead).
