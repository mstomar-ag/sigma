# Plan #1957 map slice 2: one refresher per repository by a ledger lease

## Files
- `skills/sigma-loop/scripts/dag_lease.py` (new): lease files `dag/lease/<writer>.json` in the ledger worktree, one file per writer (no write conflicts), `{writer, taken_at, expires_at}`. `holder(root, now)` = the unexpired lease with the smallest `(taken_at, writer)`. `acquire(sdlc, config, now, force, git)` -> `holder` | `fold` | `local`. Steps: ledger off or no worktree -> `local` (read as today); not force and the snapshot is younger than the TTL -> `fold`; pull; a foreign unexpired holder -> `fold`; write my lease (expires = taken_at + TTL + margin, margin = max(300 s, 10 percent of TTL)), publish, pull, re-read: I am the holder -> `holder`, else `fold`. `force` skips the two fold checks before the write (it reads on this machine and takes the lease) but the race tiebreak still runs for the record.
- `skills/sigma-loop/scripts/dag_refresh.py`: `refresh_if_due` calls `acquire` after the due check and before any GitHub read; `fold` returns `{status: "folded"}` with no `gh` call and stamps the meta (`last_status: folded`) so a tick does not retry before `RETRY_SECONDS`; `local` is today's path.
- `skills/sigma-loop/scripts/dag.py`: `rebuild` takes the lease (force) before it reads.
- `skills/sigma-loop/scripts/sync.py`: `publish` stages my `dag/lease/*.json` (a lease-only change must push).
- `docs/dag.md` (reads per hour per repository before and after, measured on the scenario, live number not measured), `docs/launch/write-surface.json` (new writer), `CHANGELOG.md` (Unreleased), `tests/test_dag_lease_1957.py` (new).

## Behaviour
- Holder rule is deterministic over files every machine can read after a pull, so a race (both wrote before seeing each other) ends with one holder after the re-pull; the loser reads the snapshot. A dead holder's lease expires; the next due machine takes over, no person.
- Failure of pull/publish/ledger read: fail open to `local` is NOT used; a git failure on a ledger-on repo returns `holder` only if my own lease file was written and no foreign unexpired lease is visible, else `fold` (conservative: at worst one extra read per TTL, never a read storm because `RETRY_SECONDS` still applies).
- Ledger off: no ledger path touched, byte-identical to today. PROVISIONAL (owner to ratify): the margin is max(5 minutes, 10 percent of the TTL); a forced read does not wait for a foreign holder.

## Risks
Extra pull/publish per due refresh (once per TTL per machine, plus one per fold at most every `RETRY_SECONDS`). Scale: lease files are one small file per writer, pruned to unexpired-or-own on read (writers are bounded by machines, not issues). Existing dag refresh tests with a ledger on may now see git calls: run the dag family.
