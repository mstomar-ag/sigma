# Plan 1070 - pending-landing record after a crash between begin and merge

## Files
- `skills/sigma-loop/scripts/feature_upkeep_landing.py`: `settle` treats a record with no recorded call as a crash before the merge call.
- `tests/test_upkeep_landing.py`: crash-injection tests.
- `CHANGELOG.md`: Unreleased entry.

## Behaviour
`begin` writes a pending record with `call` None. If the process dies before `do_merge`, the next landing's `settle`
read the PR back but defaulted the call to `lost`, so an open PR classified `unconfirmed` and `begin` refused with
`unsettled-record` until the prune. Now a never-called record whose PR reads open and unmerged settles as `refused`
(`crash-before-merge`), which `begin` overwrites. Merged, closed and unreadable read-backs classify as before.
A record with a recorded lost call is unchanged. Closed gate stays byte-identical (settle returns before any read).

## Test list
- crash between begin and merge, retry lands and removes the record
- settle on a never-called record with an open PR returns refused crash-before-merge and begin then succeeds
- recorded lost call with an open PR stays unconfirmed (control)

## Risks
A merge call that reached the host just before the crash, but is not yet visible to the read, could be re-issued; the merge
is idempotent per head sha and the post-call read-back classifies it.
