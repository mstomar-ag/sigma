# Plan: #1304 unpark / keep-parked write records only for gestures that landed

## Goal
`unpark.py resolve` must write the decision record (store file + fenced comment + applier close)
only after the label change landed, and must refuse `keep-parked` and `unpark` on an issue that
carries neither the parked nor the blocked label (no record, exit 1, clear message).

## Design (PROVISIONAL choices marked)
- In `resolve`, after the closed check: `parked = parked_label or goal_blocked_label in names`.
  Not parked -> outcome `failed`, detail names the issue and says nothing was recorded. This also
  covers `--dry-run` (the refusal is the same answer the real run would give).
- Failed label write: no `_comment_decision`. PROVISIONAL: the typed answers are still kept as a
  plain comment plus the body block (the interview is not re-askable), but no record id, no
  store file, no applier close. The answers are not a decision; the decision did not happen.
- The old "already pickable, answers recorded" path is replaced by the refusal above.
- Closed rulebook gate and the landed happy path: unchanged bytes.

## Test list
1. unpark, label write fails, records open: no store file, no fenced decision comment, exit 1.
2. keep-parked on an unparked issue, records open: no store file, no comment, exit 1, message.
3. unpark on an unparked issue: same refusal.
4. Landed unpark and parked keep-parked with records open: one record each (unchanged).
5. Closed gate happy path comment bytes unchanged for unpark and keep-parked.
6. Documented CLI gesture `unpark.py resolve <sdlc_dir> <issue> --answers <file> --decision ...`
   returns 1 on the refusal and on the failed write.
Controls: revert each clause once (record before swap; parked check on keep-parked; parked check
on unpark) and see the matching test red.
