# Plan 1073: fix two load-flaky tests at the seam

## Causes
1. `tests/test_board_phase.py` hung-gh test: `communicate(timeout=1)` starts its clock at spawn. On a loaded machine the
   stub shell had not yet run `echo $! > pidfile` when the kill landed, so the pidfile was missing or empty. The trailing
   `< 0.5s` wall-clock bound on the second call was also load-sensitive.
2. `tests/test_upkeep_audit.py` near-enabled matrix, job entry point: the drivers loaded the job script INSIDE the attempt
   trap. Loading imports sibling scripts, and under a cold bytecode cache that writes a `.pyc`, which the trap records as
   the closed run's write. Which parallel worker warmed the cache first decided red or green.

## Files
- `tests/test_board_phase.py`: gate the Popen clock on the stub reporting its grandchild (bounded wait, not a raised
  timeout); replace the wall-clock bound by a spawn count; add a deterministic control (stub that starts 2s late).
- `tests/upkeep_support.py`: `drivers()` loads every script before the trap opens; lambdas only call.
- `tests/test_upkeep_audit.py`: cold-bytecode helper, a control showing a load inside the trap records a `.pyc`, and the
  matrix run under a cold cache for the job drivers.
- `CHANGELOG.md`: Unreleased entry.

## Test list
- hung gh killed with its process group (gated; no wall-clock bound on the second call)
- control: un-gated slow-starting gh records no pid before the kill; gated, the pid is recorded and killed
- control: loading a script inside the trap under a cold cache records a `.pyc` write
- job drivers closed under a cold cache (red when `drivers()` loads inside the lambda, seen once)

## Risks
- The gate waits up to 30s for the pidfile; a stub that never writes it would then fail on the later assertions, not hang.
- Cold-cache tests evict script modules from `sys.modules` through monkeypatch, restored afterwards.
