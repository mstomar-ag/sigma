## Done when
- [ ] Before a refresh reads GitHub, it takes a refresh lease recorded on the ledger (writer token, taken-at, expiry = the TTL plus a margin); a machine that sees an unexpired lease held by another writer, or a snapshot younger than the TTL, folds the ledger snapshot instead and makes no GitHub call.
- [ ] An expired lease is taken over by the next due machine, with no person; two machines racing for it end with one holder (the ledger's existing claim rules decide), and the loser reads the snapshot.
- [ ] `dag.py rebuild` and `refresh --force` still read GitHub on the machine they run on, and take the lease.
- [ ] Tests on two fake writers sharing one ledger: only the holder reads; expiry hands over; a race yields one holder; ledger off reads as today. `docs/dag.md` states the read count per hour per repository before and after, measured on the scenario, and says the live number is not measured.
