## Done when
- [ ] Board GraphQL calls from watchers on the same account are spaced or batched (a machine-wide token bucket or a shared backoff file under the state directory), with the spacing stated.
- [ ] A doctor row that hits a secondary limit says "secondary limit" and when to retry.
- [ ] A test feeds a secondary-limit response and shows the backoff and the doctor wording; it goes red when the response is read as a primary limit.
- [ ] Every wait on a GraphQL refusal reads `X-RateLimit-Remaining` / `X-RateLimit-Reset` (or `Retry-After`) from the refused response itself, never `/rate_limit`; a test with a fake response whose headers disagree with `/rate_limit` shows the wait follows the headers, and goes red when `/rate_limit` is read instead.
- [ ] Calls that have a REST equivalent (the label lookup in `label_drain.py` and the pick's label check first) use REST, so a spent GraphQL hour does not stop a plan or a pick; a test shows a plan succeeds with GraphQL refused.
- [ ] GraphQL use is budgeted machine-wide per account (a shared bucket under the user state directory, read by every watcher and loop session on that account), with the spacing and the per-tick share stated in the docs.
