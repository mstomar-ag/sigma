## Goal in one paragraph
Slice 2 of part A makes the repository's two static guards able to see the deletions and ref writes that slices 5 to 7 will introduce, before any of that code exists. (1) The never-delete guard (`tests/test_no_autonomous_feature_branch_deletion.py`) must flag, against the backup namespace, a push with a delete flag, a colon-empty refspec, a REST delete of a git ref, `update-ref -d`, and a `gh_api` delete helper, and its exact-site pin is updated. (2) The write-surface scanner (`tools/readiness/write_surface.py`) must classify push-scoped deletes and forces as destructive, see `update-ref`, and see `gh_api` write helpers by name, with an inventory row and a real gate for every new site and no change to any existing row (a phantom row may be fixed deliberately). (3) One pinned constant holds the new rule wording and a test pins it. Each widened rule is shown red against the unwidened code first. D-29 asks whether the scanner's phantom high-risk `work.py` `finish` row is fixed here.

## The never-delete guard: measurements
Current classification of every deleting shape, by planting it in a tracked file under `skills/` and running the guard's own `_delete_call_sites`:

| Shape | Seen today? | Red-first control (against the unwidened guard) |
| --- | --- | --- |
| `git branch -D`, `git push … --delete`, `branch --delete` | yes (`branch_dD`, `push_delete`), any namespace | already covered |
| `git push -d <remote> <ref>` (short form) | **no** | planted test |
| colon-empty `:refs/sigma/backup/…` | **no** | planted test |
| colon-empty built dynamically (`f":{ref}"`, `":%s" % ref`, `":" + ref`) | **no** (needs the literal `:refs/heads/`) | accepted gap unless the guard learns an AST pass (Open questions) |
| REST `-X DELETE …/git/refs/sigma/backup/…` | **no** | planted test |
| REST `--method DELETE …/git/refs/heads/…` | **no** | planted test |

| `update-ref -d refs/heads/x` and `refs/sigma/backup/…` | **no** | planted test |
| `update-ref --delete` | accidentally, as `push_delete` (the `--delete` substring) | planted test for its own kind |
| `gh_api.<delete or merge helper>(…)` call | **no** | planted test (helper names) |
| restore or backup-create refspec `<sha>:refs/…` | restore into `refs/heads/` yes; into `refs/sigma/backup/` no | planted test |

Measured widening (applied to the guard's own source in memory): a REST check of `"-X"|"--method"` plus `DELETE` with `git/refs/` on the line, a `push … "-d"` same-line check, an `update-ref (--no-deref)? (-d|--delete)` check as a new kind `update_ref_delete`, and `":refs/" in line` for the colon check. Result on the real tree: the found-set equals the current five-site pin exactly (no extra, none missing). All shapes above except the dynamic colon builds and the two-physical-line verb/endpoint shape are then seen; docstring and comment lookalikes stay quiet. A looser colon check (any string literal starting with `:`) was tried and rejected: it adds 76 false sites across `skills/` and `hooks/` (measured).

Pin consequence ("the exact-site pin is updated"): with the ref-anchored REST check the pin's tuples do not change on today's tree, only its kind vocabulary and docstring do; with an endpoint-agnostic REST check (any `-X`/`--method` `DELETE`) the pin gains exactly one tuple, `("skills/sigma-loop/scripts/gh_api.py", "remove_label", "rest_delete_ref")`. That is measured. Which is wanted is an Open question.

What a backup namespace adds later (slices 5 to 7), and which assertion trips: the backup-create refspec in the same atomic push adds a colon hit in `feature_rebase.py` (a second physical line breaks the `:335` unpack, a same-line one does not); a restore adds a colon-refspec tuple for a new function; the prune adds a `push_delete` or REST-delete tuple for a new function. The namespace string `refs/sigma/backup` does not occur anywhere today, so a pin of "every line naming the backup namespace" is the empty set now and forces each later slice to list its sanctioned sites. A constant such as `BACKUP_PREFIX = "refs/sigma/backup/"` would itself be a hit on that pin, so the pin has to allow the constant's definition by name.
