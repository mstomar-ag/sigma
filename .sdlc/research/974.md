# Research 974: doctor preflight for a missing verify interpreter and a branch-creation ruleset

## Findings
- The doctor already has a row that flags a relative interpreter path in the verify command, and a
  gh-backed block gated on work.enabled. Neither looks at whether the first word of the command exists.
- The doctor script is large, but no size ceiling test covers it. New logic still goes in a new small
  library module in the loop scripts folder, loaded the way the doctor loads its other siblings.
- Reads of GitHub go through the gh_api helper (a ratchet forbids new direct gh call sites). It already
  has a branch-rules read. It has no read of one ruleset, which is where the bypass flag lives.
- The doctor's real runner bounds every gh call with the init network timeout. A failed call raises through
  the existing raising adapter, so the new check degrades to a could-not-check row.
- The push target is the work remote, not the issue repository, so the repository to probe comes from
  that remote's URL.
- Size: small lane. Blast radius: one new module, one helper in gh_api, two call sites in the doctor.

## Not known
- The live reply shape of the branch-rules and ruleset reads was not seen here; it is faked in tests.
