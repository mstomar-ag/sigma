## How the GitHub gate works today (Q1)
- **Parse**: `blocker_scan.EXPLICIT_TRIGGERS` = blocked by / depends on / depends upon (`blocker_scan.py:115-119`); regex `\b(trigger)\b[^\n#,;.!?]{0,40}?#(\d+)` (`:122-127`); `extract_refs(text, self_ref)` strips the unpark-QA span, dedups, drops self (`:233-265`). Run at FETCH time by `mirror.normalize_issue` into `blocker_refs` (`mirror.py:125`); read back by `read_refs` (`blocker_scan.py:194-230`).
- **Decide**: `_pick_dependency_hold` (`loop.py:1577-1727`): mode off -> "" ; not github -> "" ; mirror index (cached per `_next` call in `gate` dict); goal absent -> one forced refresh per process, still absent -> CLAIM with stderr; refs resolved by `_resolve_blockers` (`:1521-1535`, open=hold); a hold buys one refresh per call (#1650), merged over the old index; refs the mirror lacks are read live (`_live_blocker_states` `:1547-1574`), still unknown -> NOT blocking + stderr; outer `except` -> claim + stderr `dependency gate failed non-fatally`.
- **Hold line** (`loop.py:2190-2191`): `loop.py: not claiming #<goal> — open prerequisite <#N (blocked by), ...>. Left untouched (still sdlc:goal, no claim); taking the next candidate`. DONE summary (`:2165-2168`): `loop.py: nothing pickable — N goal(s) are waiting on an open prerequisite (#g → #N (blocked by)). They become pickable by themselves when it closes; nothing was written to them`.
- **Callers**: `_next` only (`loop.py:2015`, gate at `:2183-2194`, before lease/lock). `_next` callers: `next_batch` `:2460` (one `_next` per slot, own `gate` cache each), `run_loop` `:5588`, CLI `next` `:6389`, CLI `next-batch` `:6410` (via `next_batch`).
- **Posture**: fail OPEN on every undeterminable state and on exceptions; ZERO `gh` calls when nothing is held.

## How local picks work (Q2)
- `LocalSource.next_pending` -> `discovery.next_pending(goals_dir, skip, order, aliases)` (`sources.py:497-498`, `discovery.py:85-110`): globs `goals/*.md` sorted, reads EVERY file, skips `str(path)` in skip, eligible iff `status` set and not in `{done, parked, failed, proposed}`; returns `str(path)` (the goal key in loop is the full path).
- Statuses: `pending`, `in_progress` (`state.set_in_progress` `state.py:1087`), `done` (`complete` `:1116`), `parked`, `failed`, `proposed`. Done = `status: done` frontmatter; the file STAYS in `goals/` (`goal_state_prune.py` never touches `goals/`). `await_merge` keeps `in_progress` until merge-reconcile (`sources.py:549-554`), so a prerequisite with an unmerged PR is not done -> holds (correct).
- Ids: filename `%04d-<slug>.md`, frontmatter `id: %04d` (`sources.py:671,681-688`; template `sigma-init/templates/goals/0001-example.md.tmpl:2`). NO code reads frontmatter `id`. `LocalSource._resolve_ref` resolves a bare numeric id by int-comparing filename leading digits (`sources.py:556-589`).
- Natural reference shape is `#N`: every machine writer emits `**Blocked by:** #<int>` (`handoff.py:1172`; `compile_plan.py:127,294` writes one line per blocker for sigma-scope children, local included since `create_dependency` returns the int gid). Probed: `extract_refs("**Blocked by:** #0007-auth-a1")` -> ref `0007`; bare `0007-auth-a1` -> nothing; `#7, #8` -> only `7`; `acme/other#12` -> ref `12` (see TD-1).
- `handoff.py track` can mark the CALLING goal blocked (`--blocks yes`) but has no flag to put a sibling marker on the NEW child; ordered siblings need `--body-file F` with a hand-written `**Blocked by:** #<sibling id>` line (`handoff.py:1413-1426`). Triage arm -> `pending`, park/queued (triage off) -> `proposed` (`handoff.py:860,928-929`).

## Constraints & unknowns
- Unverified: performance at 10x/100x — not measured. Index build is one extra O(N) pass per `_next` call, lazily, only when a candidate has refs; TD-4 dominates.
- Blocking (Q-B1): "by id or file stem" vs. the `#\d+`-only vocabulary pinned by `test_the_pick_gate_declares_no_blocker_vocabulary_of_its_own`. `#0007-slug` and `#7` already work; a non-numeric stem (`auth-a1.md`) or a bare stem cannot be named today. Options: (a) numeric only, stem = leading-digit stem; (b) add `blocker_scan.extract_local_refs` that also accepts a stem token, restricted to the canonical `**Blocked by:**` marker line. Because unresolvable refs HOLD, a loose stem matcher ("depends on the parser" -> ref `the`) would phantom-hold forever, so (b) must be marker-line-only.
- Non-blocking: does a `parked`/`failed` prerequisite hold (acceptance says "not done" -> yes)? Should the stderr name a cycle (A<->B both held; no hang, one-level lookup)? Duplicate leading ids (`0007-a.md`, `0007-b.md`) -> ambiguous -> hold and name. Hold line wording for local (`<stem>`, "still pending").

## Proposed seam (Q3)
At `loop.py:1669`, when the source is LocalSource-shaped (`goals_dir` + `fetch_title_body`), return `_local_dependency_hold(source, goal, cache)` instead of `""`. It reads the dependent's body via `source.fetch_title_body`, gets refs ONLY via `blocker_scan` (self ref = own id/stem, cross-repo skipped), resolves each against a goals index built once per `_next` call into the existing `gate` cache (pure helper in `discovery.py`: leading-int, frontmatter `id`, stem -> status). Not `done` -> hold; unresolved -> hold plus a stderr line naming it. Outer fail-open `except` and the `_next` skip/hold flow are reused unchanged; BR-3 takes a mode-aware label. GitHub branch untouched.
