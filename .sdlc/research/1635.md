## Edge cases and decisions
- **Number parse**: last non-empty stdout line, `float()` after strip; reject nan/inf (`math.isfinite`), reject multiple tokens ("12 34") and non-numeric: all `unmeasured`. Negative allowed. Only stdout, stderr never parsed. `same` = exact equality (tolerance is R-02/D-2).
- **Failure**: exit != 0, `TIMEOUT`, `ERROR` (command not found: Popen OSError), `truncated`, no number: `unmeasured`, never `same`; one side unmeasured makes the row unmeasured.
- **Env scrub** (denylist, since an allowlist breaks PATH/HOME-dependent tools): start from `unattended_env()` (drops git location vars, pins no-prompt), then drop exact `GH_TOKEN, GITHUB_TOKEN, GH_ENTERPRISE_TOKEN, GITHUB_ENTERPRISE_TOKEN, SIGMA_SLACK_BOT_TOKEN, SIGMA_SLACK_BOT_SOCKET_TOKEN, SIGMA_SMTP_PASS, ANTHROPIC_API_KEY, OPENAI_API_KEY` and any name ending `_TOKEN|_SECRET|_PASSWORD|_PASS|_API_KEY`, prefix `AWS_`. Names in this codebase: `slack_commands_listen.py:172-173`, `rg '"SIGMA_SMTP_PASS"'`. State plainly it is a denylist: unknown credential names survive (C-4 says "other credential variables"). Test: AC-6 plants GH_TOKEN and a `_TOKEN` suffix var and has the command print `env`.
- **No shell**: `command` must be a non-empty list of strings else the metric is refused (config malformed). A tool that is not installed: `unmeasured` ("not found"), never installed.
- **Config at base**: absent/no `quality`/no `metrics` = print `no metrics configured`, exit 0, spawn nothing (AC-5, including head-only fixture). `git show` failing because the path is not in base = absent (this is Sigma's own repo; self-hosting measures nothing, say so in docs). Merge-base unresolvable or git error = `unreachable`, distinct text, still no process. Malformed JSON/`metrics` not a list/entry missing keys/bad direction or scope = refuse naming the index, exit 2, nothing run.
- **changed-files contract** (decision, non-blocking): argv element exactly `{changed_files}` is replaced by the file list (no substring interpolation, no shell, so no injection). List = `git diff --name-only --no-renames <mb> HEAD` plus untracked, restricted to files present at BOTH commits so both sides measure the same set; cap 200 files else `unmeasured` (ARG_MAX); empty = `unmeasured`. Env-file alternative rejected: extra write under `.sdlc/state`, another scanner row.
- **Where head runs**: head = the goal worktree itself (what verify judges, includes uncommitted work). Risk BR-13: a command that writes tracked/untracked files there. Plan should snapshot `git status --porcelain` before/after and print a `side-effect` warning; wrappers must write to ignored paths.
- **Concurrent goals**: scratch `state/quality_delta/<goal>` plus `.owner` pid marker `diff_revert.py:234`: two goals never collide; the same goal twice: live pid = abstain, print `unmeasured (another run owns the scratch)`. Goal ids sanitised as `scratch_dir:230` does. A different quality_delta from verify's diff_revert never collides (BR-3). Git worktree add on the shared repo is safe for different paths; `git` takes its own locks.
- **Memory floor**: probe = free memory (Linux `MemAvailable`, `/proc/meminfo`; macOS `vm_stat` free+inactive+speculative pages x page size parsed from its header) vs total from `os.sysconf(SC_PHYS_PAGES)*SC_PAGE_SIZE` (works on both, no subprocess). Propose floor = 25% of total: 16 GB host needs 4 GB free, 8 GB host 2 GB. 25% is a judgement, not a measurement; flag for owner. Unreadable, parse mismatch or other platform = `unmeasured` for every metric, run nothing (AC-7). Probe once before the first command (per PRD); with one at a time, re-probe before each command is cheap and safer: recommend per command.
- **Timeout**: schema in PRD has no timeout field. Propose optional `timeout_seconds` (default 300, max 3600) in each metric: non-blocking owner call; without it, a constant copied from a laptop violates SAFETY.
- **Output bound**: `max_out_bytes` 1 MiB, `tail_bytes` small; peak memory about 3x cap (`bounded_run.py:97-99`, measured there, not by us).

## Scale (bounds, not measurements)
Runs = 2 x M metrics, serial; wall time <= 2 x sum(timeouts) = 2 x M x T. 10x metrics: 10x wall, same memory (one process at a time). 100x commits: base worktree checkout is one `git worktree add` of the tree at merge-base: cost O(tree size), independent of commit count; merge-base is O(history walk) in git. Many metrics on `repo` scope is the ceiling; `changed-files` bounds it by file count (cap 200). Serialised chokepoint named: strictly one process at a time machine-wide per goal; two goals run two at once unless the plan adds a global lock (not proposed; probe-per-command is the guard, and it is racy between probe and spawn: name it).
No unbounded growth: scratch removed in `finally`; `.owner` removed by cleanup.
