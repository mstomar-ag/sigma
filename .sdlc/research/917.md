## The recording trap, concretely
**What exists to build from (all in `tests/`, stdlib plus pytest):**
1. Files: `tests/path_recorder.py` `Recorder` (PEP 578 audit hook; inert when no recorder is active, so it is safe in
   a long-lived xdist worker; it records open/rename/remove/mkdir/rmdir paths). It does not keep the open mode, so pair
   it with a before/after tree diff for creation: `tests/test_script_help.py:73-95` (`_snapshot`/`_diff`, `lstat`
   walk of `(is_dir, mtime_ns, size)`). The recorder's own controls to copy: `tests/test_feature_registry.py:646-675`.
2. Processes and network: `monkeypatch.setattr` on the `subprocess` module attributes plus `socket` (precedent
   `tests/test_phase_report.py:1849-1853`, `tests/test_board_phase.py:361-382`). Shipped code has no aliased
   `from subprocess import` (query above, empty), so module-attribute patching sees every call. The file
   `tests/conftest.py:92-130` already wraps `subprocess.run`/`Popen` per test with a subclass-based guard for `gh`;
   a test's own `monkeypatch` replaces it for the test and restores it at teardown. Copy that subclass idea for `Popen` so
   `isinstance` checks keep working.
3. Alternative that sees all three channels plus write-mode opens with one mechanism: a PEP 578 hook with an
   `_ACTIVE` list exactly like `tests/path_recorder.py`. Measured (Python 3.13): it sees `subprocess.Popen`,
   `os.system`, `socket.getaddrinfo`, `urllib.Request` and `open` with a write mode, and raising from the hook vetoes
   the action, so a "fully enabled" control never runs a real command. 3.10 to 3.12 not measured here (CI covers
   them; the existing recorder's docstring says the events are version-independent). The out-of-process recorder
   `tools/readiness/egress/sitecustomize.py` uses the same events but logs only a subset (no `os.system`, no file
   writes), so it is not enough alone.
4. A model attempt is never an in-process call in this codebase: every model launch is a child process
   (`claude -p ...` at `S/feature_judge.py:161`, the supervisor's command from `SIGMA_CLAUDE_CMD`/`SIGMA_CODEX_CMD`
   at `S/supervise_daemon.py:437`, `:528`, the reviewer routes). So "model attempts" = recorded process launches whose
   program is `claude`, `codex`, `cursor-agent` or the first token of those override variables; keep it a separate
   counter so the three categories in the acceptance are asserted separately.
5. Pick-time half: `_calls_for_one_started_goal` (`tests/test_docs.py:736-770`) already records every call
   `work.start` makes. Generalised to take a config, the call list under a near-enabled `upkeep` block must equal the
   list under none (4 unadopted, 17 adopted).

**Shape of the test:** a fixture installs the three recorders (and sets `HOME`/cwd to a temp directory), a parametrised
test runs every registered entry point against each config, and asserts all three counters empty and the tree diff
`([], [], [])`. Configs: `{}`; `json.loads` of the shipped template; and the near-enabled set: `enabled` as `"true"`,

pair if it reads one. **Control:** a fully enabled config run through an entry point that really attempts all three

## Constraints & unknowns
- **Verified facts that constrain the Plan.** (1) The module must be stdlib-only, import no network module, and stay
  3.10-compatible (`tests/test_third_party_imports.py`, `tests/test_no_network_in_core.py`). (2) The gate takes an
  already-loaded dict; `state.load_config` already guarantees a dict (`S/state.py:36-50`), but the gate must still
  tolerate a non-dict argument. (3) Template notes: valid JSON, no release-shaped numbers, notes inside the block must
  not trip a strict unknown-key check (underscore-prefixed keys exist inside other blocks, for example
  `config.json.tmpl:84`, `:161`). (4) Order inside the slice: settle the block name (D-19), then fix the template and
  the variable literal, then register the variable; the registration and the discoverability pin both embed the name.
  (5) The independent verify command is the whole suite; a throwaway-copy run is reported under Measurements.
- **Conditional review.** Review must run `/sigma-contract-check`: a new top-level config key in the shipped template
  and a new environment variable are exported surface (additive; existing adopters never receive the block).
  Not `sensitive`; not `migration` (no stored data shape changes).
- **North-star early warning.** The resolver answered `absent` (resolved to the main checkout; no file), so there is
  nothing to trip. The repository's own five properties apply: the gate must be total (reliability, safety), constant
  cost with no I/O (scalability: one dict walk, called once per decision, not once per unit), and fail closed

## Lane rationale
Medium, by footprint, not by guessed time. Counts: **1** new shipped module (no callers, no new store, no new
boundary); **2** edited shipped files (the template, `legacy.py`); **5** existing test files edited at one place each
(`test_feature_registry.py` conditional, `test_script_help.py`, `test_config_discoverability.py` or a new file,
`conftest.py`, and possibly `test_docs.py` if its helper is generalised); **1 to 2** new test files; **3** records
committed (design, brief, this dossier) beside the existing acceptance file. Modules crossed: scripts, template,
registry, tests. It sets up a new contract (a config block and an environment variable) but with zero consumers, so it
is not large. It is not small because several pins turn red on a wrong move (measured), the naming decision spans
every later slice, and the recording trap is new test infrastructure. Escalate to large if Plan wires the gate into
`work.start`, the watch tick or the doctor, or edits the pinned documents.
