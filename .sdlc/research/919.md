## Goal in one paragraph
Add the library half of "when is a feature branch due for upkeep": a drift measure that counts pull-request arrivals on
the default branch (and on the unit) by AUTHOR date over a bounded history walk, and answers UNKNOWN, never zero, when
the walk cap is hit, when git fails, or when commits exist but none classify; a threshold derived from the window and
burst rates and clamped; one small state file per unit, written atomically, where an unreadable file reads as overdue;
and the due rule (a cooldown since the last attempt, a backstop since the last success, a longer backstop for dormant
units). It also carries two review items from the design: classify the new path joins for the unit-key fold inventory,
and settle the retention rule for the new stores (D-41), with growth dispositions. Nothing in the product calls any of
it yet: slice 6 (the pass) and slice 7 (the scheduler) consume it, so with the upkeep gate closed there is nothing to
run. Acceptance (the recorded acceptance for #919) in five checkable bullets: (1) author-date arrivals, bounded walk,
UNKNOWN rules, derived and clamped threshold, a skewed-committer-date fixture; (2) atomic per-unit state, unreadable
reads as overdue; (3) the due rule shown for cooldown, backstop and dormant units; (4) growth dispositions, path joins
classified, default numbers shipped with their source stated, a fixture for first-parent commits with no pull-request
number; (5) every new behaviour red before green, nothing changes while the gate is closed, the independent verify
command green.

Two consequences that the design text does not state:
- The mapping cooldown = `triggers.min_interval_minutes`, backstop = `triggers.every_hours`, dormant window =
  `triggers.dormant_days`, dormant backstop = `triggers.dormant_every_hours` is my inference. It is checked by value
  (2 h, 24 h, 14 d, 72 h in design section 2 equal the defaults at 82-83), not by any sentence in the gate. Plan should
  state the mapping in the new module and pin it with a test that reads `DEFAULTS`.
- A closed reading returns `DEFAULTS`, so a slice-3 function must never infer "enabled" from the settings it is handed;
  the caller (slice 6 or 7, behind `gated`) owns that.
