## The live list, measured (22 generators needed for 23 entries; see note)
Hash used: first 10 hex of sha256 over `"<flags>:<pattern>"`. All 23 hashes are distinct, so the
two duplicated names (`private-key`, `credential-assignment`) are told apart by hash, as designed.
Python 3.9 and 3.10+ give the same `flags` (32, or 48 for DOTALL); the pattern text is the stable part.

| # | name | commit gate | what the redactor does to a generated value |
| - | --- | --- | --- |
| 0 | private-key (terminated block) | yes | redacted; the unterminated sibling (#1) also matches |
| 1 | private-key (unterminated fallback) | yes | redacted; body of 3 long base64 lines consumed |
| 2-5 | aws-key, gh-token, jwt, auth | yes | redacted, typed label, value and tail gone |
| 6 | authorization-header | no (redactor-only) | redacted, label is the bare `[REDACTED]` |
| 7 | credential-assignment-suffix | no (redactor-only) | redacted, label is the bare `[REDACTED]` |
| 8-20 | the 13 prefix and URL shapes of `SHAPE_RULES` | yes | redacted, typed label |
| 21 | credential-assignment (quoted, from `SHAPE_RULES`) | yes | redacted as bare `[REDACTED]` (a sibling wins) |
| 22 | credential-assignment (original anchored) | yes | redacted as bare `[REDACTED]` (a sibling wins) |

Note: the table needs one generator per ENTRY (23), not per name (21). The generator list is
therefore keyed by name plus hash, or the two duplicated names carry a `#n` suffix.

For all 23 generated values: the redactor removes the whole value, the typed or bare placeholder
is present, and no value is in `COMMIT_FIXTURE_VALUES`. Exceptions to "tail gone" are only an
artefact of what "the secret" is: for `url-password` the secret is group 1 (the password), and the
last ten characters of the whole URL are the host, which correctly survives. Therefore the pinned
entry must also say WHICH span is the secret (whole value, or group 1), and the tail check must be
done on that span. The slack-webhook and the two quoted-assignment shapes are the same case.

## Measured commit outcomes (`commit_secret_hits` over one planted line)
- 19 entries: refused, and the rule that fires is the entry's own name. Private-key (both entries)
  reports the rule twice (two specs match one block); the quoted assignment reports
  `credential-assignment` twice (both assignment specs match).
- `authorization-header`: **refused by sibling** `credential-assignment` (this reproduces the
  design's PC-8 with the real function). Expected outcome: `refused-by:credential-assignment`.
- `credential-assignment-suffix` (an upper-case env name ending in a password word, `=`, value):
  **accepted**, zero hits. Expected outcome: `accepted`.
- `COMMIT_FIXTURE_VALUES` holds one public AWS example value. The aws generator draws sixteen
  characters from an alphabet that omits the letters I and O; the exempt value contains both, so a
  collision is impossible by construction. D-3 is still asserted at run time, once as "no generated
  value contains an exempt value" and once end to end ("the aws entry produces a commit hit").
  Use the same non-alphanumeric boundary logic as `commit_secret_hits`, or the stricter plain
  substring test; the stricter one cannot be fooled.

Masking (D-4) measured by leave-one-out (every other spec applied, this one removed): 21 of 23
entries leak when removed (the value or its tail stays), so removal is visible. The two
assignment entries do NOT leak when removed, because `credential-assignment-suffix` redacts the
same text. Consequence for slice 1: the two-way pin is the only guard that sees those two being
removed; a behavioural probe (slice 2) cannot. State this in the module docstring so the claim is
not larger than the proof.

## How a generator avoids a whole shape on any source line
Technique that passed all three scans below: split the provider prefix across two adjacent string
literals (the second starts mid-prefix), and produce the filler from a seeded `random.Random` over
an alphabet. Fixed-width suffix shapes use the exact count (npm: 36, google: 35, aws: 16); the
variable-length ones use a count comfortably above the minimum (24 to 60). Specific cases:
- PEM: build the header and the END line from a run of five dashes plus a split `PRIV`/`ATE KEY`;
  body lines are 64 characters of base64 alphabet (need 40+ per line for the leak gate, 16+ for the
  redactor; the unterminated entry simply omits the END line).
- JWT: three dot-separated runs of 12, with the first run beginning after a split two-letter prefix.
- Provider prefixes starting `sk-` and `sk_`: the anthropic and openai shapes need their hyphenated
  middle word; the plain `sk-` shape must be ALNUM ONLY after the prefix, and it did not collide with
  the other two (measured: each text matched exactly its own spec and no other, except the cases
  noted below).
- Webhook: the host path with `services` split, plus two upper-case ids and a 24-character tail.
- URL with embedded credentials: scheme and `//` split; 14 filler characters in the credential slot; host `example.com`.
- Assignment shapes: a split key name (`api_`/`key`, `pass`/`word`), then a filler value.

Sibling matches (a text that another spec ALSO matches): `private-key` terminated (matches the
unterminated entry), `authorization-header` (matches the original `credential-assignment`),
the quoted assignment (matches the suffix and original specs), the original assignment (matches
the suffix spec). All other 19 entries match only themselves.

## Constraints that will react (all measured or read in the worktree)
1. **The commit refusal reacts to the check's OWN source.** Running `commit_secret_hits` over each
   line of a prototype table showed the original `credential-assignment` rule firing on 8 lines:
   every dict-literal line whose key ends in a credential word followed by a colon and a value
   (a quoted key such as the gh-, slack-, npm-, pypi-, gitlab-, huggingface- or url- credential
   name closing its quote, then `:` and `lambda`), and a plain local variable assignment named for
   the secret (a local named for the secret, assigned from a match group). The loop's own `work.py commit` would refuse the goal's
   commit of `check.py` and the test file. So: store entries as tuples (`("name", hash, gen, outcome)`,
   where the name is followed by a comma, not a colon), never as `name: value` mappings, and never
   name a variable or keyword argument after a credential word with `=` or `:` and a 4+ character
   value (use `hit`, `span`, `body`). Same rule for docstrings and comments in both new files. Re-run
   `commit_secret_hits` over every added line before committing (a cheap self-check; leave it as a test).
2. **Leak scan** (`tools/leak_scan.py`, runs over every tracked file): measured clean on the
   prototype source (no findings), and a control with one whole planted shape on a line was caught

## Proof plan (tests, each seen red then green)
Pure functions taking the scrub module; fake modules built with `types.SimpleNamespace`.
- Clean: the real scrub module against the real table gives no findings (exit 0).
- Red 1: remove a live spec from the fake module -> a "pinned entry missing from live" finding naming
  the shape and its hash prefix. Run this for one of the two duplicated names to prove the key is
  name plus hash (removing only the second `private-key` entry must still name `private-key`).
- Red 2: add an unpinned spec (or edit one regex) -> a "live spec missing from table" finding.
- Red 3: drop one generator from the table -> a finding naming the shape.
- Red 4: `SHAPE_RULES` carries an entry that is not in the live list -> a subset finding.
- Red 5: flip a redactor-only entry's expected outcome (`accepted` vs `refused-by:...`) -> red;
  and a measured mismatch (generator output that the real redactor does not match) -> red.
- Red 6: put an exempt fixture value into a generator's output -> D-3 finding.
- No finding line ever contains a generated value (assert on captured output), and the CLI gesture
  `python3 evals/safety/check.py` is run as a subprocess: exit 0 on the real tree; a deliberately
  broken copy of the table (in `tmp_path`, loaded by path) exits 1.
- Self-check test: every line of both new files passes `commit_secret_hits` (constraint 1), and
  `leak_scan.scan_text` reports nothing on them.
- Control (AGENTS.md "run the control"): break each guard once in the real file and see its named
  test red before trusting it.
