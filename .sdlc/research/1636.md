## AGENTS.md constraints and scale
Stdlib only, host-agnostic (no hook), no `gh`, no network, no writes, no env var, no config key. Output lines are plain, not a status block. Own `USAGE`.
Scale: ONE `git log <base> --since=<window+14d> --name-only -z` pass (measured here: 30d = 313 commits, 5,703 file lines, 0.11 s) plus one read per goal file (as log.py). Cost O(commits + sum file lists); per-goal then in memory via file->goals index (never per-goal `git` calls). 10x/100x: 3,000 commits ~1 s, 30,000 ~10 s (extrapolated, NOT measured). Bounds: cap files per goal considered (a huge list is truncated and flagged), cap window at 90d (retention), bounded `subprocess` timeout; output capped (top 20 goals + totals).

## Edge cases and decisions (proposed; Plan-Review owns them)
- Squash (default): find merge commit by last `(#PR)` in subject. Merge-commit method (`Merge pull request #N`): locate via subject, own-branch = `sha^1..sha^2`, excluded. Rebase method: no marker, goal counted `unlocated`, NOT in the 10 floor. Show unlocated count.
- Own-branch exclusion is automatic for squash (branch commits are not on base); implement by position, not time: only commits NEWER than the merge on the base walk, within merge time + 14d by committer time (clock skew: topology decides, time only caps).
- Later-goal exclusion: a commit whose last `(#N)` equals a later-merged goal's `pr` is skipped. Consequence to state: Sigma-made fixes never count; only human or non-goal fixes. Apply to `fix` only; reverts always count (AC-1 has no exclusion).
- Revert: subject `Revert "..."` or body `This reverts commit <sha>`. Attribute to the goal whose merge sha is the target when resolvable, else by file overlap. Revert of a revert (`Revert "Revert`) is a re-land: not counted as a defect.
- `fix` variants: case-insensitive `^fix(\(.*\))?!?:?\s`; not `^prefix`, `^fixture`.
- Hot files: CHANGELOG.md is in 148 of 313 commits, README.md 62, docs/launch/write-surface.json 70 (measured). Literal AC-2 means attribution to ALL overlapping goals, which would count nearly every fix against nearly every goal. Recommend: attribute to ALL (AC-2 literal), report the TOTAL as distinct commits (not the sum), and print how many counted fixes matched only through shared files. A silent exclusion list would break AC-2 as written. Blocking question B-1.
- Immature: goal merged <14d ago is `immature`, listed, excluded from rate numerator and denominator; the floor counts mature goals only (B-2).
- Renames: use `-M --name-status`, count both paths; copies ignored. Detached HEAD: use `--base` default `origin/<work.base or main>`, never HEAD. Shallow clone: `git rev-parse --is-shallow-repository` true prints `unmeasured (shallow clone)`. Unborn/missing base: `unmeasured` with reason.
- Action log: off -> `unmeasured` (log off); config unreadable/worktree (#1778) -> `unmeasured` (state unknown), a different line; malformed lines skipped; unreadable file skipped and counted; `pr` missing -> goal unlocated.
- Output order: line 1 proxy sentence, then `unmeasured`/figures; never a rate when unmeasured.
