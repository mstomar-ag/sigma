## Goal in one paragraph
Slice 4 gives the upkeep feature two reusable building blocks that no later slice should have to invent. (1) A shared verify runner: given a command, a working directory that is a scratch worktree, and a wall-clock budget, it runs the command in its own process group, kills the whole group on overrun, stops when a stop file appears, returns a distinct outcome when no verify command is configured, and refuses to run at all unless the operator made the git-local shell-command trust decision for that checkout. (2) An unattended git environment for the engine runner: environment pins (no prompts, no editor, no signing, a hooks policy) and per-command timeouts, applied to the same `(cwd, argv) -> stdout` runner contract the rebase engine already uses. Three carried items ride along: background fetches must not rewrite the main worktree's fetch record or start automatic maintenance (F7), the doctor helpers that later readiness rows build on must have bounded probes (D-39), and no shared helper may arm a ledger claim (D-36). The recorded acceptance for this goal adds that every new behaviour is shown red before green, that nothing changes while the upkeep gate is closed, and that the independent verify command is green. Conservative readings chosen where the wording is open: no existing verify path is rewired (the runner is added, not substituted); the engine's default runner stays byte-identical and the unattended runner is injected by gated callers; no new environment variable; no skill or reference text is edited; the doctor gets a new bounded helper rather than a changed `_real_run`.

## Constraints & unknowns
**Constraints the Plan phase will face**
1. Red-to-green binding (drain procedure, enforced by `skills/sigma-loop/scripts/red_green.py`: the whole test file is hashed at `:84-95`, the red is recorded with that hash at `:169-175`, and the green must match it at `:200` and `:216`): every node in the plan's tests section needs a recorded assertion red whose whole-file hash equals the file's hash at the green run. Stage plan, research, acceptance and design records with `git add` before the green verify (M-11: untracked files are invisible to the ratchet and the exposure scan).
2. Planned tests must be silent, unparametrised and fail as assertions; keep test function names at 72 characters or fewer (slice 1 capped the whole node id at 53); a new module needs a credited red, so tests load it inside the body behind an assertion (as `tests/upkeep_support.py` does) rather than importing it at the top, which earns no credit (M-12). One to 25 backticked selectors, one per bullet.
3. Record caps: a committed plan or research record is at most 131,072 bytes (`tests/test_b6_462.py:34-35`); plans stay under about 118 KB; pin large test bodies by hash instead of embedding them.
4. Markdown hygiene on tracked records: backticked paths must exist (or be unticked), no bracket expression followed directly by parentheses, no home paths, no addresses.
5. Pins that must stay green and are touched by nothing: the 18 files of M-15 first group plus the seven of the second, `tests/test_doctor.py:249` and `:1765-1767`, `tests/test_upkeep_proof.py` (including `test_pick_time_unchanged`), the write-surface check, `tools/rename_check.py`, `evals/phase_context_budget.py`.

7. Closed-gate proof for a library: slice 1's trap proves a gated function stays quiet; a library has no gate to close, so the proof is structural and needs its own control: a pin that no shipped module other than tests loads the new module, shown red by a planted caller, plus unchanged `test_pick_time_unchanged`. 8. Guard the documented gesture, not a stronger one: kill-the-group tests must call the runner exactly as callers will (timeout in seconds, no extra flag), and each control is run red once by breaking the kill (for example a direct-child kill) and seeing the grandchild survive.
9. Probabilistic controls: a race between exit and kill, and stop-file latency (0.25 s poll) are timing-sensitive. Add a deterministic in-process seam (an injected clock and sleep) for the assertions and demote real-time tests to smoke tests with generous limits.
