## 4. Edge cases for classify
- Path forms: leading `./` (strip), backslashes (normalise to `/`), absolute path inside repo (relativise to toplevel), absolute or `..` outside repo -> typed refusal, exit 2.
- Directory path and trailing `/`: fnmatch on the string only, no filesystem access; document that `src/legacy/*` matches everything below (since `*` crosses `/`).
- Glob semantics: `fnmatch.fnmatchcase` (case-sensitive on every OS; plain `fnmatch` is case-insensitive on Windows, a host divergence). Empty glob -> refuse typed (it would match nothing silently).
- design.zones wrong shapes: not a list, entry not a dict, glob not a non-empty str, zone not in {legacy, modern}, unknown extra keys -> refuse typed, naming the index; never treat as absent. `design` itself not a dict -> refuse. Missing `design` or `zones` key -> undeclared (AC-2).
- Merge-base: base_ref comes from the worktree record (remote/base); resolve `HEAD` merge-base. If the record is missing, merge-base fails, or HEAD is detached/unborn, print `unknown` (or refuse) for the newness column; NEVER print `new` or plain zone as if existing. Shallow clones can fail merge-base: same path. Absent-at-merge-base test: `git cat-file -e <fork>:<path>` (exit 1 = absent, other failures = unknown; distinguish them).
- `new` precedence: PRD says print zone AND `new`; D-3 says new file follows principles, existing undeclared file keeps today's behaviour. Fixed output grammar needed (blocking-free, plan decides).
- Renamed file: treated as absent at old path = `new`; note `diff --no-renames` idiom used elsewhere.
- Running from a worktree: `.sdlc/config.json` is only present if the adopter commits it; in this repo `.sdlc/*` is gitignored, so resolve `.sdlc` via git-common-dir like north_star.py does (#1778), else config reads as missing and everything prints `undeclared` falsely. Decide: absent config file vs unreachable are different (same ABSENT-is-not-PASS trap).
